- [ ] **本人確認（1 つずつ）**: 待機 → 走り → 顔 → 1 段目の手付け攻撃（実機で「だいぶマシ」）→ **2・3 段目の手付け攻撃**（重撃、回避はこの確認のあとで手付けにする）。確認が取れたものから次へ。未確認のまま量産しない
- [x] 実機確認: fps。**再計測で 60 fps（dpr 1.50）**（2026-10-03 夜、ADR-011 の適用後。以下は適用前の経過）。適用前の実機スクショは **42〜43 fps**（dpr 1.5、描画 188k 三角形、draw calls 69〜73）。60 fps に届いていない。
  - 切り分け用の計測モード `?perf=1` を入れた（`src/debug/perf-probe.ts`）。iPad で `<URL>/?perf=1` を開いて「計測開始」を押し、約 1.5 分触らずに待つと、機能を 1 つずつ止めたときのフレーム時間（js / gpu待 / 計）が表で出る。結果の画面を共有してもらい、効いた項目から対策する。
  - 読んで見つけた候補（未計測）: ① ポストの出力側バッファ（グレードの書き込み先）まで MSAA 4× 半精度になっている（シーンの描画先だけで足りる）② タッチボタンの `backdrop-filter: blur`（毎フレーム再描画される WebGL の上）③ キャラ 59k 三角形が 影・本体・輪郭線で 3 回描かれる（188k のうち約 178k）④ 影マップ 2048²・ブルームの多段ぼかし・dpr 1.5
  三角形数は影パス 1 回と輪郭線パスを含む（キャラ 59k × 3 ≒ 177k）。
  - 実機計測の結果、fps は解像度に比例して落ち、ポストの構成が支配的だった。対策として ADR-011 を入れた（2026-10-03）: ポストを「シーン → 最終 1 パス」の 2 工程に減らし（画面サイズ・MSAA のパスが 3 → 1）、解像度の動的調整（1.5 → 1.25 → 1.0）を追加。実機の再計測で 60 fps（dpr 1.50）に達した。
  - 残る候補: ③ キャラ 59k 三角形が 影・本体・輪郭線で 3 回描かれる ④ 影マップ 2048²。再計測の結果次第で着手する

## 既知の問題（実機で見つけたもの）

- 2026-10-03: 1 体目のキャラは実機で全動作が崩れた（静止画検査では見逃した）→ 2 体目に差し替え、数値検査を導入
- 2026-10-03: 2 体目でも「まだ不安定」「走りに違和感」「顔が判別できない」の指摘 → 顔・走りを修正、待機を直立に変更。以後は 1 つずつ本人確認してから進める
- 2026-10-03: 2 体目を全方向で検査（静的メッシュ・12 方向・顔・全クリップ 4 方向）。崩れはないが、腕を頭上へ振り上げる姿勢（重撃・コンボの振りかぶり）で脇のトップス縁がささくれる。近距離でのみ見える。本人確認のあと、脇のウェイト平滑化か振りかぶりの小さいクリップへの差し替えで対処する（`docs/05-asset-automation.md`）
- 2026-10-03: 「腰〜ウエストが角度によって静止時から崩れる」→ 原因は輪郭線の突き破りと焼き込みテクスチャの描き崩れ（メッシュ・ウェイトではない）。輪郭線の対策とテクスチャの塗り直しを入れた。実機で未確認（`docs/05-asset-automation.md`）
- 2026-10-03: 「待機で足が地面に全て設置していない」→ 配信元クリップの足の姿勢が全クリップでつま先 15〜24° 上向きだった。足の姿勢の補正と、足裏の頂点による接地補正を入れた（`docs/05-asset-automation.md`「足の接地」）。実機で未確認。stance・slash などは元のポーズのせいで高いほうの足が 2〜3.5cm 浮く（IK が要る）
- 2026-10-03: 「走りの横顔の違和感」→ 顔の輪郭線が太すぎて横顔が黒い塊になっていた。顔の輪郭線の倍率を 0.04 に下げ、待機・走りの頭を起こした（`docs/05-asset-automation.md`「頭の向きと横顔」）。前髪が顔の前に垂れる形は残る。実機で未確認
- 2026-10-03: 脇のささくれ → 3 連コンボを振りかぶりの小さい 3 本（Right_Hand_Sword_Slash / Left_Slash 1 振り目 / Thrust_Slash）に組み直した。上腕の挙上は 111° / 128° / 112°（目安 130° 以下）で、4 方向の近接でもささくれなし。攻撃データを剣先の実測に合わせて直した（`docs/05-asset-automation.md`「3 連コンボの組み直し」）。手触り・見た目は実機で未確認。heavy（161°）・dodge（143°）はまだ脇が破れる姿勢を含む
- 2026-10-03: 「攻撃モーションの違和感」→ 1 段目を手付け（キー → IK → 焼き込み）に置き換えた（ADR-012、`docs/05-asset-automation.md`「攻撃を手付けに変更」）。上腕の最大挙上 104°、接地足の滑り 0.0cm、剣先は体の前の通過で最高速（当初「約 25m/s」と書いたが測り方の誤りで、実測は 119m/s。のち 85m/s に下げた）。
  実機で未確認。2 段目（Left_Slash）・3 段目（Thrust_Slash）は Meshy クリップのままなので、1 → 2 のつなぎはクロスフェード（姿勢差が大きい）。heavy・dodge は Meshy のまま（脇が破れる姿勢を含む）。
- 2026-10-03 夜: 実機で「1 段目は少し違和感はあるがだいぶマシ。2 撃目以降は体の形が変形するなど課題が多い」→ 2・3 段目も手付けにし（逆袈裟 / 突き）、前の技の受付時点の姿勢から続ける仕組み（`continueFrom`）を入れた（ADR-012 追記）。3 段とも腕・脚のクランプ 0、接地足の滑り 0.0cm、手首のねじれは ±180° をまたがない。1 段目の斬りは剣先が 119 → 85m/s（コマ飛びを減らす）、予備動作の左腕を前へ出した。**実機で未確認**。1 段目の「少し違和感」の中身は未特定（本人に聞く）。heavy・dodge は Meshy のまま（脇が破れる姿勢を含む）。
