# 01. 設計判断の記録（ADR）

形式: 背景 → 決定 → 理由 → 代償 → 見直し条件。
変更時は上書きせず新しい ADR を追加し、旧 ADR に「Superseded by ADR-xxx」と書く。

---

## ADR-001 Web 技術（Three.js + TypeScript）で作り、iPad Safari で遊ぶ

**状態**: 採用（2026-10-03）

**背景**: 最大の失敗要因は「放置」。開発ループの摩擦を最小にし、生成 AI が自律的にビルド・検証・配信まで
回せる構成が必要。遊ぶ端末は iPad Pro 2021（M1）。

**決定**: Three.js（WebGL2）+ TypeScript + Vite。GitHub Pages に配信し、Safari で PWA として起動する。

**理由**:
- Xcode / Mac / Apple Developer 登録 / 実機署名が不要。push すれば iPad で URL を開くだけ
- 全資産がテキストまたは標準フォーマット（TS / JSON / glTF）で、AI エージェントが扱える
- クラウド環境からビルド・テスト・ヘッドレス描画の目視確認・デプロイまで完結する
- 本人の過去プロジェクト（ブラウザ + AI 駆動開発）と同じ型

**代償**:
- 性能上限はネイティブ（Unity 等）より低い。ただし M1 iPad とデモ規模なら 60fps は十分可能
- Safari 固有の制約（音声解放、フルスクリーン API 不可、メモリ上限、タッチの既定動作）
- Unity のアニメ調シェーダ資産（UniVRM, lilToon 等）は使えない。トゥーン表現は自前で組む

**検討した代替**:
- Unity: 業界標準でアニメ調資産が最も豊富だが、iPad 実機に乗せるまでの距離が長く、
  エディタ依存資産を AI が扱いにくい
- Godot 4: テキスト資産で魅力的だが iOS 書き出しは Mac/Xcode 必須、Web 書き出しは iOS Safari で不安定
- Babylon.js: 妥当だが、アニメ調キャラ（VRM 等）周辺の資産は Three.js の方が厚い

**見直し条件**: Safari の WebGL 性能や安定性がデモ規模でも不足した場合。

## ADR-002 WebGL2 で開始し、WebGPU は後から検討

**状態**: 採用（2026-10-03）

**決定**: `WebGLRenderer` と既存のポストプロセス資産を使う。レンダラ初期化は 1 箇所に閉じ、
マテリアルは自前のトゥーンマテリアル経由でのみ生成し、将来 WebGPU 版へ差し替え可能にする。

**理由**: iPadOS 26 以降の Safari は WebGPU に対応するが、Three.js の WebGPU 経路は周辺資産
（ポストプロセス・サンプル）が WebGL 経路より薄い。デモ完成を優先し、安定経路を取る。

**見直し条件**: デモ完成後、性能余力が欲しくなった時。

## ADR-003 物理エンジンは入れずに開始

**状態**: 採用（2026-10-03）

**決定**: 衝突は XZ 平面上のカプセル（円）同士と、アリーナ境界、地面高さの取得のみ。自前実装。

**理由**: アリーナ型のキャラクターアクションに必要なのは「キャラ同士が重ならない」「壁を越えない」
「攻撃判定の重なり」であり、剛体シミュレーションは不要。Rapier 等は WASM 読込と同期層を増やす。

**代償**: 坂・段差・ラグドール・物理的な押し合いは出来ない。

**見直し条件**: 段差のある地形、物を投げる・壊す、ラグドール死亡演出が欲しくなった時 → Rapier を検討。

## ADR-004 固定タイムステップ + フレームデータ駆動の戦闘

**状態**: 採用（2026-10-03）

**決定**: シミュレーションは 60Hz 固定（`step(dt=1/60)`）、描画は `requestAnimationFrame` に従い
補間する。攻撃は「発生 / 持続 / 硬直 / キャンセル受付」をフレーム数で定義する。
ヒットストップは時間スケール（`timeScale`）で実装し、UI やカメラは影響を受けない別の時間を持つ。

**理由**: 端末や rAF レート（60/120Hz）の差で手触りが変わらない。戦闘ロジックが純粋関数化でき、
vitest で検証できる。

## ADR-005 キャラクター資産の経路: Tripo を主、VRoid を保険

**状態**: 暫定採用（2026-10-03）。生成と取り込みの手順は ADR-010 で自動化経路に置き換え（Tripo 系の 3D 化を主とする方針は維持）。プレイヤーの採否は M1 の検査で確定する。

**背景**: 本人は画像生成（ChatGPT）→ Tripo（画像→3D）でキャラを作れる。Tripo クレジットは潤沢。
VRoid Studio（VRM）はアニメ顔・髪の揺れ（SpringBone）が標準で、three-vrm で忠実に描ける反面、
デザインの自由度が低い。

**決定**:
- 敵・ボス・小物・環境オブジェクト: **Tripo**（本人が重要キャラの原案を作り、それ以外は AI が順次作る）
- プレイヤー: Tripo で 1 体作り、`03-asset-pipeline.md` の検査基準で判定。
  合格 → Tripo 経路で確定。不合格 → VRoid（VRM + three-vrm）に切り替え、敵は Tripo のまま
- どちらの経路でも、描画は自前トゥーンマテリアルに統一する（MToon 固有の見た目に依存しない）

**懸念（確率順）**: 顔が横から見て破綻する / 関節変形が汚い / 髪・布が揺れない / テクスチャに陰影が焼き込まれている。
対策は `03-asset-pipeline.md`。

## ADR-006 タッチ専用の操作系

**状態**: 採用（2026-10-03）

**決定**: 横持ち iPad、両親指操作。左半分: 浮動仮想スティック（触れた位置が原点）。右半分: ドラッグで
カメラ回転、右下に攻撃（大）・回避・ロックオンのボタン。ロックオン中はカメラが対象を自動で捉える。
コントローラ・キーボードはデモ完成まで対応しない（開発用のキーボード操作は入力抽象化の裏で許容）。

**理由**: タッチではカメラ操作が最大の負担。ロックオンと自動追従で「カメラをいじらなくても戦える」
ことを基本にし、ドラッグは補助とする。

**詳細**: `04-controls.md`

## ADR-007 配信は Vercel（GitHub Pages は使わない）

**状態**: 採用（2026-10-03）。当初案（GitHub Actions → GitHub Pages）を置き換え

**経緯**: 当初は GitHub Pages を想定したが、リポジトリが private で Pages が使えず、
本人が Vercel を接続して iPad 実機で動作確認した（操作感は問題なし）。リポジトリは後に public 化された。

**決定**: 配信は Vercel のリポジトリ連携（push で自動デプロイ、ビルド基点は既定の `/`）。
GitHub Actions（`.github/workflows/ci.yml`）は typecheck / test / build で `main` を守るだけにする。
`vite.config.ts` の `BASE_PATH` 環境変数は、将来 Pages 等に載せたくなったとき用に残す。

**注意**: リポジトリが public のため、資産（Tripo 生成物等）とコードは誰でも読める。
API キー・トークンは絶対にコミットしない（`docs/05-asset-automation.md` 参照）。

## ADR-008 UI は DOM/CSS、フレームワークなし

**状態**: 採用（2026-10-03）

**決定**: HUD・メニュー・仮想ボタンは素の DOM と CSS。React 等は入れない。

**理由**: ゲームループ側は命令的な更新が自然で、UI の規模も小さい。依存を減らす。

## ADR-009 トゥーン描画の方針

**状態**: 採用（2026-10-03）

**決定**:
- 全オブジェクトに自前のトゥーンマテリアル（階調ランプ・影色・リムライト・（必要なら）マットキャップ）
- 輪郭線は inverted hull（法線方向に押し出した裏面描画）。生成メッシュは法線を平滑化してから使う
- ライトは平行光源 1 つ + 半球光のみ。影はシャドウマップ 1 枚。ライトを増やさない
- ポストプロセス: ブルーム（控えめ）・ビネット・色調補正。輪郭線のポスト処理（深度/法線エッジ）は
  inverted hull で不足する場合に追加
- アニメらしさは演出（剣筋トレイル・ヒットストップ・フラッシュ・カメラシェイク）で担保する

**理由**: 資産の出自（Tripo / VRoid / プリミティブ）に依らず見た目を統一する。

## ADR-010 キャラクター資産は Higgsfield コネクタ経由で自動生成する

**状態**: 採用（2026-10-03）。ADR-005 の手順部分を置き換え

**背景**: 人手の工程（画像生成→Tripo→リグ→Mixamo）が放置の最大要因になりうる。computer use・ブラウザ操作・
ChatGPT/Codex CLI は、このセッションからは使えない（PC 未接続、`chatgpt.com`/`api.openai.com` は遮断）。

**決定**: 画像生成（`gpt_image_2_5`）→ 3D 化（Tripo H3.1）→ リグ＋モーション（Meshy）を Higgsfield コネクタで実行し、
結果 GLB を CDN から取り込んで `tools/inspect-glb.mjs` で AI が検査する。詳細と費用は `docs/05-asset-automation.md`。
人間の関与は「デザインの採否」のみ。重要キャラの原案をユーザー自身が作る運用は引き続き可能（同じ経路に画像を渡す）。

**理由**: 仮キャラ 1 体で全工程を通し、約 17 クレジットで品質が許容範囲であることを確認した。

**代償**: 別サービスのクレジットを消費する（ユーザーの Tripo 手持ちクレジットは使わない）。Meshy のリグは
人型前提で、指・髪・服のボーンがなく、スキニングに破れが出る。非人型の敵は未検証。

**見直し条件**: M1 でスキニングの破れが許容できない場合、VRoid（VRM）経路か Tripo 直接 API の骨格に切り替える。

**一部置き換え（2026-10-03）**: **攻撃モーションの調達**は ADR-012 で手付け（キー → IK → 焼き込み）に変えた。待機・走り・回避・被弾・死亡は引き続きこの経路（Meshy ライブラリ）。

**追記（2026-10-03）**: 1 体目は実機で全動作が崩れた。`tools/skin-stress.mjs` で測ると辺の 11〜15% が 1.8 倍超に伸びており、
Meshy の返却直後でも同値 → 自動リグのウェイト破綻（裾の広い服が主因）。2 体目は本人の 3 面図から四角メッシュで生成し、
位置結合＋ウェイト平滑化＋接地補正を加えて 0.26〜1.1% まで下げて採用した。手順は `docs/05-asset-automation.md`。
以後、キャラ資産は**数値検査を通さずに採用しない**。

**追記（2026-10-03）— 輪郭線の弱点と対策**: 生成メッシュの細い溝（背骨・脇）や裾では、inverted hull の押し出しが表面を突き破り、
暗いギザギザの線になる（腰の背面で実機の指摘。輪郭線を消すと消えることで切り分けた）。対策は 3 つ。
(1) 押し出し専用に平滑化した法線 `aONormal`、(2) 凹み量による輪郭線の削減 `aOutlineCut`（`src/render/outline-attrs.ts`。UV の継ぎ目で複製された頂点は同じ値にする）、
(3) 輪郭線を視線方向に 6mm 奥へ送る `uDepthPush`。外周の輪郭は手前に何もないので影響しない。キャラ以外のメッシュは属性が無く、従来どおり満額の輪郭線になる。

**追記（2026-10-03）— 顔の輪郭線**: 輪郭線の太さは画面上で一定（距離に比例して押し出す）ので、ゲームのカメラ距離（約 5m）では目鼻・唇・前髪の筋より輪郭線のほうが太くなり、
横顔が黒い塊になる（実機の指摘「横顔の違和感」。輪郭線を消すと目・鼻・唇・耳がはっきり見えることで切り分けた）。顔（頭ボーンに乗る頂点）の太さ倍率を 0.35 → 0.04 に下げた
（0.12 でも黒い筋が残り、0.04 でほぼ消える。`src/character/loader.ts` の `faceOutlineScale`）。髪の外周の輪郭線は細く残る。

## ADR-011 ポスト処理を 2 工程に減らし、解像度を負荷に応じて自動調整する

**状態**: 採用（2026-10-03）。ADR-009 のポスト処理の「構成」だけを置き換える（ブルーム・ビネット・色調補正という方針は変わらない）

**背景**: iPad 実機の計測（`?perf=1`）で、fps が描画解像度に比例して落ち、ポストの構成が大きな割合を占めていた。
EffectComposer の構成は「シーン → ブルームを MSAA ターゲットへ加算 → グレードをもう 1 枚の MSAA ターゲットへ → 出力」で、
画面サイズ・HalfFloat・MSAA 4× のパスを 3 回通し、そのたびに深度も含めて解決（resolve）していた。

**決定**:
- ポストは `src/render/post.ts` に自前で持ち、「シーン（MSAA 4×・HalfFloat・深度は解決しない）→ ブルーム（半解像度のミップ鎖）→
  最終 1 パス（ブルーム加算 + 色調 + ビネット + フラッシュ + sRGB 出力、画面へ直接）」の 2 工程にする。
  ブルームの式・ミップ構成・色調の式は旧構成（UnrealBloomPass / 旧 GradeShader / OutputPass）と同じ。EffectComposer は使わない。
- 描画解像度は動的に調整する（`src/render/adaptive-resolution.ts`、純粋ロジックで vitest 済み）。段は pixelRatio 1.5 → 1.25 → 1.0
  （デバイスの DPR を超える段は潰す）。実フレーム間隔の 60 フレーム平均が 21ms を超えたら 1 段下げ、17.6ms 以下が 6 窓（約 6 秒）続いたら 1 段戻す。
  戻して失敗した段は次に戻すまでの待ちを倍にして振動を防ぐ。起動直後と段の切り替え直後は捨てる。
- URL: `?dpr=1.25` で解像度を固定、`?adaptive=0` で動的調整だけ止める（スクリーンショット・計測用。`npm run shot` は止めて撮る）。

**試して捨てた案**: シーンを RGBA8（sRGB 格納）にして帯域を半分にする案。クリスタルなどの発光物は 1.0 を超える値でブルームを出しており、
LDR に潰すとブルームがほぼ消えた（旧構成との画像比較で確認）。HDR のまま保つ。R11G11B10（HDR で 4 byte/px）は端末対応が要るので、
既定にはせず `?perf=1` の計測行に入れてある。

**検証**: 旧構成と同じ決定的なフレームで画像比較し、背景・ブルーム・色調は差が 2/255 以内（キャラの輪郭の縁は実行ごとの揺れと同程度）。
ヘッドレス（SwiftShader）でポスト分の時間が約 33% 減（CPU ラスタライザなので実機の値ではない）。実機の fps は本人が再計測する。

**代償**: ポストを自前で保守する（パスは 2 + ブルーム 11 回で単純）。最小段 1.0 では画面がやや甘く見える場面がありうる（2388×1668 の画面に対し 1194×834 相当）。

**見直し条件**: 実機の再計測で 60 fps に届かない場合、`?perf=1` の行（ブルーム 1/4 解像度・MSAA 切・R11G11B10・影・輪郭線）を見て次の手を選ぶ。

## ADR-012 攻撃モーションは手付け（キー → IK → 焼き込み）で作る

**状態**: 採用（2026-10-03）。ADR-010 の「攻撃モーションを Meshy ライブラリから取る」部分を置き換える。1 段目（combo1）から始め、2・3 段目、重撃・回避へ広げる。

**背景**: 実機で「攻撃モーションはやはりまだ違和感が大きい」。Meshy の斬りクリップは (1) 全身が振り回され重さが無い、(2) 区間を切り出してつなぐと段の境目でポーズが跳ぶ
（フェードで 70m/s の剣先になる）、(3) 腕の挙上が大きいと脇が破れる（129° 超）、(4) 片足が 1.6〜3.5cm 浮く、(5) 手の持ち方と剣の向きが合わない、という問題を持ち、
区間の選び直しやクロスフェードの調整では直せなかった。モーション自体を、こちらの狙いどおりに作れる必要がある。

**決定**: 攻撃のポーズを「**どこに剣があり、体がどう向き、足がどこにあるか**」で書き、腕と脚を IK で関節に直して 60fps の `AnimationClip` に焼く。
- `src/character/ik.ts`（2 ボーン IK・座標系・蝶番）/ `rig.ts`（骨の親子・基準ポーズ・蝶番軸・グリップの純粋なデータ）/ `pose-solver.ts`（1 フレーム分の意図 → 全ボーンの回転）/
  `authoring.ts`（キー列 → タイムライン → サンプル → 焼き込み）/ `rig-capture.ts`（読み込んだ GLB から Rig を作る）。データは `src/character/data/*.ts`（combo1.ts）。
- 体幹（腰・胸・頭）は idle の t=0 に対する差分回転（yaw / pitch / roll）。剣の位置は右肩からの極座標 [方位°, 仰角°, 距離] を**胸の座標系**で書く（胸をひねると腕と剣がいっしょに動く）。
  剣の向きは「刃の向き + 面の法線のヒント」。肘は pole（向かう方向）で決める。足は**ワールドに固定**した位置で書き、ルートが進んでも滑らない（届かなければ腰を下げる）。
- 基準ポーズは idle クリップの t=0（Meshy のバインドポーズは左右非対称で、そのまま使うと片腕が浮く）。肘・膝の蝶番軸は走りクリップの曲がったフレームから**実測**する
  （cross(上腕の向き, 前腕の向き) を骨のローカルへ戻して平均。実機の資産で腕のばらつき 0.003°、脚 0.7°。本当に蝶番として動いている）。
- 剣はグリップ（`HERO.sword`）から逆算して手首の位置と手の回転を決める。前腕のねじれは前腕と手首で半分ずつ。
- 前進（踏み込み）は authored の `rootZ` カーブに従い、`Player.stepAttack` が毎ステップの差分で動く。攻撃データ（`AttackDef.authored`）が持つのは当たりの時刻だけ。
- クリップは読込時に焼く（37 フレーム、ミリ秒）。Rig 外の骨（head_end など）は idle の姿勢の定数トラックで固定する（トラックが無いと再生のたびに元の状態へ戻る）。

**試して捨てた案**
- **ねじれの自動最適化を実行時に入れる**: 手首のねじれ・曲がりが最小になる剣の roll を毎フレーム探す案。刃の面が斬りの面から外れ（横腹で叩く）、局所解で roll が跳ぶ恐れがあるのでやめた。
  代わりにオフラインの探索（`tools/scratch/combo-opt.scratch.ts`、git 管理外）で候補を出し、キーに `roll`（度）として書く。
- **キー間をスプライン補間にする**: 速度の折れは 60fps の 6〜8 フレームの斬りでは見えない。ポーズ（キー）の質と最高速の位置のほうが効く。必要になったら足す。
- **手首の曲がりを骨の Y 軸で測る**: 手ボーンの Y 軸は指の向きから約 22° ずれているので、idle でも 33° と出る。`HERO.hand.right.f`（指の向き）で測る（idle 50° 基準）。

**検証（1 段目、実機の資産）**: ゲーム内で 3 方向 + 手元の近接を撮って確認（脇のささくれなし、手首の破綻なし）。上腕の最大挙上 104°（目安 130° 以下）、肘は伸び切りの手前（最小 11°）、
接地足の滑りは 0.0cm（初回は最大 3cm: アニメは攻撃開始の描画で 1 フレーム進むので、sim の前進を 1 フレーム先にそろえて解消）、剣先の最高速は体の前を通る瞬間でそこから減速（当初「約 25m/s」と書いたのは測り方の誤りで、剣先の実測は 119m/s だった。のち 85m/s に下げた。下の追記）。
手首のねじれは最大 127°（前腕と手首に半分ずつ）、曲がりは idle 基準から約 +50° で、見た目に破綻はないが、近接で見える段が出たら `roll` で詰める。

**代償**: ポーズを手で書く労力がかかる（1 段で 5〜6 キー）。指は動かない（Meshy のリグに指ボーンがない）ので、握りは固定。（2・3 段目は 2026-10-03 夜に手付けになった。下の追記）
**見直し条件**: 手付けの質が iPad 実機で「違和感が残る」と言われたら、キーの数・補間・グリップ角の可変（掌の中で剣を回す）を検討する。

**追記（2026-10-03 夜）: 2・3 段目も手付けにした／連鎖の仕組み（`continueFrom`）**
実機の指摘「1 段目はだいぶマシ。2 撃目以降は体の形が変形するなど課題が多い」。原因は、2・3 段目が Meshy の Left_Slash / Thrust_Slash のままで、1 段目の終わりの姿勢からクロスフェードしていたこと
（腰のひねり方が違うクリップ同士を混ぜると胴がねじれてつぶれる）。そこで 2 段目（combo2: 右逆袈裟）・3 段目（combo3: 右の突き）も手付けにし、Meshy の区間は撤去した。
- **`AuthoredAttack.continueFrom = { attack, t }`**: 前の技の時刻 t の姿勢から始める。t=0 のポーズ（体幹・剣・両手・足・腰の高さ）が前の技の時刻 t と一致するので、受付時点のつなぎ目で姿勢が跳ばない。
  キーの無いチャンネルは idle ではなく前の姿勢のまま保つ（`'idle'` と書けば本当の idle）。ルートは新しい攻撃の原点に付け替える（rootZ は 0 から。足の z は「前の足の位置 − 前のルートの前進量」＝世界での位置は変わらない）。
  `rootZCurve` は前の技に依存せず 0 から数える（sim が見た目と切り離して使える）。`attacks.test.ts` が「continueFrom が前の技のクリップと cancelAt を指す」ことを検査する。
- **受付中は姿勢を保つ**: 受付（cancelAt）から戻りの手前までは振り抜きの姿勢を保ち（combo1 は 0.37〜0.5、combo2 は 0.32〜0.45）、そのあとで idle に戻る。遅めに押してもつなぎ目が跳ばない。
  代償として単発の硬直が 0.07〜0.13 秒延びる（回避キャンセルは持続の後からできる）。保持のあとの押下（戻りの途中）は、フェード 0.05 秒で 2 段目の開始姿勢へ引き戻すので、右足が最大 7cm/フレーム動く（測定のみ。目立つなら戻りを短くする）。
- **斬りの速度**: 1 段目の剣先が 3 フレームで 2m 動いて（119m/s）コマ飛びに見えたので、斬りの区間を 0.055 → 0.075 秒に延ばして最高速を 85m/s（1 フレーム 1.4m）に下げた。2 段目も最高 81m/s。
- **手首のねじれが ±180° をまたがない**: 3 段目の突きは面の向きの取り方でねじれが 109° → 156° → −125° と折り返して、前腕の骨が 1〜2 フレームで反転しうる値になった。面を「平らな面が上」（`face: [0,1,0]`）にして 109° → −52° の連続な変化に収めた
  （ねじれは `swingTwist` で ±180° に折り返されるので、キー列の途中で 180° をまたぐと前腕が反転する。`combo-roll2` / `combo-diag` の表で確認する）。
- 診断値: 3 段とも腕・脚のクランプ 0、握りの誤差 1e-16 m、上腕の最大挙上 104° / 92° / 92°、手首のねじれ最大 128° / 126° / 109°、接地足の滑り 0.0cm（3 連続でも。3 段目の後ろ足は小さく浮かせて引き寄せる）。

**追記（2026-10-03 深夜）: 左手の置き場／重撃・回避も手付けにした**
実機の指摘「もう片方の手が手持ち無沙汰になっているのが気になる。何も持っていない場合は違和感のない手の形にして」「重と回避にも手をつけてみましょう」。
- **左手（素手）**: 指ボーンが無く手の形は変えられない（力を抜いて軽く握ったメッシュ）。形ではなく**置き場所で意味を持たせる**。腕をまっすぐ伸ばすと手が力なく垂れて見え、腹に当てると腹を押さえて見え、
  体の中心へ寄せると胸を抱えて見えたので、(1) 肘は必ず曲げる（距離は腕の長さ 0.487m の 0.8 倍以下）、(2) 手は体から離す、(3) 剣の動きと逆に動かす（引き手）、の 3 点を守る。
  共通のポーズを `src/character/data/offhand.ts` に置いた: 構え手（左肩の真正面・みぞおちの高さ、振りかぶりと溜め）/ 引き手（左腰の前、斬りに合わせて引く）/ 脇（左腰の横に垂らす、振り抜き後）。
  盾を持つ場合は同じ枠（左腕の置き場）を盾持ちのポーズに差し替える想定（`docs/06-moveset-ideas.md`）。
- **重撃（heavy）**: 縦斬り（斬りの面 tilt = 90°）。0 → 0.38 腰を落として体を反らせ剣を頭上へ（0.44 まで頂点で一拍）→ 0.51 に剣が前を水平に通る最高速（82m/s）→ 0.58 に前下で止まる。
  右足の大踏み込み（0.3 → 0.53、弧 0.16m）でルートが 0.5m 進み、左足は戻りで追いつく。全体 1.0 秒（60f）。剣先は止まった所で床に約 13cm 食い込む（叩きつけた見え方。気になれば角度を詰める）。
  診断値: クランプ 0、上腕の最大挙上 108°、手首のねじれ最大 85°、肘の最小曲がり 43°。
- **回避（dodge）**（**superseded by ADR-019**: 実機で崩れて見えたため、前転と後ろステップに作り直した）: 低く前傾して 2 歩で駆け抜けるダッシュ。剣は右腰の後ろに水平に寝かせる。0.04 → 0.46 で 3.1m（最高 10m/s。旧 Meshy の前転は初速 9.5m/s・3.6m）。右足を振り出して 0.2 に着き、0.15 に蹴った左足が 0.34 に前へ着く（0.15〜0.2 と 0.3〜0.34 は両足が浮く）。全体 0.58 秒（35f）。
  最初の版は足の運びと腰の沈みを間違え、腰が地面すれすれの滑り込みに見えた。原因は「後ろ足が腰から 0.95m 後ろに残った」ことで、**蹴り足は腰から約 0.5m 後ろになった時点（ルートの進みから逆算）で離す**ように直した。
  診断値: クランプ 0、上腕の最大挙上 38°、手首のねじれ最大 112°。
- **回避の前進も rootZ に従う**: これまで回避の前進は初速 9.5m/s・減衰の定数（`DODGE.speed`）だったが、手付けのクリップと一致しないと足が滑るので、`DODGE.clip`（= `DODGE_CLIP`）の rootZ カーブを使い、
  `Player.stepDodge` が攻撃と同じ 1 フレーム先にそろえた差分で進む。無敵は 3〜20f（0.05〜0.33 秒、飛び出しから着地まで）、攻撃へのキャンセルは 26f 以降（立ち上がりの手前）。
  Meshy の `heavy` / `dodge` の区間と `HERO.dodge.rate` は撤去した。`attacks.test.ts` に重撃と回避の検査（前進の単調性・最高速・無敵とキャンセルの順序）を足した。
- **重撃の入力は暫定**: 専用の「重」ボタン（`InputIntent.heavyPressed`、キーボードは H）を置いた。コマンド構成の決定（`docs/06-moveset-ideas.md`）まで、実機で動きを確認するための仮。
- 実機（ゲーム内）の接地足の最大の動き: 重撃 0.9cm/フレーム、回避 1.6cm/フレーム、3 連コンボ 1.9cm/フレーム（いずれも着地・離地の 1〜2 フレームのみ）。


**追記（2026-10-04）: 踏み込み（ステップイン）を強めた**
実機の指摘「踏み込みが足りない？のが違和感かもしれない。よくある 3D アクションゲームのモーションを参考にしてみて欲しい」。
- **測定（改修前）**: 着地の瞬間の前足は腰（ルート）より 1 段目で 0.12m 前、2・3 段目は腰の真下かそれ以下。足の幅は 0.5m 以下、腰の沈みは 5〜7cm、ルートの前進は 0.3m（重撃 0.5m）。
  足は「ルートといっしょに運ばれる」だけで、**前へ踏み出して体重を乗せる**動きになっていなかった。2・3 段目は右足が剣の通過（0.15s）より遅れて 0.23s に着く（着地より先に斬っていた）。
- **参考にした作り**: 軽い攻撃は 0.4〜0.8 秒・予備動作 0.1〜0.2 秒で、ルートモーションで 0.5〜1m 前進して間合いを詰める。力は足 → 腰 → 胸 → 腕 → 剣の順に伝わる。
  斬りの当たる瞬間に足を着き、体はそこで止まって振り抜きの余韻が残る。フェンシングのランジは前足が 0.3m 前へ出て、最終の足の幅が腕の長さの約 2 倍（約 1.45m）になり、
  力は「腕の伸び → 腰の前進 → 膝がつま先の上 → 後ろ足の回転」の順に出る。出典: [Sword melee animation guide](https://mocaponline.com/blogs/mocap-news/sword-melee-animation-guide) /
  [Combat animation game dev guide](https://mocaponline.com/blogs/mocap-news/combat-animation-game-dev-guide) / [Anatomy of an enemy attack in Dark Souls 3](https://www.gamedeveloper.com/game-platforms/anatomy-of-an-enemy-attack-in-dark-souls-3) /
  [Max your lunge (Guy Windsor)](https://www.guywindsor.net/wp-content/uploads/2013/03/Max-Your-Lunge-2007.pdf) / [Pixelblog 9: melee attacks](https://slynyrd.com/blog/2018/9/8/pixelblog-9-melee-attacks)。
- **作り直し（combo1〜3・重撃）**: 次の 7 つを守る。
  1. **足は腰の前後へ開いて着地**する: 前足は腰の 0.3〜0.4m 前、後ろ足は 0.3〜0.4m 後ろ（幅 0.5〜0.8m）。
  2. **ルートは着地まで加速し、着地で減速**する（`in` → `out` の 2 区間で、加速と減速の最高速を揃える。1 段目は約 4.1m/s）。着地のあとも腰が前足の上まで流れる。
  3. **着地は剣の最高速の直前**（1 段目 0.235 → 0.245、2 段目 0.16 → 0.17、3 段目 0.17 → 0.18、重撃 0.5 → 0.51）。
  4. **着地で腰が沈み、体が前へ倒れる**（腰 −0.14〜−0.2m、胸の前傾 10〜24°）。予備動作でも腰を少し沈めて後ろ足に体重を乗せる。
  5. **後ろ足は床を滑らせず、小さく浮かせて引きつける**（空中で最大 10m/s ほど。接地中の滑りは 0）。足が前へ出る間もルートが先行して、足が腰から 0.5m 以上離れて腰が自動で下がることがない。
  6. **腰 → 胸 → 腕・剣の時間差**（`src/character/data/stagger.ts` の `pose()`。腰の回転を 0.03 秒、胸と頭を 0.015 秒だけ早く完了させる。腰の沈みと前傾、足は基準の時刻）。
     全部が同時に動くと体が一枚の板のように回る。
  7. **受付（cancelAt）から先はルートを止める**。遅めに押しても、次の技の原点と見た目がずれない（`attacks.test.ts` が検査）。
- **数値**: 着地の瞬間の前足の位置（腰から）/ 後ろ足 / 幅 / ルートの前進（着地まで → 終端）:
  1 段目 +0.39 / −0.34 / 0.73 / 0.30 → 0.57m（旧 +0.12 / −0.38 / 0.50 / 0.3m）。2 段目 +0.27 / −0.26 / 0.53 / 0.34 → 0.58m（旧 0.00 / −0.17 / 0.17 / 0.3m）。
  3 段目（突き。ランジ）+0.39 / −0.42 / 0.81 / 0.34 → 0.60m（旧 +0.01 / −0.41 / 0.42 / 0.3m）。重撃 +0.37 / −0.37 / 0.74 / 0.48 → 0.81m（旧 −0.01 / −0.40 / 0.39 / 0.5m）。
  3 連の総移動はおよそ 1.7m、重撃は 0.81m。足を空中で運ぶ速さは最高 6〜10m/s（走りの足の速さ）。腕・脚のクランプ 0、腰の自動補正（足が届かず腰を下げた量）は重撃の着地直前（0.45〜0.48s）の最大 0.05m だけ（沈みを前倒しする向きなのでそのまま使う）で、ほかは 0。
  剣先の最高速は 1 段目 89m/s（0.233s）・2 段目 67m/s・重撃 84m/s。
- **足を手で書くときの計算**: 足首の腰（ルート）からの前後位置 A = 「idle の足首 − 腰」（左 +0.136 / 右 −0.094）+ 足の z − ルートの前進 − 腰の z（前傾）。
  脚の長さは約 0.75m なので、腰の高さが 0.17m 下がっていれば前足は +0.5m まで、後ろ足は −0.45m まで届く（届かないと腰が自動で下がる）。
  戻りで idle に揃う条件は「最後に残る足の z = ルートの前進」。2・3 段目は着地した右足が idle では後ろの足なので、戻りで左足が前へ出て右足が少し引く。
- **代償・調整**: 連続コンボで大きく進む（総 1.7m）。進みすぎ・足りないは、各ファイルのルートと足の z（着地の位置）を同じ率で増減すると、つなぎ目を保ったまま変えられる。足の運びが速すぎて見えるなら、剣の通過を 0.02 秒遅らせる。
  後ろ足のかかとを上げる（`pitch` + `lift`）のは未実装（足は平らなまま）。**実機で未確認**。

## ADR-013 コマンド構成は「攻撃 / 回避 / ガード」の 3 つにする（案 A）

**状態**: 採用（2026-10-04）。**実装は M3 の後**（`CLAUDE.md` の最優先原則: デモ完成まで武器・技・防御などの新システムには着手しない）。

**背景**: 「少ないコマンド数（最大でも 3 種程度）で色々な剣のモーションのバリエーションを」という指示に対し、`docs/06-moveset-ideas.md` に 3 案を出した
（A: 攻撃 / 回避 / ガード、B: 弱 / 強 / 回避、C: 攻撃 / 回避 / 特技）。2026-10-04 に本人が **案 A** を選んだ。
iPad は両親指で、画面の右下にすでに攻撃・回避・LOCK（と確認用の「重」）が並ぶ。ボタンを増やさず、入力の種類・スティック方向・直前の行動で技を出し分ける案 A が、
指の置き場と作る本数（技 1 本は手付けで数時間）の両方に合う。盾（左手）の役割がそのままガードボタンになり、左手の件（盾か素手か）とも噛み合う。

**決定**
- ボタンは **攻撃 / 回避 / ガード** の 3 つ。技は次の軸で出し分ける: 攻撃のタップ / 長押し、スティック方向（押した瞬間）、コンボの位置、直前の行動（回避直後など）。
- **重撃は攻撃の長押し**。押した瞬間は軽攻撃の予備動作に入り、まだ押していれば頭上の構えで止まり、離すと振り下ろす（押下時間を待ってから軽攻撃を始めると全攻撃が遅れるので）。
- **ガード**は左手の役割。盾あり: 保持で構え、敵の攻撃の直前のタップで弾く（パリィ）。盾なし: 剣を体の前に立てて受ける。盾は拡張フェーズ。
- 作る順番（M3 の後）: ① 回避直後のダッシュ斬り（`continueFrom` で安く作れる）② スティック方向の 1 撃目（前突き / 後ろ払い / 横薙ぎ）③ 長押しの溜め → 重撃 ④ ガード / パリィ ⑤ ジャスト回避の反撃。
- 数の目安は、攻撃 8〜10 技・ガード側 2〜3 技・反撃 1〜2 技（ボタンは 3 つのまま 13 技前後）。

**いまのコード（暫定のまま）**: 専用の「重」ボタン（`InputIntent.heavyPressed`、キーボードは H）は残す。上の ③ で長押しに置き換えるときに外す。ガードのボタンはまだ無い。
**→ 更新（2026-10-04、ADR-018）**: ①②③ を実装し、「重」ボタン（`heavyPressed`）は廃止して長押し（`attackHeld`）に置き換えた。ガード（④）は M4-2。

**未決**: 盾を標準にするか、素手を標準にして盾は装備で出すか（`docs/06-moveset-ideas.md` §4・§6）。ガードを入れる M3 の後に決める。
**→ 決定（2026-10-04、ADR-020）**: **素手を標準にして、盾は装備で出す**。ガード（④）は M4-2 で実装した。

**代償**: 長押しとスティック方向に技が隠れるので、操作の発見しやすさ（チュートリアル表示）が要る。ガードが入るまで、左手は構え・引き手・脇に置くだけ（`offhand.ts`）。
**見直し条件**: 実機で長押しの判定がもたつく、またはスティック方向の技を誤爆するなら、案 B（強ボタン）の追加を検討する。

## ADR-014 ヒット判定は「攻撃者に付く前方の領域 × 敵の円」で行い、剣先の軌跡では判定しない

**状態**: 採用（2026-10-04）。ADR-003（XZ 平面のカプセル衝突）・ADR-004（フレームデータ駆動）の具体化。

**背景**: M2 の最初に「当たり」を作る。攻撃の剣先は手付けクリップで最高 85〜119m/s（1 フレーム 1.4〜2m）で動くので、
フレームごとの剣先の位置（または前フレームとの線分）で判定すると、相手の円（半径 0.5m）をすり抜ける・当たる時刻が演出と合わない。
物理エンジンを使わない方針（ADR-003）では、剣のボーンに追従する当たり判定のコライダーも持たない。

**決定**
- 攻撃側のヒットボックスは **攻撃者の XZ 位置と向きに付く領域**。形は 2 種類: `arc`（扇形。斬り。届く距離 `range` は相手の円の縁まで、`halfAngle` は片側の角度）と
  `line`（線分に幅。突き。`length` と `radius`）。相手の円の大きさぶんは判定に含める（扇の角度は円の見かけの広がりだけ広がる）。
- 領域は **持続フレーム（`activeStart`〜`activeEnd`）のあいだ毎 sim ステップ評価する**。攻撃者がルートモーションで進めば領域も一緒に進む。剣先の最高速とは無関係なので、すり抜けない。
- 被弾側（ハートボックス）は XZ の円（`Hurtbox` = 円 + id + 無敵フラグ）。高さ（Y）は見ない。
- **1 攻撃 1 対象 1 回**は `HitTracker`（対象 id の集合）。攻撃を始めるたびに `reset()` する（コンボの次段は新しい攻撃なので、同じ敵にまた当たる）。
  無敵の対象には当てず、記録もしない（無敵が切れたあと、持続が残っていれば当たる）。
- 持続の判定は「攻撃を始めてからの sim フレーム f が `startup ≤ f < startup + active`」。`Player.step()` の後に読むと、f は描画されている姿勢のアニメ時刻 f/60 に一致する。
- ダメージ・ヒットストップ・ノックバックは攻撃データ（`src/combat/data/attacks.ts`）、敵の HP・半径・ひるみ・ノックバックの掛け方は `src/ai/data/enemies.ts`。
- ノックバックは「指定の距離を指定のフレームで進んで止まる」（`Knockback`。線形に減速し、総移動量が距離ちょうどになる）。
- 命中の結果は `HitEvent`（ダメージ・ノックバック・ヒットストップ・方向・命中位置）。演出（ヒットストップ・フラッシュ・シェイク・数字）はこれを受け取る側が起こす。

**理由**: 当たる範囲を「技の見た目（振りの弧・突きの線）に合わせたデータ」として 1 か所で調整できる。純粋関数なので vitest で境界（縁・角度の継ぎ目・無敵・重複）を検査できる。

**代償**: 剣先が実際に通った所でなく「前方の扇」で当たるので、剣が敵の横を通っても扇の中なら当たる。見た目と当たりのずれは、`hitbox` の数値と持続フレームで合わせる。
高さの違う敵（空中・伏せ）は扱えない。

**見直し条件**: 大きな敵の部位ごとの当たり（頭だけ・弱点）、空中の敵、飛び道具が必要になったら、ハートボックスを複数の円/カプセルにする、または Y を含める。

## ADR-015 敵は FSM + 予備動作 + スーパーアーマー、プレイヤーは被弾後に無敵

**状態**: 採用（2026-10-04）。ADR-014 の続き（M2 の敵の攻撃・被弾）。

**背景**: 最初の敵（子鬼）を作ると、弱攻撃を連打するだけで敵が一度も攻撃できなかった（ボットで測定: 2.7 秒で撃破、被弾 0）。
敵は命中のたびにひるみ（22f）に入り、プレイヤーのコンボの受付間隔（20〜22f）と同じ長さなので、連続ひるみで完封される。
これでは予備動作（テレグラフ）も回避の無敵フレームも意味を持たない。

**決定**
- 敵の状態: `idle`（出現直後の待ち）→ `chase` → `windup`（予備動作 38f）→ `attack`（startup 3f + 判定 6f + 硬直 42f）→ `chase`、`hit`、`dead`。数値は `src/ai/data/enemies.ts`。
  予備動作の前半 22f はプレイヤーを向き続け、後半は向きを固定する（横へ動けば当たらない）。攻撃は判定の間前へ踏み込む。硬直のあと 40f は次の予備動作に入れない。
- **スーパーアーマー**: 予備動作の 16f 目から攻撃が終わるまで、ダメージが `armorBreakDamage`（30）未満の攻撃ではひるまない（ダメージは通り、ノックバックは 0.2 倍、フラッシュは出る）。
  重撃（34）は割り込める。前半（〜16f）は弱攻撃でも中断される。HP が 0 になる攻撃では倒れる。これで「攻撃を続けるか、避けるか、重撃で割るか」の選択ができる。
- 敵の攻撃の判定はプレイヤーの攻撃と同じ（ADR-014: 扇形/線分 × 円、1 攻撃 1 対象 1 回、無敵は当たらず記録もしない）。同じフレームに当たり合うなら、先にプレイヤーの攻撃を解決する（相打ちはプレイヤー優先）。
- プレイヤーは被弾すると `hit`（24f の操作不能）に入り、攻撃・回避は中断（先行入力も消える）、攻撃してきた側を向いて押される。**被弾後 56f は無敵**（ひるみの 24f を含む。連続被弾で即死しない）。
  HP が 0 なら `dead`（死亡クリップ）。無敵は回避の [3, 20]f、被弾後、死亡後の 3 つで、判定は `Player.body.invulnerable` に集約する。
- ヒットストップは sim だけを止める（`FixedStepper.timeScale = 0`）。止める長さは sim フレームで指定し、実時間（描画の dt）で数える。カメラ・エフェクト・UI は止めない（ADR-004）。

**暫定**: 全滅後の再スポーン（2.5 秒）、倒れてからの最初からのやり直し（3 秒）、頭上の HP バーは、M3 のリザルト・再戦・ロックオン HUD ができるまでの暫定。

**代償**: スーパーアーマーのせいで、弱攻撃のコンボは敵の予備動作の後半では止められない。ボットの目安は、連打のみ 3.6 秒で撃破・被弾 1 回、棒立ちは 20 秒で倒れる。
数値（HP・予備動作の長さ・アーマーの開始・無敵時間）は実機で見て調整する。
**見直し条件**: 敵が複数になったら、同時に予備動作に入る数の制限（攻撃権トークン）と敵同士の押し合いを足す。

## ADR-016 ロックオンとウェーブ戦闘・リザルト（M3）

**状態**: 採用（2026-10-04）。ADR-014・015 の続き。

**ロックオン**（`src/combat/lockon.ts`・`lockon-state.ts`、数値は `src/combat/data/lockon.ts`）
- ロックボタン: ロック中なら解除、そうでなければ **「画面の正面寄りの最寄り」** をロック（点数 = 距離 ×（1 + 0.7 × 正面からのずれ / π）。16m 以内）。対象がいなければ何も起きない。
- 切替: ロック中に右半分の **横スワイプ**（90px。1 回のドラッグで 1 回）、キーボードは Q / E。いまの対象から見て右（左）に最も近い角度の敵へ移る。その向きに敵がいなければ今のまま。連続しないよう 14f の間隔を空ける。
- 対象が倒れたら **残りの敵へ自動で移る**（いなければ解除）。22m を超えて離れたら解除。プレイヤーが倒れたら解除。
- カメラ（`ThirdPersonCamera.stepLock`）: sim で yaw を対象の方へ減衰補間する（ヨーの入力は使わない。ピッチは使える）。描画では注視点を対象へ 30% 寄せ、離れた敵が映る分だけ距離を引く（最大 2.5m）。ロックを解くとその向きのまま通常の操作に戻る。
- プレイヤー（`Player.setAim`）: 照準があれば、攻撃は対象の方を向いて始まり、立ち止まっているときも対象の方を向く。走るときはスティックの向き、回避はスティック方向（無入力なら向いている方の後ろ）。
- 見た目: 対象の胸に四隅の枠（ロックの瞬間に絞り込む）、画面上部に対象の名前と HP バー（頭上のバーはロック対象には出さない）、LOCK ボタンの点灯。

**ウェーブ戦闘**（`src/game/encounter.ts`、数値は `src/ai/data/encounters.ts`）
- デモの構成は 2 体 → 3 体の 2 ウェーブ。全滅させて 100f 後に次のウェーブ、最後を全滅させて 75f 後に勝ち。プレイヤーが倒れて 150f 後に負け（同時なら負け）。敵は「プレイヤーから見てアリーナの中心の向こう側」に、左右に散らして出る。
- **攻撃権**（`src/ai/swarm.ts`）: 同時に予備動作〜攻撃に入れる敵は 2 体まで。残りは攻撃の距離で構えて待つ。敵どうしは押し合って重ならない。
- 最後の 1 体を倒した瞬間と、プレイヤーが倒れた瞬間は **スローモーション**（`HitStop.slow`。0.3 倍 0.9 秒 / 0.35 倍 1.2 秒）。
- **リザルト**: VICTORY（撃破数・タイム・被ダメージ・被弾回数・S〜C のランク。ランクは時間と被ダメージの両方で決まる）/ DEFEAT。「もう一度」で最初から。連打の指で一瞬で再戦しないよう、出て 1.1 秒は押せない。リザルトの間は操作を受け付けない。暫定だった自動の再スポーン・やり直しは廃止した。

**代償**: ロック中はカメラを自由に回せない（ピッチのみ）。スワイプでの切替は、通常のカメラ操作と同じ領域なので、ロックしていないときの大きな横ドラッグでも「切替の入力」は出る（ゲームはロック中だけ使うので害はない）。
ボットで測った目安（2 ウェーブ・5 体）は、連打のみが約 19 秒でクリア・ランク A（被ダメージ 60）、回避を混ぜると被弾が減って S も出る、棒立ちは約 23 秒で敗北。数値は実機で見て調整する。
**見直し条件**: 敵が大きく増える・種類が増えるなら、攻撃権を敵ごとの重みづけにする。ロックの切替が誤爆するなら、スワイプのしきい値を上げる、または専用の切替ボタンを置く。

## ADR-017 効果音は WebAudio で合成する（音声ファイルを持たない）

**状態**: 採用（2026-10-04）

**背景**: M3 の完成定義に効果音（攻撃・命中・被弾・敵撃破）がある。音声資産の調達・ライセンス・容量・読込の手間を、個人用のデモのためにかけたくない。

**決定**
- 音はすべて **WebAudio のノイズと発振器の重ね合わせ** で合成する。レシピは `src/audio/data/sfx.ts`（層ごとに: 種類、周波数の from → to、フィルタ、attack、長さ、音量、遅れ）。外部依存も資産も増えない。
- 再生は `src/audio/sfx.ts`（レシピ → ノード。同時発音数 24 の上限、距離による音量、雑音は毎回違う位置から）。出力は `src/platform/audio.ts` の `AudioBus`（マスター → コンプレッサ → 出力）。
- **iOS Safari の作法は `src/platform/audio.ts` に集約**: AudioContext は開始画面のタップ **のイベントの中で** 作って resume し、無音のバッファを 1 つ鳴らす（`Hud.waitForStart(onTap)` が同期で呼ぶ）。
  止まっていれば以降のタップで再開を試す（電話・スリープからの復帰）。非表示で suspend。操作なしで始める `?autostart=1` や解放前は黙って何もしない。`?mute=1` で消せる。
- 鳴らす場面: プレイヤーの振り 4 種（当たりの 0.07 秒前に）・回避、命中（軽・重）・撃破、被弾、敵の予備動作の合図と振り（距離で音量）、ロック・切替・解除、ウェーブ、勝ち・負け、UI。
- 検証: `node tools/sfx-check.mjs`（`npm run build` のあと）が全音を OfflineAudioContext で書き出し、ピーク・実効値・長さ・終わりの静けさ（尻切れのプチ音）・直流成分を数値で検査し、`artifacts/audio/*.wav` を出す。`Sfx` は偽の AudioContext で vitest する。

**代償・既知の問題**: **耳での確認はしていない**（数値で「壊れていない・音量がそろっている」まで）。質感・音程・うるささは実機で聴いて、レシピの数値を直す。
iPad の無音スイッチ（消音）で WebAudio が鳴らない端末がある（ブラウザの仕様）。合成音なのでリアルな斬撃音ではなく、アニメ調の効果音の域。
**見直し条件**: 合成音の質感に満足できないなら、フリー素材などの音声ファイルを `public/assets/` に置き、同じ `SfxName` で差し替える（呼び出し側は変えずに済む）。

## ADR-018 コマンドの実装: 入力から技を選ぶ純粋関数と、攻撃の長押しの溜め

**状態**: 採用（2026-10-04、M4-1）。ADR-013（案 A）の実装。

**背景**: M3 でデモが完成し、拡張フェーズ（M4）の最初に「片手剣もコマンドの組み合わせで技を増やす」を入れる。ADR-013 で決めた案 A（攻撃 / 回避 / ガード の 3 ボタン）のうち、
攻撃側（タップ・長押し・スティック方向・回避直後）をここで作る。のちの盾（M4-2）・大剣（M4-3）が同じ仕組みを使えるよう、「どの入力でどの技か」と「技の数値」を分ける。

**決定**
- **技の選択は純粋関数**（`src/combat/moveset.ts`。vitest で検査）: 攻撃を押した瞬間の `stick`（none / forward / back / side）と `afterDodge`（roll / back / null）から技の id を返す。
  回避直後なら回避の種類のダッシュ技、そうでなければスティックで決まる。コンボの 2 段目以降（`AttackDef.next`）と溜めの放ちは通らない（Player が続きを管理する）。
- **スティックの読み方**: 大きさ 0.3 以上で「倒している」。ロックなしは常に「前」（攻撃は倒した向きを向いて始まるので、走りながらの攻撃 = 踏み込み）。
  ロック中は対象の向きから ±50° 以内が「前」、130° 以上が「後ろ」、その間が「横」。向きは対象のまま。数値は `src/combat/data/moveset.ts`。
- **技のセット（`SWORD_MOVESET`）**: なし = 弱攻撃 1 段目（→ 2 → 3）/ 前 = 踏み込み突き（`lunge`）/ 後ろ = 下がりながらの払い（`retreat`）/ 横 = 横薙ぎ（`sweep`）/
  ロール直後 = ダッシュ斬り（`dash`、逆袈裟の斬り上げ）/ 後ろステップ直後 = 踏み込み突き。回避が終わって 12f 以内、または回避のキャンセル可能フレーム以降に押すと「直後」。
- **重撃 = 攻撃の長押し**（「重」ボタンは廃止）: 押した瞬間は 1 段目の予備動作に入る（軽い攻撃が遅れない）。押し続けて 9f（0.15s、1 段目の斬りが始まる 0.17s の前）になったら溜め（`charge` 状態）へ移り、
  1 段目の予備動作の途中の姿勢から頭上の構え（`heavyCharge`、終端で止まる）になる。離すと構えが整ってから重撃（`heavy`、構えの終端から `continueFrom`）を放つ。
  構えが整って（18f）から 24f・54f 保持するごとに段階が上がり、威力が 1.0 → 1.25 → 1.6 倍（ダメージ・ノックバックの半分・ヒットストップ）。100f で自動で放つ。構えのあいだは動けず、向きだけロック対象へ向く。構えに入って 8f 以降は回避でキャンセルできる。
  剣が段階に応じて金色に光り、段階が上がる瞬間に閃いて合図の音が鳴る。
- **暴発の防止**: 長押しの判定は「この攻撃を始めたときに押していて、そこから一度も離していない」ときだけ（連打の指が触れたまま次の攻撃に入っても溜めない）。溜めに入れるのは 1 段目だけ（2 段目以降を押し続けても入らない）。
- 入力は `InputIntent.attackHeld`（ボタンを押している間 true）を追加し、`heavyPressed` を削除した。キーボードは J（長押しで溜め）。
- 数値（`ATTACKS` の lunge / dash / retreat / sweep / heavy、`CHARGES`）はすべて `src/combat/data/` にある。

**代償・既知の問題**: 長押しとスティック方向に技が隠れるので、操作の発見しやすさ（チュートリアル表示）が要る。技の手触り・長押しの速さ・スティック方向の誤爆は **実機で未確認**。
モーションは静止画の連続（`tools/motion-sheet.mjs`）と数値（`tools/motion-check.mjs`）で検査しただけで、動きの速さの感じは実機で見る。
**見直し条件**: 実機で長押しの判定がもたつく、またはスティック方向の技が誤爆するなら、ADR-013 のとおり案 B（強ボタン）の追加を検討する。
**追記（M4-3、ADR-021）**: 長押しの判定フレーム（`CHARGE_HOLD_FRAMES`）は溜めごとの値（`ChargeDef.holdFrames`。片手剣 9f / 大剣 12f）にした。クリップが 1 段目から続く時刻 × 60 と一致させる（テストで検査）。

## ADR-019 回避の作り直し: 前転（ロール）と後ろステップ、足の「腰基準」

**状態**: 採用（2026-10-04、M4-1）。ADR-012（手付け）の拡張。ADR-012 追記の「回避（2 歩のダッシュ）」を置き換える。

**背景**: 実機で「回避のモーションが崩れている」との指摘。モーションシートで側面から見ると、足が 1.5m 開く大股の飛び出しを 2 回繰り返し、剣は体の横へ針のように突き出ていて、
メッシュの変形ではなく **動きの設計そのもの**（回避というより大股のダッシュ）が崩れて見えていた。

**決定**
- 回避を 2 種類にする: **前転（ロール）** = スティックを倒していれば、その向きへ向きを変えて体を丸めて転がる（0.58s、前進 2.95m、無敵 3〜22f）/
  **後ろステップ** = 入力なし、またはロック中に対象から離れる向き（真後ろ ± 50°）へ倒したとき、向きを保って（対象を向いたまま）後ろへ跳ぶ（0.46s、後退 2.0m、無敵 2〜16f）。どちらも 26f / 22f 以降は攻撃でキャンセルできる。
- ポーズソルバに **足を腰の座標系で置く** 機能を足した（`FootTarget.rel`（0 = 世界に固定、1 = 腰に付く）と `lx/ly/lz`（腰の座標系の位置）、`knee`（膝の向きを腰の向きに追従させる））。
  ロール中は腰・胸・頭のピッチを 0 → 360° 回し、足は腰に付いて丸まって回り、着地で世界に固定し直す。後ろステップでは跳んでいるあいだ足が腰にぶら下がる。
  オーサリングの角度チャンネル（腰・胸・頭のヨー/ピッチ/ロール、足のヨー/ピッチ）は、`continueFrom` で姿勢を受け渡すときに ±180° を折り返して補間する（360° 回転の技のため）。
- ロールは「回転軸と平行に寝かせた剣」「逆さのとき腰を高く（頭が床に入らない）」「ルートの前進 ≒ 転がる球の周」の 3 点で成り立たせた。数値は `tools/motion-check.mjs` で床からの高さを骨単位で測って詰めた（頭の骨の最低 0.20m、剣先は床の上）。

**代償・既知の問題**: 見た目の確認は静止画の連続だけ。実機で見た「動きの速さ・距離・無敵のタイミング」は未確認。ロールの 0.58s は旧版（0.5s）より長い。
**見直し条件**: ロールが遅い・長いと感じるなら、`DODGE_CLIP` の時間と `DODGES.roll`（無敵・キャンセルのフレーム）を詰める。

## ADR-020 ガード・パリィ・盾: 素手が標準・盾は装備、構えは動けない、パリィで敵が崩れて反撃が通る

**状態**: 採用（2026-10-04、M4-2）。ADR-013（案 A）の ④ ガード / パリィの実装。ADR-013 の未決（盾を標準にするか素手を標準にするか）を決着する。

**背景**: M4-1 の実機確認のあと、本人の決定:「**素手を標準にして盾は装備で。2 系統ははっきりさせる**」（片手剣は左手が素手 / 盾、もう 1 系統は両手の大剣 = M4-3）。
ガードは左手の役割（ADR-013）なので、左手に何を持つかで構えの性能と動きが変わる。

**決定**
- **装備の組（ロードアウト。`src/combat/data/loadouts.ts`）**: `sword`（片手剣・素手。標準）/ `sword-shield`（片手剣 + 盾）。M4-3 で大剣（左手は塞がる）を足す。
  技のセット・溜め・ガード・走る速さ・クリップの版は装備で決まる（数値は attacks.ts / guard.ts / moveset.ts にあり、loadouts.ts は「どれを使うか」だけ）。
  **選び方**: 開始画面（チップ。選んだものは localStorage に保存、`?loadout=` で上書き）と、戦闘中の切替ボタン（右上。立っている・走っているあいだだけ。押すと次の装備へ）。
- **ガードは 3 つ目のボタン**（旧「重」の位置）。**押している間だけ構える**（`InputIntent.guardPressed` / `guardHeld`。キーボードは H、装備の切替は G）。
  - 構えは**その場から動けない**（向きだけ変えられる。ロック中は対象へ）。ADR-013 は「移動は遅くなる」としたが、手付けのクリップは全身を 1 つの姿勢で焼くので、歩きながらの構えは足が滑って崩れる（代償の節）。
  - 押した瞬間から構えに入る。先行入力は 12f（攻撃の持続が終わる・溜めの構え・回避のキャンセル可能フレームに入った時点で、押していれば構える）。
    構えに入って 4f 以降は攻撃・回避でキャンセルできる（弾いた直後の反撃はここから出る。スティックを倒していれば踏み込み突きなど、通常の技の選択）。
    構えは入って 8f までは解けず（連打でちらつかない）、解いてから 8〜12f は構え直せない（パリィの受付を開き続けられない）。
  - **盾**: 正面 ±80° の攻撃を 85% 軽減して受け止める（削りだけ通る。最低 1）、押されは 0.3 倍、受け止めた直後の硬直 12f。**構えに入ってから 10f（0.167s）はパリィ**。盾を持つと走る速さが 0.92 倍（盾の重さ）。
  - **素手**: 剣を体の前に斜めに構えて受ける。正面 ±60°、50% 軽減、押されは 0.6 倍、硬直 16f。パリィはない。
  - 構えの正面の外（横・背後）から来る攻撃は防げず、通常の被弾になる（構えは解ける）。
- **パリィ**（盾のみ）: 受付のあいだに敵の攻撃が当たると**弾く**。ダメージなし・押されなし・構えは保つ。敵は**体勢を崩す**（`stagger` 66f。予備動作・攻撃を中断し、スーパーアーマーは効かない。そのあと 30f は予備動作に入らない）。
  体勢を崩しているあいだに当てた攻撃は**反撃**: ダメージ 2 倍、ノックバック 0.5 倍（遠くへ飛ばさず、続けて当てられる）。崩れているあいだは何度当たっても崩れたまま（ひるみに上書きされない）。
- **盾の見た目**: 丸盾（`src/game/shield.ts`）を左前腕のボーンに付ける。面の向きは肘の蝶番軸から決める（曲げの外側 = 前腕を立てたとき前）。装備したときだけ表示。
  盾を持つ間は、攻撃・溜め・回避の手付けクリップを**左腕を盾の持ち位置に固定して焼き直した版**（`名前@shield`。`AuthoredSampler` の `leftHold`）で再生する（盾を構えたまま振る・転がる。体の左側に置くので剣の斬りが盾に当たらない）。
  待機も盾版（`idle@shield`。Meshy の待機は腕を下ろすので、盾の面が後ろを向いてしまう）。ガードの構え・受け・パリィは左腕を自分で決める手付けで、版は作らない。走りは Meshy のまま（腕と一緒に盾が振れる）。
- **演出**: パリィの受付のあいだ盾が水色に光る（弾けるタイミングが見える）、受け止め・弾いた瞬間に暖色の閃光、受け止めは小さなヒットストップと揺れ + 暖かい火花、パリィは強いヒットストップと揺れ + 水色の大きな火花 + 「PARRY」の文字。
  敵は体勢を崩すあいだ、のけぞって腕を振り上げ、水色に脈打つ。効果音は guard / parry / guardUp / equip を追加。リザルトに「パリィ」の回数（削りダメージは被ダメージに入れるが、被弾の回数には数えない）。
- 判定は純粋関数（`src/combat/guard.ts`: 向き・受付・軽減）と、`resolveEnemyAttacks` の防御の分岐（`Player.guardOutcome` → パリィ / ガード / 被弾）に分けた。Player は構えの状態機械、Enemy は `stagger`。

**代償・既知の問題**
- **構えは動けない**。複数の敵に囲まれると、正面の外からは防げない。歩きながらの構え（下半身は歩き・上半身は構え）は、クリップを部位ごとに重ねる仕組みが要るので拡張候補。
- **実機で未確認**: パリィの受付（10f）の難しさ、盾の軽減（85%）が強すぎないか、素手のガードの使いどころ、盾の重さ（走る速さ 0.92）との釣り合い、構えを解いたあとの待ち。数値はすべて `src/combat/data/guard.ts` / `loadouts.ts`。
- ガードできない攻撃（ガード破り）は未実装（敵が子鬼 1 種のため）。盾は 1 種（丸盾）。
- 盾版のクリップを起動時に焼く（全体で約 60ms@PC。クリップ数が倍になる）。大剣で左手が塞がるぶんも同じ仕組みで足せる。
**見直し条件**: パリィが難しすぎる・簡単すぎるなら parryFrames。ガードが強すぎるなら damageReduction と構えを解いたあとの待ち。歩きながら構えたいなら上半身の合成を検討する。
**追記（M4-3、ADR-021）**: パリィの数値は盾専用の `PARRY` から、**弾かれた敵の反応ごとのデータ**（`PARRY_EFFECTS`: `stagger` = 盾 / `down` = 大剣）に分け、`GuardDef.parryEffect` から引く形にした。盾の数値と挙動はそのまま。大剣のガード・パリィは ADR-021。

## ADR-021 大剣（両手持ち）: 左手が柄を握る、重く手数が少なく広い、パリィは盾よりシビアで弾かれた敵は倒れる

**状態**: 採用（2026-10-04、M4-3）。ADR-020 の 2 系統目（片手剣（素手 / 盾）と**両手の大剣**）。ADR-012（手付け）・ADR-018（コマンド）・ADR-020（ガード）の拡張。

**背景**: M4-2 の実機確認のあと、本人の指示:「盾はないが大剣でも盾よりシビアなパリィが可能。被パリィ時の敵の挙動も盾とは異なる。また、大剣は重く手数は少ないが高火力広範囲でこちらも色々なモーションが欲しい」。
大剣は盾を持てないので、**パリィの手段は剣そのもの**。盾の「受付が長くて安全に弾ける」と差をつけ、**狙って決めるぶん見返りを大きく**する。

**決定**
- **両手持ちの仕組み**（`AuthoredAttack.twoHanded`、`src/character/authoring.ts`）: 左手首の目標を、右手の握り（`grip`）と剣の向き（`blade`）から**毎フレーム導く**（右手の握りから石突き側へ `offset` = 0.24m）。
  手付けに左手（`left`）は書かず、左肘の向き（`leftPole`）だけ書ける（既定 `TWO_HAND_POLE`）。`continueFrom` の連鎖でも、前の技の導いた左手から続く。届かない姿勢は左腕のクランプとして `--stats` の armL に出る。
  **両手が柄に付くので、剣は胸の前から大きく外せない**（右肩 − 左肩は 0.24m、腕の長さは 0.44m。握りを右へ離すと左手が届かない）。大きな振りは**腰・胸のひねり**で作り、握りは胸の中心の近くを回す。
- **剣**（`src/game/greatsword.ts`）: 柄の中心（右手）から切っ先まで 1.62m、石突きは −0.4m（左手は下 0.24m）。右手のソケットに片手剣と一緒に付け、装備したほうだけ見せる。刃の光（溜め）・剣筋の帯は武器ごと。
  刃が長いので、腰・胸が前へ倒れていると前を向いた刃が下へ傾く（世界の仰角 ≒ 胸の座標の仰角 − 前傾）。**前傾の分だけ刃を上げて書き**、切っ先が床に刺さらないようにする（検査: 切っ先の最低 0.04m）。
- **手首のねじれ**: 大剣の刃は表裏が同じなので、`roll`（刃の軸まわり）は ±180° まで使える（片手剣は縁の向きがあり ±35°）。手付けの `roll` は **`?motionlab=1`**（ページ内で実リグに対して `AuthoredAttack` を焼いて統計を返す開発用フック。`src/debug/motion-lab.ts`）で、
  ねじれ・曲がりが小さく ±180° をまたがない組を探して決めた（実測: ねじれ ≤ 106°、曲がり ≤ 115°、腕・脚のクランプ 0）。
- **構え・待機・走り**: すべての技が構え（`GS_STANCE`: 剣を体の右前、腹の高さに、切っ先は前上がり）から始まり、構えへ戻る（`continueFrom`）。待機は構えの息づかい（`idle@greatsword`）、
  走りは **Meshy の走りの胴・脚のまま、腕のトラックだけを担ぎの姿勢で固定**（`overlayPose`。剣を体の右前に立てて持つ。走りは胴が前へ傾くので刃を立てて書く）。装備を替えたときは待機・走りのクリップを装備の版へ選び直す。
- **技のセット**（`GREATSWORD_MOVESET`。片手剣より予備動作が長く（約 0.3 秒）、ダメージ約 2 倍、範囲が広く、ヒットストップ・ノックバックが大きい。硬直も長い。数値は `src/combat/data/attacks.ts`）

  | 入力 | 技 | 動き | ダメージ | 範囲 |
  |---|---|---|---|---|
  | タップ | `gs1` | 右上 → 左下の袈裟斬り。左足を踏み込む（0.7m） | 22 | 扇 2.7m ±85° |
  | 1 段目の受付で再度 | `gs2` | 左下 → 右上の逆袈裟。**2 連で終わる**（手数が少ない） | 30 | 扇 2.8m ±90° |
  | 前 | `gsLunge` | 牛の構え（両手を頭の高さへ）から体ごと踏み込み（1.5m）、胸の高さへ貫く | 26 | 線 3.0m |
  | 後ろ（ロック中） | `gsRetreat` | 後ろへ 1.3m 跳びながら水平に薙ぎ払う | 18 | 扇 2.8m ±100° |
  | 横（ロック中） | `gsSpin` | 腰を沈めて跳び上がり、体ごと 1 回転して水平の円を描く（腰・胸のヨーを 360° 回す） | 30 | **円 2.7m（全方位）** |
  | ロール直後 | `gsDash` | 転がった低い姿勢から前へ 1.6m 跳び、真上から叩きつける | 34 | 扇 2.8m ±65° |
  | 後ろステップ直後 | `gsRise` | 低い姿勢から踏み込み、右下 → 左上へ斬り上げる | 24 | 扇 2.7m ±80° |
  | 長押し → 離す | `gsHeavy` | 頭上の構えから左足を大きく踏み込み（1.3m）、真上から叩き割る | 60 × 溜め | 扇 3.0m ±90° |

  子鬼のスーパーアーマー（`armorBreakDamage` 30）を割れるのは `gs2`・`gsSpin`・`gsDash`・`gsHeavy`。ヒットストップは 1 発 24f を上限（`HIT_FEEDBACK.maxHitStop`。溜めの倍率後）、ダメージ 20 以上は「強」の見た目（数字が大きく黄色）。効果音は大剣用に低く長い風切り 8 種。
- **溜め**（`CHARGES.greatsword`）: 12f（0.2 秒）押し続けると頭上の構え（1 段目の予備動作の途中。左足が床を離す前なので足を置き直さない）。構えが整ってから 30f・66f で段階が上がり、威力 ×1.3・×1.8（片手剣は ×1.25・×1.6）。最大 120f。
- **ロール・後ろステップ**: 片手剣のロールからルート・足・腰と胸の動きを引き継ぎ、**腕だけ作り直す**（`dodge@greatsword` / `dodgeBack@greatsword`。ルートの前進・長さは同じなので、sim の移動・無敵と見た目がずれない）。ロール直後 = `gsDash`、後ろステップ直後 = `gsRise` はこの版の受付の姿勢から続く。
- **ガード（盾なしでもパリィ）**（`GUARDS.greatsword`）: 両手で剣を体の前に立てて受ける。**パリィの受付は構えに入ってから 6f（0.1 秒）**（盾は 10f）。構えの動きそのものが「弾き」で、早すぎても遅すぎても弾けない。
  受け止めるだけのときの軽減は 65%（盾 85%・素手 50%）、正面 ±70°、押されは 0.5 倍、受けた硬直 14f、構え直しの待ち 14f（盾 12f）。**失敗すると痛い**。走る速さは 0.88 倍。
- **パリィの効果の種類**（`PARRY_EFFECTS`）: 弾かれた敵の反応を構えごとのデータにした（`GuardDef.parryEffect`）。

  | | `stagger`（盾） | `down`（大剣） |
  |---|---|---|
  | 敵の反応 | その場でのけぞって体勢を崩す（立ったまま） | **弾き飛ばされて倒れ**、寝て、起き上がる |
  | 押される距離 | 0.7m | **2.6m**（22f かけて滑る） |
  | 動けない時間 | 66f（1.1 秒） | **112f（1.9 秒）**、そのあと 50f は予備動作に入らない（盾は 30f） |
  | 反撃（ダメージ倍率 / ノックバック） | ×2 / ×0.5。**全期間** | **×2.4 / ×0.15**。倒れて起き上がる前まで（86f）。起き上がりの終わり（26f）は無防備だが倍率なし |
  | 演出 | ヒットストップ 9f、揺れ 0.05m、閃光 1.2、「PARRY」 | ヒットストップ 14f、揺れ 0.1m、閃光 1.7、「PARRY」（1.5 倍の大きさ）、重い効果音、倒れた音 |
  | 反撃の取り方 | 近距離のまま続けて当てられる | 遠くへ飛ぶので**踏み込みが要る**（突き・跳び叩きつけ・溜め斬りで届く）。1 撃が大きい（溜め斬りの反撃は子鬼を 1 撃で倒す） |

  敵は `down` 状態（`Enemy.parried(ev, effect)`）になり、`riposte`（反撃の倍率を持つ効果、受付のあいだだけ）を持つ。`resolvePlayerAttack` は `target.riposte` の倍率で反撃を計算する。見た目は後ろへ倒れて寝る（足元を軸に傾け、胴の太さぶん持ち上げる）→ 最後の 26f で起き上がる。
- **装備**: ロードアウト `greatsword`（表示名「大剣」。開始画面のチップ・切替ボタンは 3 つを順に回る）。左手が柄を握るので盾は持てない。

**代償・既知の問題**
- **実機で未確認**。確かめること: パリィの受付 6f の難しさ（狙って決められるか。厳しすぎないか）、倒れた敵への踏み込み（反撃に間に合うか）、大剣の重さの手触り（予備動作 0.3 秒・硬直・ヒットストップ）、各技の見た目と使い分け、走りの担ぎの見た目、ロールの見た目（剣を体の右へ水平に伸ばして転がる）。数値はすべて `src/combat/data/`。
- 左手は指ボーンが無いので、柄を握る形は作れない（位置だけ。手のメッシュは柄のそばに来る）。右手のソケットと左手のずれは目視で確認した範囲。走りの担ぎでは、左手が届く位置まで握りを上げてあるが、左腕はほぼ伸び切る（`gsCarry` の左腕のクランプは待機からの遷移の数フレームのみ）。
- `gsSpin` は全方位（半角 180°）。回転の見た目は 1 コマ 50〜70° で動くので、実機で目が追えるか見る。着地後は剣が体の右後ろに水平に残ったまま戻る（簡素）。
- 溜め斬りの切っ先は床すれすれ（0.04m）まで下りる。叩きつけの衝撃波・砂ぼこりは未実装。→ **追記（M4-5、ADR-023）**: 最大まで溜めたときの地割りで、剣が床に当たって跳ね返る技と、衝撃の輪・砂ぼこり・ひび割れの演出を実装した。
- 敵が子鬼 1 種のため、`down` が使えない（倒れない）大きな敵・ガード破りの攻撃は未実装。
**見直し条件**: パリィが厳しすぎる・簡単すぎるなら `GUARDS.greatsword.parryFrames`（4〜8f の範囲）。倒れた敵への反撃が間に合わないなら `PARRY_EFFECTS.down` の距離・時間。大剣が強すぎる・弱すぎるなら技ごとのダメージ・硬直。

## ADR-022 リグの補正: 骨をメッシュの断面の中心へ寄せ、胴の重みを位置から作り直す

**状態**: 採用（2026-10-04、M4-4）。ADR-010（資産の自動生成）・ADR-012（手付け）の補強。`hero.glb` の骨と重みを加工する（メッシュ・テクスチャ・アニメーションの意味は変えない）。

**背景**: M4-3 の実機確認で本人の指摘:「操作感は問題ない。モデルがやはり崩れている。特に腰回り。一度根本的にモデルの関節やリグなどを見直した方が良いのでは？色々な動きに対応できるよう精巧化した方が近道ではないですか？」
これまでの腰の対処（輪郭線・テクスチャ。docs/05「腰の背面の崩れ」）は**静止時**の見た目で、ポーズ中の腰は未確認のままだった。再現して測ると、**リグそのものが原因**だった（本人の見立てのとおり）。

**診断**（`tools/motion-sheet.mjs --mode weights|wsum:…|ybands`、`tools/measure-joint-centers.mjs`、`tools/waist-stress.mjs`）
1. **骨がメッシュの中心から全体にずれていた。** メッシュは x = +4.2cm を軸に左右対称（胴・腕・脚の断面の中心が ±0.1cm で一致）なのに、骨盤・背骨は x = −3.6cm（**7.8cm 右へずれ**、右のウエストの縁から 1.7cm 内側 = ほぼ表面）。
   股関節は大腿の中心から右へ 6.6〜9.3cm、左肩は肩の中心から 6.8cm 胸の中へ、膝・足首は右へ 3.4〜4.1cm、肘は 2.0〜2.5cm（全体に体の右へずれている）。腕の長さも左 48.7cm・右 43.8cm と非対称（メッシュの腕は左右とも約 46cm）。
   関節を軸に皮膚を回すスキニングは、回転の中心がずれていると、ひねる・曲げるたびに体の片側が余計に振られる（骨盤の軸が体の右の縁にあると、左のウエストは 2 倍近い腕の長さで振られる）。
2. **重みが胴で漏れていた（左右非対称）。** 脇腹（Hips の +14〜+20cm）に**腕の骨（LeftArm）の重みが 50〜80%**、腰（ショーツの縁）に**脚の骨（LeftUpLeg）の重みが 65%**。胸の骨（`Spine`）の重みは全体で 6（使われていない）、
   `Hips` は骨盤のごく一部（左の尻に山が 1 つ）。左の肩・脚の骨が体の反対側まで重みを持つ（総重みは LeftShoulder 2797 に対し RightShoulder 201）。腕を上げる・脚を踏み出すと、離れているはずの脇腹・腰の皮膚が引かれ、腰が細く潰れ、ショーツの縁がささくれる。
3. **手付けの 2 ボーン IK は「子の位置が親のローカル +Y 軸の上にある」ことを前提にしている**（`pose-solver.ts` の `limb()` は `frameRotation(_Y, …)`）。骨の位置を動かすなら、四肢の骨の向きも子へ向け直さないと、IK の目標に手が届かない（最初の試作で左手が柄から 4cm ずれた）。

**測った効果**（全 54 クリップ。盾・大剣の版と Meshy 由来の待機・走りを含む。`tools/waist-stress.mjs`。最悪値）

| 指標 | 補正前 | 補正後 |
|---|---|---|
| 腰の辺の伸び p99 / 最大（変形後 ÷ バインド） | 5.79 / 17.2（ロール） | **2.10 / 2.43** |
| 腰の辺の縮み最小 | 0.03 | 0.12（死亡の倒れ込み。股・膝の折れ目） |
| 腰の断面の大きさ（輪切りのバインド比。1 = 保つ） | **0.22**（腰が細く潰れる） | **0.96** |
| ひねりの集中度（隣の輪切りの相対回転 度/cm。手付けの技 ≤ 3.2、ロール 5.5、Meshy の斬り・死亡 ≤ 6.9） | 28.7（ロール） | **6.9**（Meshy の死亡） |
| 胸（脇の下・肩甲骨）の p99 / 最大 | 2.59 / 9.05 | **2.06 / 2.30** |

**決定**
1. **骨の位置の補正**（`tools/recenter-skeleton.mjs` + `tools/data/hero-joint-offsets.json`）: 各関節のバインド姿勢の位置を、メッシュの断面の中心（`tools/measure-joint-centers.mjs` で測る）へ寄せる。**目標の位置を絶対座標で持つ**ので、補正済みの GLB にかけても何も変わらない。
   動かすのは x だけ（骨盤〜頭 +7.8、股関節 左 +9.3 / 右 +6.6、膝 +3.4 / +4.1、足首 +3.4 / +3.6、肩 左 +6.8 / 右 +5.0、肘 +2.0 / +2.5、左手首 +3.2）。**右手首は動かさない**（剣の握り `HERO.sword` が手ボーンのローカルで調整済み）。
   - 逆バインド行列（IBM）・骨ノードのローカル位置・Hips の位置アニメーション（全キーに同じ差分）を一貫して書き換える。メッシュの頂点は触らないので、バインド姿勢の見た目は変わらない。
   - **四肢の骨（上腕・前腕・大腿・脛）のバインドの向きを、新しい子の位置へ最短の回転で向け直す**（IK の前提）。向け直した分 `D = R⁻¹·dR·R` だけ、その骨と子の回転（ノードの静止回転と全クリップの回転トラック）を共役で直す（`Q' = D_親⁻¹ · Q · D`）。
     全クリップで「バインドからの世界回転の変化」が元と同じになるので、Meshy の待機・走りなど既存の動きの意味は変わらず、**回転の中心だけが体の中心へ来る**。
2. **胴の再スキン**（`tools/reskin-torso.mjs` + `tools/lib/torso-weights.mjs`）: 胴（骨盤〜胸〜首の付け根）の重みを**位置だけの関数として作り直す**（腕・頭・髪・膝から下は元のまま。位置が同じ頂点には同じ重み）。
   - 背骨: Hips の +8.5cm（ショーツの上端）までは Hips 100%、素肌の帯（+8.5〜+24.5cm）で Hips → Spine02 → Spine01 → Spine へ連続的に移し（PoseSolver が腰・胸の回転を 0 / 1/3 / 2/3 / 1 で配るので、帯の中の回転は高さに対してなめらかに増える）、胸は Spine 100%。肩から首の付け根（+25〜+40cm）は作り直しを弱めながら Spine から neck の骨へ渡す。
   - 脚: 大腿の軸（股関節 → 膝）に沿った位置で、骨盤は Hips、大腿は UpLeg、間（股関節の上下 10cm）は連続的に混ぜる。左右は中心線からの距離で分ける。
   - 腕: **腕の軸への距離 ÷ 腕の半径 − 中心線への距離 ÷ 胴の半幅**（相対的な近さ）で胴か腕かを判定し、胴では腕の骨の重みを 0 にする。体の中心線から横に 17〜23cm 以上の頂点（腕・手・指）は元のまま（指は手首の骨から 20cm 近く先まである）。
3. **変形の崩れ度を測る道具と、資産の約束のテスト**: `tools/waist-stress.mjs`（全クリップで胴の辺の伸び・断面・ひねりを three.js のスキニングで測る。`--check` でしきい値を超えると終了コード 2）、`tools/hero-asset.test.mjs`（骨の左右対称・中心線・四肢の +Y 軸・Hips の位置トラック・腰の重みに腕脚が漏れないこと。補正前の資産では 4 項目が落ちる）、`tools/lib/torso-weights.test.mjs`。
   `tools/motion-sheet.mjs` に `--mode weights|wsum:<骨>|ybands|normals|wire`・`--no-outline`・`--tile` を足した（重みを色で見る、服の縁や関節の高さを帯で測る）。
4. **手付けのデータは 1 か所だけ**: 補正で左腕が 3cm 短くなる（48.7 → 46.7cm。右は 43.8 → 46.2cm で左右対称になる）ので、大剣のガードの握り `GUARD_HOLD.grip` の r を 0.40 → 0.36 にした（左手が柄に届かず腕が伸び切るのを防ぐ。左腕のクランプ 0）。
   大剣の構え・走りの担ぎは、待機から構えへ遷移する数フレームだけ左腕がクランプする（5 → 6、7 → 8 フレーム。もとから 5・7 フレームあった）。

**生成の手順**（`raw/` は git に入っていないので、`hero.glb` を直接加工する。元は `git show 1c85286:public/assets/characters/hero.glb`）
```
git show 1c85286:public/assets/characters/hero.glb > /tmp/hero-before.glb
node tools/recenter-skeleton.mjs /tmp/hero-before.glb /tmp/hero-mid.glb
node tools/reskin-torso.mjs /tmp/hero-mid.glb public/assets/characters/hero.glb
```
`build-character.mjs` を raw から通し直したときは、その出力にこの 2 つをかける。`recenter-skeleton` は何度かけても同じ（目標の位置）。`reskin-torso` は、腕との境目の「元の重みを混ぜる帯」だけ元の重みを使うので、補正前の資産にかけること。

**検討して退けたもの**
- **Blender の自動ウェイト・ボーンの追加（ねじれ骨）**: Blender のボーンヒートはこのメッシュで失敗済み（docs/05）。ねじれ骨は不要だった（回転の中心を体の中心へ寄せ、重みを高さになめらかに作れば、背骨の 4 本で断面 0.96 を保てる）。
- **腕の判定を「腕の軸から一定距離」にする**: 脇の下では腕が胴のすぐ脇にあり（脇腹は腕の軸から 8cm、中心線から 9cm）、脇腹まで腕と判定して腕の重みが残った。相対的な近さで比べる。
- **脇の下の移り変わりを広くする**（腕の重みを肩甲骨・脇の下で広い帯に散らす）: 腕が動いたときの皮膚のずれが増えて悪化した。**作り直しの範囲を首の付け根まで延ばす**（肩の線で切ると、そこが「胸は Spine、その上は腕に引かれる」境目になり、腕を上げるたびに背中に横帯状のずれができる）のが効いた。
- **姿勢の上限（腰↔胸の相対回転を制限する）**: 手付けの技の相対回転は最大 37°（ロールの丸め 68°を除く）で、Meshy の斬り・死亡（43°）の範囲に収まっている。原因は回転量でなく回転の中心と重みだった。
- **デュアルクォータニオン・補正形状**: 断面 0.96 まで保てたので不要。描画（トゥーン・輪郭線の shader）への影響も大きい。

**代償・既知の問題**
- **実機で未確認**。確かめること: 腰まわり（大剣・片手剣の振りかぶり・踏み込み・ロール・走りでの、ショーツの縁・ウエストのくびれ・尻の形）、手が柄・盾に付く位置（腕の長さが変わった）、足の接地（足首の関節をメッシュの足の中心へ寄せた。足裏の高さは変えていない）。
- 脇の下・肩甲骨は、腕が動くと皮膚がずれる（既知の「脇のほつれ」。補正前より小さいが残る。胸の最大の伸びは 9.05 → 2.30）。首・髪（うなじの毛）は元のまま。
- 股・膝の折れ目は縮む（ロール・死亡の倒れ込み。0.12〜0.35）。見えない内側。
- 腕・脚の長さが変わるので、手付けの値（握りの r・左手の置き場）を新しく書くときは、リグから読む長さ（`rig.length`）を基準にする。
**見直し条件**: ひねりの帯（`y0` / `y1` / `ease`）を実機の見た目で調整する。ショーツの縁・尻の形が気になるなら脚の混ぜ幅（`legRamp`）。肩・脇の下が気になるなら鎖骨の動き（現状は胸に従うだけ）を足す。

## ADR-023 大剣の左手を柄に合わせる・コンボの分岐・地面を叩く技

**状態**: 採用（2026-10-04、M4-5）。ADR-012（手付け）・ADR-018（コマンド）・ADR-021（大剣）の拡張。

**背景**: M4-4 の実機確認で本人:「崩れは解消されました。後気になるのは**剣の持ち方が攻撃モーション時に崩れていないか**と、**剣のモーションのバリエーションを今あるコマンドでもっと増やしたい**。特に大剣では**地面にあたるまで振り下ろす（地面にあたって少し跳ね返る）ような重厚感あるモーション**も欲しい。」

### 1. 握りの診断と、大剣の左手の修正

**診断**（`tools/motion-sheet.mjs --track`・`tools/grip-check.mjs`・`tools/motion-check.mjs --stats|--trace`）
- 右手の握りは「手ボーンの固定の位置と向き（`HERO.sword`）」なので、どの技でも手と柄の関係は変わらない（握りのずれ 0、剣の位置の誤差 0）。片手剣の技は握りが崩れていなかった（手首の曲がり・ねじれは技の姿勢で動くが、手と柄の関係は一定）。
- **崩れていたのは大剣の左手**。M4-3 の両手持ちは、左手首の**位置**だけを右手の握りの石突き側（0.24m）の柄の軸の上に置き、**手の向きは idle のまま**だった。そのため手のひらの中心は柄の軸から離れ（手首が軸上 → 手のひらは手首から約 7.5cm 先）、
  手の向きも柄と無関係なので、振りの途中で**平手が柄に載る・柄が手のひらの外を通る**見え方になった（拡大して確認。手のメッシュは指ボーンが無く、握った形ではなく「柄が手のひらを斜めに横切る位置と向き」で握りを見せている）。手首のねじれも最大 164°（前腕が 80° 以上ねじれる）だった。

**決定**
1. **左手の握りは右手の握りの鏡像**（`src/character/mirror-grip.ts`）: 両手のメッシュの座標系（指の向き f・親指側 t・手の甲側 d。`tools/measure-hand-axes.mjs` が頂点の主成分分析で測り、`HERO.handFrames` に置く）の対応で、右手の握り（位置・剣の座標系の 3 軸）を左手ボーンのローカルへ写す。
   **骨の向きではなくメッシュの座標系で写す**: 左手の手のメッシュは右手の鏡像だが完全ではなく（左手の指の向きは、右手を骨の向きで鏡に写したものから約 17° 違う）、骨の向きで写すと左手のひらに握りが合わない。
   左手系になる剣の座標系は、**面の法線を反転**して回転にする（右手と左手が柄の反対側から握る。両方の親指が刃のほうを向き、手の甲が外を向く。両手持ちの自然な握り）。
2. **PoseSolver の両手持ち**（`PoseInput.twoHand` = 石突き側への距離 m）: 左手の向き = 剣の向き × 左手の握りの逆（右手の `Rhand` と同じ作り）。手のひらの中心を柄の軸の上（右手の握りから石突き側へ 0.24m）に置き、そこから手首を逆算して 2 ボーン IK。前腕のねじれは肘と手首で分ける（右腕と同じ）。
3. **柄の軸まわりの回り方 ψ は自由**（柄は円柱）。手首のねじれ・曲がりが小さい ψ をソルバが選ぶ（費用 = (ねじれ ÷ 60°)² + (曲がりの 80° 超過 ÷ 40°)² + 弱い正則化 + 届かない罰。±120° を粗く走査して黄金分割で詰める）。
   ψ はそのフレームの姿勢だけで決まるので、`continueFrom` のつなぎ目の姿勢は前の技の同じ姿勢と一致する。谷が入れ替わる瞬間に ψ が跳ぶので、**焼き込みで 1 フレームの変化を 10° に制限**して連続にする（`bakeAttack`。最初のフレームは最良のまま）。
   （ψ = 0 から下るニュートン法は、前腕のねじれの ±180° の折り返しで谷に入れず、むしろ悪かったので退けた。）
4. 検査: `tools/grip-check.mjs`（手のひらの中心が柄の軸の上か・握りの向きが合っているかをフレームごとに、実際の骨で測る。`--check` で超過なら終了コード 2。待機から構えへ入る遷移の `gsStance` / `gsCarry` は最初の数フレームが届かないので対象外）、
   `tools/motion-check.mjs` に左手首の曲がり・ねじれ・ψ の列、`tools/motion-sheet.mjs --track grip|hands|handR|handL|tip`（握りを追尾して拡大）。テスト: `src/character/mirror-grip.test.ts`、`pose-solver.test.ts`（両手持ちの節）。

**効果**: 左手のひらの中心の、柄の軸からの距離は**全クリップで 0.0cm**（待機の腕から構え・担ぎへ入る遷移の数フレームを除く。もとから届かない）、握りの向きのずれは 0.2° 以下（`grip-check --check` 通過）。M4-3 の実装は手首を軸に置いていたので、手のひらは手首から約 7.5cm 先、軸から最大その分外れ、向きも柄と無関係だった。
柄まわりの回り方 ψ を自由にした効果（鏡像のまま ψ = 0 → ψ を選ぶ。左手首のねじれの最大）: ロール 152° → 91°、ロール直後の跳び叩きつけ 148° → 47°、溜め斬り 71° → 39°、ガード 98° → 75°、下がりながらの薙ぎ払い 144° → 114°。
残り: 1・2 段目の振り抜き（左へ流れた剣）は左手首のねじれが 140〜163° のまま（剣が左へ流れ、左腕が体を横切る姿勢では、柄の軸まわりの回り方では減らせない。肘の向きを動かす余地）。拡大して見ると手は柄に付いている。

### 2. コンボの分岐（スティックの向きで続きが変わる）

**コマンドは増やさない**（案 A のまま）。次段の受付（前の技の振り抜きの姿勢を保っている間）に攻撃を押した瞬間の**スティックの向き**（ロック中は対象に対して。`classifyStick`）で、続く技を選ぶ（`AttackDef.branches` / `pickFollowUp`）。
- 向きを倒していなければ今までどおり（`next`）。**普通の続きを奪わない**: `next` のある技の分岐は横・後ろだけ（前へ倒したままボタンを連打する人が多い）。`next` の無い技（コンボの終わり）は、**前へ倒したときだけ延長**する（そのまま押すだけでは今までどおり終わる）。
- ロックなしでは「横」「後ろ」が無い（倒せば前）ので、分岐は前へ倒す延長（大剣の叩き落とし・片手剣の打ち上げ）だけが出る。

| | 1 段目の受付 | 2 段目の受付 | 3 段目の受付 |
|---|---|---|---|
| 片手剣 | 後ろ（ロック中）→ **跳び退き斬り上げ** `comboHop` | 横（ロック中）→ **回転斬り** `comboSpin`（全方位） | 前 → **打ち上げ** `comboUpper`（跳び上がる縦の斬り上げ。3 連の延長） |
| 大剣 | 横（ロック中）→ **連携回転斬り** `gsSpin2`（全方位。右回り） | 前 → **叩き落とし** `gsDrop`（床を叩いて跳ね返る。2 連の延長） | — |

どれも前の技の受付時点の姿勢から続く手付け（`continueFrom`）で、足の位置もつなぎ目で合う（テスト）。片手剣の分岐先は盾版も焼かれる。分岐先からはさらに続かない（1 段だけ）。

### 3. 溜めの段階で放つ技が変わる

`ChargeDef.levelNext`（段階ごとの技。無ければ `next`）。**大剣は最大の段階まで溜めたとき（押し始めて約 1.7 秒）だけ地割り**（`gsSmash`）、途中で離せば今までの溜め斬り（`gsHeavy`）。威力の倍率（最大 1.8 倍）は地割りにも掛かる。片手剣は変えない。

### 4. 地面を叩く技（地割り・叩き落とし）

- **モーション**（`src/character/data/gs-smash.ts`・`gs-drop.ts`）: 剣が床に**当たる**まで振り下ろす（切っ先の高さ 0）→ 急に止まり → 剣が**少し跳ね返り**（切っ先が 0.5〜0.8m。体が反動で浮く）→ もう一度沈んで落ち着く → 長い硬直。地割りは溜めの構えからさらに振りかぶって左足を踏み込み、真上から叩きつける（1.2 秒）。叩き落とし（`gsDrop`）は 2 段目で右上へ抜けた剣を 1 段目の袈裟の軌道で左前の床へ叩き落とす（1.0 秒。小さめ）。
- **演出**（`AttackDef.impact` = 床に当たる時刻・体の前の距離・強さ）: その時刻に `Player.impactSerial` が増え、`Game` が **衝撃の輪・砂ぼこり・破片・床のひび割れ（`src/render/ground-fx.ts`）、画面の揺れ、ヒットストップ、音（`groundSmash`）**を出す（敵に当たらなくても出る）。数値は `GROUND_IMPACT`（`src/combat/data/hit-feedback.ts`）。
- **攻撃データ**: 地割りは威力 60（×溜めの倍率）・範囲 3.3m・220°（衝撃が周りへ広がる）、叩き落とし 38・3.0m・190°。当たりは床に着く手前から跳ね返りまで。硬直は地割り 1.2 秒（全体 72f。ほかは 60f 以内）。

**検討して退けたもの**
- 床に当たったあと剣を**物理で跳ね返す**: 手付けのキー（0.1 秒で 0.5m 持ち上がる）で十分に見え、物理エンジンは入れない方針（CLAUDE.md）。
- 分岐の入力を新しいボタン・長押しにする: ボタンを増やさず、受付での**スティックの向き**だけにした（前へ倒したまま連打しても普通のコンボが出る）。
- 左手の握りを骨の向きで鏡像にする: メッシュの左右差（約 17°）が出るので、手のメッシュの座標系で写す。

**代償・既知の問題**
- **実機で未確認**。確かめること: 大剣の両手の握り（振りかぶり・振り抜き・ロール・ガードで、左右の手が柄に付いて見えるか）、地割り・叩き落とし（床に当たる瞬間の間・跳ね返りの量・砂ぼこりと揺れの強さ・硬直の長さ）、分岐の出しやすさと誤爆（前へ倒したまま連打して普通のコンボが出るか、後ろ・横の分岐を狙って出せるか）。
- 大剣の 1・2 段目の振り抜き（左へ流れた剣）の左手首は、ねじれが 140〜163° まで残る（拡大では手は柄に付いている）。気になるなら左肘の向き（`leftPole`）を技ごとに書く。
- 右手の握りは変えていない（片手剣・大剣とも手首のねじれ・曲がりは技の姿勢のまま。最大 143°・116°）。
**見直し条件**: 地割りの溜めが長い（約 1.7 秒）・硬直が長い（1.2 秒）なら `CHARGES.greatsword.levels` / `gsSmash` の hold。衝撃の演出が強い・弱いなら `GROUND_IMPACT` と `GroundFx`。分岐の誤爆が多いなら、受付の窓（`cancelAt`）か、分岐の向きの範囲（`STICK_RULES`）。


## ADR-024 立ち姿の前傾・操作ガイド（連携の見える化）・連携の続きの技

**状態**: 採用（2026-10-04、M4-6）。ADR-018（コマンド）・ADR-023（分岐）の拡張。

**背景**: M4-5 の実機確認で本人:「**キャラが常にやや後傾姿勢なのが気になる。コマンドの入力方法がやや分かりづらいので、操作中にどの連携になっているのか分かりやすい工夫が欲しい。モーション、コンボ自体はさらに増やして欲しい。**」

### 1. 立ち姿の前傾

**診断**（`tools/scratch/lean*.mjs`＝骨の世界位置から腰 → 首の線の傾きを測る。+ が前傾）: 資産（Meshy）の待機は**腰 → 首が −6.9°（上体が後ろへ反っている）**で、手付けの攻撃・ガード・大剣の構えはすべてこの待機を基準（`rig.idleWorldQ`）に差分で作ってあるので、立っているあいだ常に後傾に見えていた（大剣の構えは −3.9°。構えに前傾 3° を書いてあっても基準が −6.9° のため）。走り（Meshy）は +24°、溜め・振りかぶりの後傾（−10〜−20°）は動きの意図。
（測り方の落とし穴: 最初に再生したクリップは `fadeIn` の途中で重みが 0.2 しかなく、バインドポーズ（直立）と混ざって「待機は +0.3°」と出ていた。最初の 1 本は捨てて測る。）

**決定**: **基準も攻撃のデータも動かさず**、立っている状態（待機・ガードの構え）にだけ、**実行時に体幹を前へ傾ける**（`src/character/posture.ts` の `PostureTrim`。数値は `src/character/data/posture.ts`）。
- 基準を動かすと、胸の座標で書いた剣の向き・床を叩く技の切っ先の高さ（±0.03m に詰めてある）がすべてずれて、全技の調整をやり直すことになる。攻撃・回避・走りは傾けない。
- 回す軸はキャラの右向き軸（Armature のローカル X）。腰から首までの骨を傾きの何割か（`POSTURE_SHARE`: 腰 0.5・胸の下 0.9・胸の中 1.2・胸の上 1.4・首 1.0・頭 0.5）ずつ回し、**足の付け根は世界の向きのまま**（腰の傾きを打ち消す）なので接地は変わらない。胸から上（腕・剣）は剛体で一緒に傾くので、握りと両手持ちの相対位置は変わらない。頭は傾き切らせず視線が下を向きすぎない。
- 傾きは状態ごと（待機 12°・ガード 8°・ほかは 0）に、`HeroVisual` が速さ 60°/秒（出す）/110°/秒（引く）でなめらかに出し入れする。攻撃に入るときは速く引く。
- **three のミキサーは骨の値が前回から変わらないと書き直さない**ので、補正の上に補正が毎フレーム重なる。毎フレーム「更新の前に補正を戻す（`release`）→ 更新 → 補正をかけ直す（`apply`）」にした。
- 効果（腰 → 首の傾き）: 片手剣の待機 **−6.9° → +4.7°**、大剣の構え **−3.9° → +8.2°**。頭は足の中心の 5〜6cm 前。腰ストレス・握りの検査は変化なし（検査はクリップを直接測るので、補正は含まない）。テスト: `src/character/posture.test.ts`（骨ごとの回転量・足の付け根が動かない・戻る・重ならない）。

**検討して退けたもの**: 基準（待機クリップ）を前傾に直す（全技の再調整）、全クリップの腰・胸の値に一律で前傾を足す（床を叩く技が床に刺さる）、`build-character` で待機クリップだけ直す（元の FBX から作り直せない）。

### 2. 操作ガイド（どの連携か・次に何が出るかを画面に出す）

**考え方**: 攻撃ボタンの「スティックの向きの読み方」を、**いつも同じ 5 つの枠**（連打 / 前 / 横 / 後ろ / 長押し）で下の中央に見せる。枠の意味は状況で変わる（枠の位置が変わらないので、指の動きと画面を結びつけやすい）。
- **立っているとき**（薄く）: 枠 = 始動の技。いまのスティックの向きで出る枠が金の縁になる（スティックを倒しながら見ると、ボタンを押す前に何が出るか分かる）。回避の直後・回避中は「ロール直後 → ダッシュ斬り」と一言出す。長押しの枠は最大まで溜めたときに変わる技を添える（大剣: 最大 地割り）。
- **攻撃中**: 上に**連携の履歴**（袈裟斬り › 逆袈裟 › 回転斬り。いまの技だけ金色で大きい）。枠 = 次に続けられる技（`next` / `branches`）。その下の**受付の帯**: 待ち（白い帯が伸びる）→ 受付中（金の帯が縮む。0 で連携が切れる）。受付が開くと枠がくっきりし、いまのスティックで出る枠が金の縁、先行入力を押してあれば ✓。続きの無い技は「この技で連携は終わり」。
- **溜め中**: 段階（● ●）・次の段階までの帯・「離す → 唐竹割り」・「最大まで溜めると 地割り」。
- 横・後ろの枠は**ロック中の向き**（ロックなしでは倒した向きは全部「前」）なので、ロックしていないときは点線・暗くして 🔒 を添える（「なぜ後ろに倒しても出ないのか」の答え）。
- **技表**（右上の「技表」ボタン / キーボード M）: 装備の技を始動の技 → 続きの木で一覧。開いているあいだは戦闘を止める（`Game.paused` = ステッパーの `timeScale` 0）。ガードの表示の入り切りもここ（保存は localStorage）。

**実装**: 表示内容は**純粋関数** `src/combat/move-guide.ts`（`buildGuide`）と `move-tree.ts`（`buildMoveTree`）が、`ATTACKS` / `CHARGES` のデータから作る（技を足せばガードにも技表にも出る。表示名は `src/combat/data/move-names.ts`、付け忘れはテストで落ちる）。DOM は `src/ui/move-guide.ts`・`move-list.ts`（変わったところだけ書く）。`Player` は `stickDir`（直近のスティックの向き）・`chain`（連携の履歴）・`locked`・`afterDodge`・`attackQueued` を公開し、`Game` が毎描画フレーム文脈を作って渡す。

**検討して退けたもの**: 十字キーの図（横が左右 2 つになり場所を取る）、連携のコマ数を ●○○ で出す（履歴の技名のほうが「いま何の連携か」が分かる。続きは枠に出る）、ガードを常に全開にする（立っているときは薄く、戦闘の邪魔をしない）。

### 3. 連携の続きの技（片手剣 4・大剣 4）

始動の技・分岐の技の**受付に続く技**。入力は ADR-023 と同じ（連打 = `next`、前 = `branches.forward`）。前の技の**保持の姿勢**（受付の時刻 = `cancelAt` = 次の技の `continueFrom.t`）から続く手付けで、足の位置もつなぎ目で合う（テスト）。**受付のあいだ姿勢を保つ**ように、元の技の保持を少し延ばした（横薙ぎ 0.66 → 0.72s、踏み込み突き 0.64 → 0.7s、大剣の踏み込み突き 0.9 → 0.98s。大剣の溜め斬りは戻りを縮めて 0.98s のまま）。

| 元の技 | 入力 | 続く技 | 内容 |
|---|---|---|---|
| 横薙ぎ `sweep` | 連打 | **返し薙ぎ** `sweepBack` | 左へ薙ぎ抜けた剣を右へ薙ぎ返す（2 連） |
| 踏み込み突き `lunge` | 連打 | **抜き払い** `lungeSlash` | 突きから左足を踏み抜けて右 → 左へ払う |
| 跳び退き斬り上げ `comboHop` | 前 | **飛び込み突き** `hopThrust` | 取り直した間合いを 1.5m 飛び込んで突き返す |
| 打ち上げ `comboUpper` | 連打 | **落下斬り** `comboSlam` | もう一度跳んで叩きつける（床を叩く。小さな輪） |
| 踏み込み突き `gsLunge`（大剣） | 連打 | **突き払い** `gsLungeSweep` | 突きから踏み抜けて右 → 左へ薙ぎ払う |
| 下がりながらの薙ぎ払い `gsRetreat` | 前 | **飛び込み突き** `gsRetreatLunge` | 牛の構えから 1.65m 飛び込んで貫く |
| 斬り上げ `gsRise` | 連打 | **飛翔叩きつけ** `gsRiseSlam` | 前へ跳んで真上から叩きつける（衝撃の輪） |
| 溜め斬り `gsHeavy` | 連打 | **地擦り斬り上げ** `gsHeavyRip` | 床に叩きつけた剣を地面をかすめて斬り上げる |

設計の約束の更新（ADR-023 から）: **分岐先からも続けてよい**（循環はテストで落とす。分岐先が「本線」＝始動の技から `next` をたどる列に入ることはない）。
作る道具: 足の始まりは「arc だけのキー」（`footR: { arc: 0 }` = 前の値を保つ）で前の技から受け取った位置のまま踏み出すまで動かさない（値を書き写すと小さくずれる）。足の幅は前足が腰の 0.5m 以内に着地・後ろ足が腰の 0.6m 以内になるよう寄せる（広げすぎると脚が届かず腰が沈む。最初の突き払い・飛び込み突きは 0.47〜0.54m 沈んでいた）。
検査: 8 つとも腕・脚のクランプ 0、握りのずれ 0.0cm、床の最低（落下斬り 0.05m・飛翔叩きつけ 0.05m。最初の落下斬りは切っ先が −0.04m でめり込み、着地の腰と握りを直した）、全クリップの腰ストレスは変わらず（p99 2.10）。

**代償・既知の問題**
- **実機で未確認**。確かめること: 立ち姿が後傾に見えなくなったか（前傾 12° が強すぎないか、構え・待機・ガードで）、操作ガイドの見やすさ（枠の大きさ・位置が指に隠れないか、金の縁で「いまのスティックで何が出るか」が分かるか、受付の帯で連携のタイミングが掴めるか）、技表（開閉・読みやすさ・戦闘が止まるか）、新しい続きの技の出しやすさと見た目（特に大剣の突き払い・飛び込み突き、床を叩く 2 つ、片手剣の抜き払い）。
- 受付の途中で押すと、保持の姿勢のあいだは継ぎ目が合うが、保持が終わった（戻りに入った）あとに押すと姿勢が少し跳ぶ（クロスフェード 0.05s）。受付の帯が縮み切る手前が目安。
- 待機・ガードの前傾は実行時の補正なので、`motion-sheet --clip` や `grip-check` などクリップを直接測る道具には含まれない（状態機械を通る `motion-sheet` の通常モードには含まれる）。

## ADR-025 敵の拡張（M5）: 突進型・予告の床表示・敵の種類ごとの見た目

**状態**: 採用（2026-10-04、M5-1）。ADR-014・015（敵の FSM）の拡張。

**背景**: M4 で戦闘の道具（3 装備・30 以上の技・ガード・パリィ・回避・溜め・操作ガイド）がそろったが、戦う相手は**子鬼 1 種（攻撃も 1 種）**だけだった。パリィの 2 種類・打ち上げからの追い打ち・地割り・全方位の回転斬りを使い分ける理由がなく、バランスの調整もできない。
本人（M4-6 の実機確認のあと「次の段階へ」）と相談して、**敵側を広げる**（M5）ことにした: 敵の種類 3〜4 種（突進型 → 遠距離型 → 重装型 → 小型の群れ）→ ボス 1 体 → ジャスト回避の反撃。見た目は**まずトゥーン調の仮モデル**（シルエットと色が種類ごとに違うプリミティブ製。戦闘の手触りを先に固めてから差し替える）。

### M5-1 暴れ猪（突進型）

**敵のデータ**（`ENEMIES.boar`、`src/ai/data/enemies.ts`）: 追跡 → 遠く（7m 以内）から予備動作 → **向きを固定して一直線に突進** → 長い硬直、という既存の FSM をそのまま使い、**データだけで**突進型にした（新しい状態は足していない）。
- 予備動作 0.93 秒（56f）: 前半 30f はプレイヤーを追って向きを変え、後半 26f は向きを固定する（既存の `windupTrackFrames`）。突進は判定のあいだ（startup 4f + active 26f）に `lunge` 6m を踏み込む（13.8 m/s）。当たりは正面の狭い扇（半角 40°、届く距離 1.6m）で、帯の幅 2.1m に収まる。ダメージ 20（子鬼 12）、ノックバック 3.2m。硬直 64f + 次の予備動作までの待ち 50f（突進を避けた直後が反撃のチャンス）。
- スーパーアーマー: 予備動作の 20f 以降〜突進の終わりは、34 以上の重い攻撃だけが割り込める（`armorBreakDamage`）。HP 110（子鬼 80）、ノックバックは 0.6 倍（重い）。
- 大剣のパリィで弾けば**倒れて**大きな反撃を受ける、盾のパリィなら体勢を崩す（既存の `PARRY_EFFECTS` のまま。テストで確認）。ロールは、突進が始まって猪が近づいたところで横へ転がれば無敵に収まる（早すぎると無敵が切れる）。

**予告（テレグラフ）の床表示**（`EnemyAttackDef.telegraph = { kind: 'lane', width }`）: 突進は速く（0.43 秒で 6m）、予備動作の赤い発光だけでは「どこを通るか」が読めないので、**通り道を床に出す**。
- 幾何は純粋関数（`src/ai/telegraph.ts` の `laneOf`。テスト付き）: 予備動作に入ると向いている方向へ帯が伸び、**追っているあいだ（前半）は薄く**、**向きが固定されたら濃く脈打つ**（ここから横へ動けば避けられる）、突進が始まったら**出発点に固定**して強く光ってから薄れ、突進の終わりで消える。長さ = 踏み込み + 当たりの届く距離（7.6m）。`Enemy.attackOriginX/Z`（突進に入った位置）を足した。
- 描画は `src/render/telegraph.ts`（`TelegraphLanes`。床に寝かせた板のプール 4 枚。進行方向へ流れる矢印のテクスチャ。色は追跡 = 橙、固定 = 赤、突進 = 明るい橙）。
- 帯の幅は当たりの扇の横幅（届く距離 × sin 半角 ≒ 1.03m の左右）に合わせた「横へ 1.5m 動けば避けられる」の目安。

**敵の種類ごとの見た目**（`src/game/enemy-visual.ts` の `EnemyVisual(kind)`）: 被弾・のけぞり・倒れ・弾かれの反応と発光は共通で、部品とポーズの付け方だけを種類で分けた（子鬼 = 縦長・紫・腕を振り上げて叩きつける、**暴れ猪 = 低く長い青緑の胴・背のオレンジの鬣・牙・脚 4 本**。予備動作は前脚で地面を掻いて頭を下げ、突進は 4 本の脚を回して前傾し、硬直で息を切らす。弾かれると前脚を蹴り上げ、倒れるときは**横倒し**）。子鬼と並べて、シルエットと色で見分けがつく。突進の音は `boarCharge`（低い唸りと長い風）。

**出現**: デモの戦闘を 3 ウェーブにした（子鬼 2 → 暴れ猪 + 子鬼 → 子鬼 + 暴れ猪 + 子鬼）。ランクの時間のしきい値を伸ばした（S 80 秒 / A 120 秒 / B 180 秒。被ダメージは据え置き）。（2・3 波の構成としきい値は ADR-026 で提灯を足して変えた: S 90 秒 / A 130 秒 / B 190 秒。ADR-027 で岩鬼の波を足して 4 ウェーブにした: S 130 秒 / A 180 秒 / B 250 秒。ADR-028 で小蝙蝠の波を足して 5 ウェーブにした: S 160 秒 / A 220 秒 / B 300 秒。ADR-029 でボスの波を足して 6 ウェーブにした: S 300 秒 / A 390 秒 / B 500 秒）

**検証**: `src/ai/telegraph.test.ts`（帯の長さ・幅、追跡中は薄く固定で濃く、固定後は向きが動かない、突進で出発点に固定され薄れて消える）、`src/game/boar-combat.test.ts`（本物の `Player` との結合: 突進の距離 = lunge・向きの固定、立っていると 1 回だけ当たる、帯の外へ横へ動けば当たらず猪は通り過ぎる、突進の近くのロールは当たらない、盾のパリィで体勢を崩す、スーパーアーマーと重撃の割り込み）。撮影: `npm run shot` に猪の帯（`shot-boar-lane.png`）と大剣のパリィで倒れた絵（`shot-boar-down.png`）を追加。

**まだ入れていないもの（次の段階）**: ガード不能の攻撃（重装型で。赤い予備動作の色分け。→ ADR-027 で入れた）、壁に当たって止まる・目を回す、遠距離型（飛び道具の仕組み。→ ADR-026 で入れた）、体勢ゲージ（→ ADR-027 で入れた）、ボス。

**代償・既知の問題**
- **実機で未確認**。確かめること: 暴れ猪の突進の読みやすさ（床の帯が見えるか・予備動作 0.93 秒で横へ動いて間に合うか・回避・パリィのタイミング）、痛さ（ダメージ 20 / ノックバック 3.2m）、見た目（仮モデルとして子鬼と見分けがつくか、突進・倒れの動き）、突進の音、3 ウェーブにした長さとランクのしきい値。
- 床の帯は、プレイヤーの側から見ると幅 2.1m の帯の外へ 1.5m 動けば当たらない設計だが、**カメラの向きによっては帯の横幅が読み取りにくい**可能性がある（斜め後ろ・遠いとき）。気になるなら幅の強調（縁を太く）や、突進の直前に帯を点滅させる。
- 見た目は仮モデル（プリミティブ）。差し替えるときは `EnemyVisual` の kind を GLB の読み込みに置き換える。

## ADR-026 飛び道具と遠距離型の敵「提灯」（M5-2）

**状態**: 採用（2026-10-04、M5-2）。ADR-025（敵の拡張 M5）の続き。M5-1 の暴れ猪（突進型）が実機で「特に問題ない」だったので、ロードマップの次（遠距離型）に進んだ。

**背景**: 子鬼・暴れ猪はどちらも近接（正面の扇）で、プレイヤーは「近づいてきた敵に対処する」だけだった。遠くから撃ってくる敵がいると、**距離を詰める判断**（撃たれながら走る・横へ避けながら近づく・ロールで抜ける）と、**飛び道具へのパリィ・ガード**（弾き返す）という、別の読み合いが生まれる。盾・大剣のパリィが近接にしか使えない状態も解消できる。

### 飛び道具の仕組み

**sim**（`src/combat/projectile.ts`。three に依存しない純粋なデータと関数）: 弾は XZ 平面を一定の速さでまっすぐ飛ぶ円（半径 `radius`）。高さは見た目だけ（`PROJECTILE_HEIGHT` 1.1m）。**1 ステップに動いた線分**（前の位置 → 今の位置）と相手の円で判定する（`segmentHitsCircle`。速くてもすり抜けない）。`ProjectileSystem` は固定長のプール（`MAX_PROJECTILES` 24。毎フレームの確保なし。満杯なら一番古い弾を消す）。寿命（`lifetimeFrames`）が尽きるか、アリーナの縁の外へ出たら消える。数値は `src/combat/data/projectiles.ts`（鬼火 `wisp`: 9 m/s・半径 0.32m・寿命 84f = 12.6m・ダメージ 10・ノックバック 1.1m・ヒットストップ 5f）。

**命中の解決**（`src/game/projectile-combat.ts`）: 弾の判定は近接の攻撃と**同じ防御の判定**（`guardOutcome`）を通る。弾が飛んでくる向きを「攻撃者 → 自分」の向きとして渡すので、**構えの正面から来た弾だけ**が防げる。
- 敵の弾 → プレイヤー: 無敵（回避の無敵フレーム・被弾後の無敵・死亡）のあいだは**すり抜ける**（弾は残る）。**パリィ** = 弾き返す（ダメージなし。弾は player の陣営になり、**撃った提灯の位置へ向けて**速く（×1.7）・強く（ダメージ 60 = 提灯 HP 50 を一撃）飛び直す。撃った敵がもういなければ来た向きへ返す）。**ガード** = 受け止める（削りだけ通り、弾は消える。盾 10 → 2）。それ以外は被弾して弾は消える。
- 弾き返した弾 → 敵: 飛んだ線分の始点に近い（先に当たる）敵 1 体に当たる（演出は反撃と同じ扱い: 水色の閃光・大きな数字）。倒れている・死んでいる敵（`invulnerable`）にはすり抜ける。
- プレイヤーの攻撃 → 敵の弾: 攻撃の判定が出ているあいだ、振りの範囲（`hitbox`）に入った弾は**斬り落とされて消える**（ダメージも弾き返しもなし）。弾き返した弾は斬らない。大剣の薙ぎ払いは広いので、まとめて落とせる。

**演出**（`Game`）: パリィで弾いたときは近接のパリィと同じ演出（ヒットストップ・揺れ・「PARRY」・構えごとの効果音）を**弾の位置**に出す（閃光は自分の目の前なので 0.6 倍に絞る）。弾が寿命・縁で消える、斬り落とされるときは小さな閃光とはじける音（`orbBreak`）。斬り落としは 2f の短いヒットストップ。

### 提灯（遠距離型）

**敵のデータ**（`ENEMIES.lantern`）: 既存の FSM に**データを足しただけ**。`EnemyAttackDef.projectile`（撃つ弾の id）と、`EnemyDef.retreatDistance / retreatSpeed`（距離を取る敵）。
- 追跡は 6.5m（`stopDistance`）まで近づいて止まり、**4.5m（`retreatDistance`）より近づかれると、向きを保ったまま 3.4 m/s で後ろへ下がる**。壁際では止まる（追い詰められる）。
- 予備動作 0.73 秒（44f）: 前半 30f はプレイヤーを追い、後半 14f は向きを固定する（既存の `windupTrackFrames`）。攻撃に入って 2f（`startupFrames`）で、固定した向きへ弾を 1 つ撃つ（`Enemy.fireSerial` が増え、`Enemy.shot` に銃口と向き。`Game` が読んで弾を作る）。近接の判定は出ない（`attackActive` は false）。撃ったあとの硬直 36f + 次の予備動作までの待ち 70f。距離 11m 以内から撃つ。
- 体は脆い: HP 50、スーパーアーマーなし（予備動作のあいだに弱い攻撃でひるむ = 撃たせずに潰せる）。近づけば 2〜3 振りで落ちるが、近づくあいだに撃たれ、下がられる。

**予告の床表示**: 暴れ猪と同じ帯（`laneOf`）。帯の長さは弾の飛ぶ距離（`laneLength` = 速さ × 寿命 = 12.6m）、幅は 0.8m（弾の半径 0.32 + プレイヤーの半径 0.38 = 当たりの半幅 0.70m より広く、**帯の外へ体が出れば確実に当たらない**。テストで確認）。予備動作の後半（向きの固定）で帯が濃くなる。

**見た目**（`EnemyVisual('lantern')`。トゥーン調のプリミティブ）: 宙に浮く赤い提灯 — 紙の胴（縦長の楕円。内側の火で薄く発光）、上下の黒い蓋、持ち手の金の輪、骨組みの横線、大きな一つ目（発光）と舌、下に揺れる房。予備動作で**前（銃口）に鬼火が膨らんで溜まり**、体は後ろへ反って紫に光る。撃つと反動で前のめりになる。倒されると真下へ落ちて、横に転がって横たわる。鬼火（`src/render/projectiles.ts`）は 白紫の核 + 輪郭線 + 後ろへ引く炎の尾（円錐のベタ塗り）+ 加算のにじみ（ブルームに乗る）+ **床に落ちる光**（奥行きの目印）。敵の弾は紫、弾き返した弾は水色（パリィの閃光と同じ色）。音は `orbShot`（息を吐く「ぽうっ」）と `orbBreak`（「ぱしゅっ」）。

**出現**: デモの戦闘を、1 波 子鬼 2 → 2 波 暴れ猪 + 提灯 → 3 波（最後）子鬼 2 + 猪 + 提灯、にした（敵の数 2 + 2 + 4）。ランクの時間のしきい値を伸ばした（S 90 秒 / A 130 秒 / B 190 秒。被ダメージは据え置き）。攻撃権（同時に予備動作〜攻撃に入れる数 2）は提灯も使う。

**検証**: `src/combat/projectile.test.ts`（直進・寿命・縁・プールの再利用・弾き返しの状態変化・線分と円の判定）、`src/game/lantern-combat.test.ts`（本物の `Player` との結合: 撃つ向きと銃口・立っていると 1 発 1 回だけ当たる・横へ動く／ロールで避けられる・追っている間は向き直る・盾 / 素手のガード・正面のコーン外・盾のパリィで弾き返して提灯を一撃・提灯が横へずれても狙う・受付に間に合わなければガード・大剣のパリィ・斬り落とし・ひるませれば撃たない・後退と停止距離）、`src/ai/telegraph.test.ts`（弾の帯の長さ・幅・固定）。撮影: `npm run shot` に提灯の予備動作（`shot-lantern-windup.png`）・飛んでいる鬼火（`shot-lantern-orb.png`）・盾のパリィで弾き返した絵（`shot-lantern-parry.png`）を追加。全ロードアウトでランダム入力を長く回しても例外なし（手元の確認）。

**まだ入れていないもの（次の段階）**: 重装型（ガード不能の攻撃・体勢ゲージ。→ ADR-027 で入れた）、小型の群れ、ボス、ジャスト回避の反撃。飛び道具の種類（追尾・扇状・連射）は、遠距離型を実機で触ってから。

**代償・既知の問題**
- **実機で未確認**。確かめること: 鬼火の読みやすさ（予備動作 0.73 秒で横へ動いて間に合うか、床の帯・溜めの鬼火が見えるか、弾の速さ 9 m/s が速すぎ・遅すぎないか）、盾（受付 10f）・大剣（6f）のパリィで**狙って弾き返せるか**と、弾き返した弾が提灯に当たる気持ちよさ、ガードの削り、斬り落とし（受付なしで気軽に消せる = 弾が弱すぎないか）、提灯の後退と追い詰め（壁際に追い込めるか・近づく苦労が楽しいか・撃つ頻度 約 2.5 秒に 1 発）、見た目（提灯の可愛さ・鬼火の色と大きさ・床の光）、音、新しい 2・3 ウェーブの長さとランクのしきい値。
- 弾は高さを持たない（XZ の円）ので、ジャンプ・しゃがみでは避けられない（ゲームにジャンプがない。将来つけるなら高さを足す）。
- 弾き返した弾は、撃った提灯が**弾いた瞬間の位置**へ向かって直進する（追尾ではない）。提灯が弾く直後に大きく動けば外れる（動きが遅いので通常は当たる）。

## ADR-027 重装型の敵「岩鬼」: ガード不能の攻撃・体勢ゲージ・円の予告（M5-3）

**状態**: 採用（2026-10-04、M5-3）。ADR-025（M5）・ADR-026（飛び道具）の続き。ロードマップの 3 番目（重装型）。

**背景**: 突進型（猪）・遠距離型（提灯）までは、どちらも**ガード・パリィで受けられる**攻撃だった。盾・大剣の「構えて待つ」が常に最適解になりやすい。ガードが通らない攻撃（避けるしかない）と、**ひるませて止める**以外の止め方（体勢を崩す）があると、回避・攻め・守りの選び分けが生まれる。

### 仕組み（`src/ai/enemy.ts` ほか。どれも FSM の状態は足していない）
- **ガード不能の攻撃**（`EnemyAttackDef.unblockable`）: `resolveEnemyAttacks` が防御の判定（`guardOutcome`）を飛ばして被弾にする。構えていても被弾（構えは解ける）、パリィの受付に重なっても弾けない。避ける方法は、回避の無敵フレーム・当たらない場所へ逃げる・攻撃を出させない（体勢崩し）。
- **常時スーパーアーマー**（`EnemyDef.hyperArmor`）: 追跡中も含めていつでも、`armorBreakDamage` 未満の攻撃ではひるまない（ダメージは通り、ノックバックは `armorKnockbackScale` 倍）。岩鬼は `armorBreakDamage` 9999 = 何でもひるまない。
- **体勢ゲージ**（`EnemyDef.poise`、純粋ロジックは `src/combat/poise.ts`）: 受けたダメージぶん減り（予備動作・攻撃の最中でも）、0 になった一撃で**体勢が崩れる**: 予備動作・攻撃を中断して stagger（その場で動けない）に入り、動けないあいだずっと**反撃の窓**（ダメージ 1.8 倍・ノックバック小。弾かれたときの反撃と同じ仕組み = `riposte`）。立て直したら満タンに戻って、すぐには攻撃しない（待ち 40f）。最後に受けてから 150f 経つと少しずつ戻る（0.35/f）。とどめの一撃では崩れない。数値は `src/combat/data/poise.ts`（`POISE_BREAK` は弾かれたときの効果 `ParryEffectDef` と同じ形）。
- **円の予告**（`telegraph: { kind: 'circle' }`、幾何は `circleOf`）: 全周の攻撃に、敵を中心にした円（半径 = 当たりの届く距離）を床に出す。**予備動作の進みに合わせて内側から満ちていき**、満ちた瞬間に攻撃が出る（円の外へ出れば避けられる）。攻撃が出たら全面が光ってすぐ消える。ガード不能は赤紫（`COLOR_UNBLOCKABLE`）で、防げる攻撃の赤・橙と見分ける。描画は `src/render/telegraph.ts` の `TelegraphCircles`。
- **地面を叩く合図**（`EnemyAttackDef.groundImpact` = 演出の強さ、`Enemy.impactSerial`）: 判定が出る瞬間に増え、`Game` が床の砂ぼこりの輪・ひび割れ・画面の揺れ・音を出す（プレイヤーの地割りと同じ `GroundFx`）。

### 岩鬼（`ENEMIES.ogre`）
- HP 320、体勢 80、半径 0.95m、高さ 2.6m。移動 1.7 m/s（遅い）、2.6m で止まる。攻撃は「地ならし」1 種: 3.4m 以内で予備動作 1.07 秒（前半 34f はプレイヤーを追い、後半は固定）→ 判定 5f の**全周（半角 180°）・ガード不能**（届く距離 3.0m、ダメージ 32、ノックバック 3.4m）→ 硬直 1.17 秒 + 待ち 1 秒。
- **攻略の幅**: ①円の外へ出る・ロール（予備動作は 1 秒あるので余裕がある）、②地ならしのあとの硬直（70f）に連続で当てて体勢を崩す（片手剣の 3 連 49 ダメージ ≒ 体勢の 6 割、大剣は 2 振りでほぼ崩れる）、③予備動作のうちに崩して攻撃を中断させる（大技の割り込み）。崩れたら 1.7 秒の反撃の窓（1.8 倍）。1 サイクルでおよそ 250 ダメージ（体勢を崩すまで 80 + 窓 150〜）で、HP 320 は 2 サイクル弱。
- **見た目**（`EnemyVisual('ogre')`）: 石の鎧をまとった大鬼 — 黄土色の肌・灰青の肩当てと胸当て・兜に 2 本の角・牙・右手に大きな金棒（トゲ付き）。体には**割れ目**が走り、体勢が減るほど溶岩のように光る（満タンは暗い橙、崩れると白熱して脈打つ）。予備動作は金棒を頭上へ振りかぶり（体が赤紫に控えめに光る）、攻撃で真下へ叩きつける。体勢が崩れると膝をついて前へうなだれる。倒れると仰向けに寝る。体が大きいので、被弾の揺れ・のけぞり・つぶれは小さくしてある（ひるまない重さ）。
- **UI**: 敵の頭上の HP バーとロック対象の HP バー（画面上部）に、**黄色い細い体勢バー**を出す（崩れているあいだは水色で満タン表示 + 点滅 = 反撃のチャンス）。予備動作の始まりに頭上へ「ガード不能」（赤紫）と鋭い合図音（`unblockWarn`）、体勢が崩れたら「BREAK」（黄）と鎧が割れる音（`poiseBreak`）・黄金色の閃光・強いヒットストップ。

**出現**: デモの戦闘を 4 ウェーブにした（子鬼 2 → 猪 + 提灯 → **岩鬼 + 子鬼 2** → 子鬼 2 + 猪 + 提灯）。岩鬼の波は子鬼を添えて、ガード不能の円を見ながら雑魚を捌く構図にした。ランクの時間のしきい値を伸ばした（S 130 秒 / A 180 秒 / B 250 秒。被ダメージは据え置き）。

**検証**: `src/combat/poise.test.ts`（減る・崩れは 1 度だけ・待ってから回復・受けるたびに待ちが数え直し）、`src/game/ogre-combat.test.ts`（本物の `Player` との結合: 追跡・予備動作・攻撃のどこでもひるまない、体勢が 0 で予備動作を中断して stagger・攻撃は出ない、崩れているあいだの反撃の倍率、立て直しで満タン、150f 後から回復、とどめは崩れない、立っていると 1 回だけ当たる・盾 / 大剣のガード・パリィが効かない、背中側でも全周で当たり届く距離の外は当たらない、円の外へ出る・ロールで避けられる）、`src/ai/telegraph.test.ts`（円の半径・満ちる・固定後の濃さ・攻撃で光って消える・他の敵には出ない）。撮影: `npm run shot` に岩鬼の円が満ちていく絵（`shot-ogre-circle.png`）・地ならしが出た瞬間（`shot-ogre-slam.png`）・体勢を崩して膝をついた絵（`shot-ogre-break.png`）を追加。ウェーブ 3・4 の構成でランダム入力を長く回しても例外なし（手元の確認）。

**まだ入れていないもの（次の段階）**: 小型の群れ（→ ADR-028 で入れた）、ボス、ジャスト回避の反撃。重装型の第 2 の攻撃（防げる横薙ぎ・突進との組み合わせ）、岩鬼の体勢をパリィで大きく削る（パリィ = 体勢ダメージ）は、実機で触ってから。

**代償・既知の問題**
- **実機で未確認**。確かめること: 円の予告の読みやすさ（予備動作 1.07 秒で円の外へ出られるか・ロールの間合い・満ちていくのが見えるか）、ガード不能の警告（頭上の文字・音・赤紫の色分け）、**体勢ゲージ**（黄色いバー・崩れるまでの手数が多すぎ・少なすぎないか、崩れたとき水色の点滅と「BREAK」が気持ちいいか）、反撃の窓 1.7 秒と 1.8 倍の効き具合（片手剣・大剣それぞれ）、岩鬼の硬さ（HP 320・2 サイクルで倒せるか）と痛さ（ダメージ 32・ノックバック 3.4m）、見た目（鎧・割れ目・金棒・膝をつく動き）、地ならしの床の演出と画面の揺れ、4 ウェーブの長さとランクのしきい値。
- 地ならしは全周なので、**子鬼などに囲まれて動けない・ロールの先に別の敵がいる**と詰みやすい（円が出てから 1 秒あるので通常は逃げられる）。攻撃権（同時に 2 体）が岩鬼にも効いている。
- 岩鬼の予備動作の発光は控えめ（全身が塗りつぶされて鎧が読めなくなるため）。足りなければ、円・警告文字の側を強める。
- 体勢ダメージは「受けたダメージ」そのもので、技ごとの個別の値はない（溜め斬りや地割りは大きく削れる）。

## ADR-028 小型の群れ「小蝙蝠」: 攻撃権の重み・周回・飛行（M5-4）

**状態**: 採用（2026-10-04、M5-4）。ADR-025〜027（M5）の続き。ロードマップの 4 番目（小型の群れ）。

**背景**: ここまでの敵は 1〜4 体が「1 対 1 を順に」さばく形で、攻撃権も「同時に 2 体まで」の整数だった。大剣の薙ぎ払い・回転斬りは範囲が広いのに、その使いどころ（数に囲まれたとき）が無く、逆に数で囲まれる怖さ（どこから来るか・どれから落とすか）もなかった。弱くて数の多い敵を足して、**範囲攻撃の価値と、囲まれたときの立ち回り**を作る。

### 仕組み（FSM の状態は足していない）
- **攻撃権の重み**（`EnemyDef.attackWeight`、既定 1）: `EncounterDef.maxAttackers` を「同時に予備動作〜攻撃に入れる数の予算」とし、`stepSwarm` は、いま攻撃中の敵の重みの合計 + 自分の重み ≤ 予算 のときだけ攻撃に入れる（浮動小数点の誤差を見込んで 1e-9 の余裕）。重み 1 の敵だけなら従来どおり（予算 2 = 2 体）。小蝙蝠は重み 0.6 で、予算 2 の中で**同時に 3 体まで**（子鬼 1 + 小蝙蝠は 1 体まで）。残りは近くで構えて待つ。
- **周回**（`EnemyDef.orbitSpeed`）: プレイヤーの近く（`stopDistance` + 1.8m 以内）では、輪（`stopDistance`）を保ちながらプレイヤーの周りを回る（向いている方向に対して横へ。輪より近い・遠いは半径方向の補正）。攻撃権を待つあいだ、敵が 1 か所に固まらず**散らばって囲む**。回る向きは id の偶奇で決まり、攻撃を終えるたびに逆になる（組によって逆回り）。
- **飛行**（`EnemyDef.flying`）: プレイヤーを押し出さず（`pushOutOfCircle` を飛ばす）、地上の敵とも体を押し合わない（飛んでいる敵どうしだけ `separateCircles`）。群れに囲まれても移動が引っかからない。

### 小蝙蝠（`ENEMIES.bat`）
- HP 12（片手剣 2 発・大剣 1 発）、半径 0.3m、移動 4.2 m/s、ノックバックは 1.8 倍（軽く飛ぶ）。**スーパーアーマーなし**（当たればひるむ）。
- 輪 3m で周回 → 攻撃権が回ってきたら、予備動作 0.43 秒（26f。前半 10f はプレイヤーを追い、後半 16f は向きを固定）→ 急降下で 2.8m（`lunge`。判定 10f）を噛みつく（扇 半角 50°・届く距離 0.8m、ダメージ 6）→ 硬直 28f + 待ち 60f。盾・ガード・ロールで防げる（ガード可）。1 発は軽いが、複数に囲まれるとまとめて来る。
- **見た目**（`EnemyVisual('bat')`）: 藍色の丸い胴・とがった耳・牙・発光する黄色い目・薄く平たい翼 2 枚（`armL` / `armR` を翼に流用。左は鏡写し）。宙に浮いてゆらぎ、通常は大きく羽ばたく（14 rad/s）。予備動作は翼を高く広げて小刻みに震え、鼻先を上げて仰け反る。急降下は鼻先を下げて翼をたたみ、硬直で体を起こして羽ばたきに戻る。倒れると真下へ落ちる。体の中心を軸に傾く（提灯と同じ作り）。
- 音: `batSqueak`（予備動作。高く短い鳴き声。群れで何度も鳴るので小さく）、`batSwoop`（急降下。小さく鋭い風切り）。

**出現**: デモの戦闘を **5 ウェーブ**にした（子鬼 2 → **小蝙蝠 6** → 猪 + 提灯 → 岩鬼 + 子鬼 2 → 子鬼 + 猪 + 提灯 + **小蝙蝠 4**）。2 波は大剣の一振りで一掃できる気持ちよさを見せる波、最後の波は群れを加えた総力戦。ランクのしきい値を伸ばした（S 160 秒 / A 220 秒 / B 300 秒、被ダメージ S 30 / A 70 / B 100）。

**検証**: `src/ai/swarm.test.ts`（重み 0.6 の蝙蝠は予算 2 で同時に 3 体まで・子鬼と混ざっても重みの合計が予算以下・予算ぴったりまで使える・攻撃権が無くても輪を保って周回し組によって逆回り）、`src/game/bat-combat.test.ts`（本物の `Player` との結合: 弱い・立っていると噛みつきが 1 回だけ当たる・向きの固定後に横へ動けば避けられる・盾のガードとロールで防げる・大剣の一振りで前方の 3 体を落とせる・6 体に囲まれても同時に噛みつくのは 3 体まで）。撮影: `npm run shot` に周回して囲む絵（`shot-bat-swarm.png`）・数体が急降下する絵（`shot-bat-dive.png`）・大剣の一振りで 6 体を落とした絵（`shot-bat-sweep.png`）を追加。小蝙蝠と岩鬼・提灯を含む波でランダム入力を長く回しても例外なし（手元の確認）。

**まだ入れていないもの（次の段階）**: ボス（→ ADR-029 で入れた）、ジャスト回避の反撃。群れの別の種類（地を這う・投げる）、群れのリーダー（倒すと散る）、周回の向きや輪の半径のばらつきは、実機で触ってから。

**代償・既知の問題**
- **実機で未確認**。確かめること: 小蝙蝠の読みやすさ（予備動作 0.43 秒で、固定後の 16f に横へ動いて避けられるか・ガード・ロールの使いどころ）、**囲まれたときの手触り**（同時に 3 体は多すぎ・少なすぎないか、どれから落とすか迷うか、ロックの切り替えで狙えるか）、大剣・片手剣の薙ぎ払い・回転斬りで落とす気持ちよさ、小蝙蝠の見た目（羽ばたき・急降下）と音、**描画の重さ**（群れ 6〜7 体で描画呼び出しが約 190〜210 回。iPad で 60fps が保てるか。重ければ翼の輪郭線を省く・翼を 1 メッシュにまとめる）、5 ウェーブの長さとランクのしきい値。
- 小蝙蝠の頭上の HP バーは、傷を負った敵のうち配列の先頭 8 体にしか出ない（バーのプールが 8）。群れ + 他の敵で 8 体を超えると、後ろの敵のバーが出ない。足りなければプールを増やす。
- ロックオンは群れの全員が候補になるので、切り替え（左右）で順に狙う。近い順の自動選択のみで、「群れの中で一番手前」を狙う補助はない。
- 攻撃権の予算は重みの合計なので、**子鬼が先に攻撃中だと小蝙蝠が 1 体しか入れない**（1 + 0.6 = 1.6、あと 0.6 で 2.2 > 2）。意図どおり（密度を保つ）だが、波の組み合わせによって攻撃の頻度が変わる。

## ADR-029 ボス「夜行の大将」: 複数の技・段階・召喚・扇と輪の弾（M5-5）

**状態**: 採用（2026-10-04、M5-5）。ADR-025〜028（M5）の続き。ロードマップの 5 番目（ボス）。方向性は本人と相談して決めた（「岩鬼の体勢ゲージとガード不能・提灯の鬼火・小蝙蝠の召喚を組み合わせ、HP が減るごとに技が増える段階制」→「その方向でいきましょう」）。

**背景**: ここまでで敵の種類（突進・遠距離・重装・群れ）がそろい、デモの 5 ウェーブでそれぞれを体験できる。最後に、**それらを 1 体に集めて総仕上げ**にする相手が要る。雑魚と違って「技が複数あり、状況で選ぶ・追い詰めると増える」ことが、ボスらしさの核になる。

### 仕組み（FSM の状態は足していない）
- **複数の技**（`EnemyDef.moves`）: 攻撃に入るたびに、**距離**（`rangeMin` 〜 `range`）・**段階**（`minPhase`）で選べる技を絞り、**重み**（`weight`）つきの乱数で選ぶ（直前と同じ技は、ほかに選べる技があれば避ける。選べる技が 1 つなら繰り返す）。選べる技が無い距離では攻撃に入らず、近づく。乱数は敵の id が種の xorshift で、同じ状況なら同じ選び方（テストできる）。`Enemy.attackDef` は「いまの技」を返し、テレグラフ・ヒット判定・見た目・音は、これまで `def.attack` を読んでいた所が `attackDef` を読む。複数の技を持たない敵は従来どおり `def.attack` 1 つ。
- **段階**（`EnemyDef.phases = [{ hpBelow, cooldownScale }]`）: HP の割合が `hpBelow` 以下になるたびに段階が 1 つ上がる（`Enemy.phase` / `phaseSerial`。とどめでは増えない）。段階が上がると、`minPhase` の技が解放され、技のあとの待ちが `cooldownScale` 倍に縮む。
- **弾の扇・輪**（`projectileCount` / `projectileSpread` / `muzzleOffset`）: 弾を複数撃つ。`fanOffset(i, count, spread)` が i 本目の向きのずれ（spread ≥ 2π は全周に等間隔）。`spawnShot`（`src/combat/projectile.ts`）が、敵の中心から銃口までの距離を保ったまま放射状に作る（体の大きな敵が体の外から撃つ。`muzzleOffset` で銃口をさらに前へ）。床の予告も同じ本数の帯を出す（`laneCount` / `laneOf(e, out, index)`。プールは 16 本）。弾き返せば（パリィ）、**ボスの HP と体勢の両方が 60 削れる**（通常の被弾と同じ `takeHit`）。
- **召喚**（`summon: { type, count, radius, max }`）: 判定が出る瞬間に `Enemy.summonSerial` が増え、`Game` が周り（`summonPoints`: 中心から radius の円周に等間隔・アリーナの縁の内側へ寄せる）に手下を出す。生きている同種が `max` 以上なら呼ばない（手下が増えすぎない）。ボスを倒すと手下は `Enemy.vanish()` で消える（倒した数には入らない）。
- **構え**（`pose`: slam / cast / roar）: 技ごとの予備動作の見た目の区別（叩きつけ = 武器を頭上へ → 真下、cast = 片腕を前へ突き出して放つ、roar = 両腕を広げて吠える）。見た目だけで、当たり判定・タイミングには関わらない。

### ボス（`ENEMIES.boss`「夜行の大将」）
- HP 900・体勢 140（崩すと **2 秒**の反撃の窓・1.6 倍。`BOSS_POISE_BREAK`）・半径 1.25m・高さ 3.9m。常時スーパーアーマー（何でもひるまない）。遅い（1.9 m/s）。
- 技（距離は敵の中心からプレイヤーの中心まで）:
  - **地ならし**（`pound`。4.4m 以内・段階 0〜）: 岩鬼と同じ全周・ガード不能の円（半径 3.6m）。予備動作 1.1 秒・ダメージ 36。
  - **鬼火の連弾**（`volley`。4.5〜14m・段階 0〜）: 扇に 5 発（広がり 1.3rad。床に 5 本の帯）。
  - **号令**（`summon`。どの距離でも・段階 1〜）: 吠えて、小蝙蝠を 3 体呼ぶ（生きている蝙蝠が 6 体いれば呼ばない）。
  - **鬼火の輪**（`ring`。段階 2〜）: 全周に 8 発（45° 間隔。輪の隙間・ロール・ガード・パリィ）。
- HP 66% と 33% で段階が上がり、技の待ちが 0.85 倍 → 0.65 倍に縮む。段階が上がった瞬間に咆哮（強いヒットストップ・画面の揺れ・閃光・文字「怒り」「激昂」・`bossRoar`）。
- **見た目**（`EnemyVisual('boss')`）: 岩鬼の部品を色違い（黒鉄の鎧・暗い赤紫の肌・マゼンタの割れ目）にして 1.3 倍に拡大し、肩当てと兜のトゲ・**背に竿で担いだ大提灯**（段階が進むほど明るく、技の予備動作で膨らんで光る）を足した。鬼火を溜める玉は提灯と同じ。
- **UI**: 画面上部（プレイヤーの HP の下）に**ボス専用の HP バー**（名前・段階の境目の目盛り・下に体勢バー。崩れたら水色で点滅）。ボスの頭上のバーは出さず、ボスがいるあいだロック対象の HP は下へずらし、ロック対象がボスなら上部のバーに任せる。カメラは、ボスがいるあいだ少し引いて少し上を見る（`CAMERA.bossPullBack / bossLookUp`。背の高いボスの頭まで映す）。ウェーブの始まりは「BOSS」のバナー。

**出現**: デモの戦闘を **6 ウェーブ**にした（… → 5 波 子鬼 + 猪 + 提灯 + 小蝙蝠 4 → **6 波（最後）ボス 1 体**）。ランクのしきい値を伸ばした（S 300 秒 / A 390 秒 / B 500 秒、被ダメージ S 40 / A 90 / B 140）。

**検証**: `src/ai/moves.test.ts`（合成データで: 距離で選べる技が変わる・届かない距離では攻撃に入らない・段階が足りない技は選ばれない・直前の技を避ける・id で選び方が決まる・重みの効き・段階で上がる・待ちが縮む・召喚の合図・扇の本数と銃口・fanOffset・扇の帯・召喚位置）、`src/game/boss-combat.test.ts`（本物の `Player` との結合: HP 900・体勢 140・段階の境目 594 / 297、段階 0 の技は近距離が地ならし・遠距離が連弾だけ、段階 1 から号令・段階 2 から輪、地ならしは盾でもガード不能・円の外へ出れば避けられる、連弾は扇に 5 本・立っていると当たる・ロールで避けられる・盾のパリィで弾き返すとボスの HP と体勢が 60 減る、輪は 8 本が 45° 間隔、体勢 140 を削ると 2 秒の体勢崩しで予備動作が中断される）。撮影: `npm run shot` にボスの登場（HP バー）・連弾の扇の帯・地ならしの円・段階 1 の号令（蝙蝠が出る）・段階 2 の輪を追加して目視確認。段階 2 のボスと手下のいる状況でランダム入力を長く回しても例外なし、ボスを倒すと手下が消えてリザルト（勝ち）に進むことを確認（手元）。

**まだ入れていないもの（次の段階）**: ジャスト回避の反撃。ボスの技のさらなる追加（二連の地ならし・突進）、段階が上がるときに体勢を回復する・一定時間無敵になる演出、ボス専用の BGM は、実機で触ってから。

**代償・既知の問題**
- **実機で未確認**。確かめること: ボスの**強さの調整**（HP 900 を倒すのにかかる時間。体勢 140 を崩す手数と、崩したときの 2 秒・1.6 倍の見返り。見積もり: 片手剣の 3 連 49 ダメージで体勢の 35%・崩して 2 秒に 2 連 ≒ 160 ダメージ、大剣は 2 振りで崩せ 1 振り 30〜60）、**連弾・輪の避けやすさ**（床の帯が見えるか・輪の隙間に入れるか・ガードで受けきれるか・パリィで弾き返せるか）、**号令で呼ぶ蝙蝠の数**（3 体 + 既存で多すぎないか）、**地ならし**の読みやすさ（ボスが大きく円が画面いっぱいになる）、段階が上がったときの演出と難しさの上がり方、**見た目**（背の大提灯・色・構え 3 種・倒れ方）、ボスの HP バー・体勢バーの見やすさ、カメラの引き（頭まで映るか・遠すぎないか）、音（`bossRoar`）、**6 ウェーブ**の長さとランクのしきい値、描画の重さ（ボスの波は敵が少ないので軽い。蝙蝠が 6 体呼ばれたとき約 170 回）。
- 技の選択は距離で絞るので、**ボスの足元に張りついている間は地ならし（と号令・輪）しか来ない**。近接で戦う限り、連弾は来ない（遠距離のとき中心）。
- ボスは攻撃権を 1 つ使う（`attackWeight` 既定 1）ので、呼ばれた小蝙蝠（0.6）と合わせると予算 2 に収まる範囲でしか同時に動かない。ボスが号令を唱えているあいだは、蝙蝠の攻撃が 1 体に減る。
- 手下の召喚は `max` 以上いると呼ばないだけで、呼ぶ技の予備動作・咆哮は出る（空振り）。
- 頭上の HP バーのプール（8 体）は、ボスの波では足りる（ボス + 蝙蝠 6）。


## ADR-030 ミスティカルドッジ（ジャスト回避）とアイテム欄（薬瓶）（M5-6）

**状態**: 採用（2026-10-04、M5-6）。ADR-025〜029（M5）の続き。ロードマップの「ジャスト回避の反撃」は、本人の指定で**ミスティカルドッジ**（成功すると数秒だけ無敵 + 敵がゆっくりになる、いわゆるウィッチタイム）として入れた。同じ依頼で「回復なしでは少し難しい」ので、**敵を倒すと適度な確率で薬瓶（小）が落ち、ストックして使える**ようにした（アイテム欄は長押し + スワイプで複数のアイテムから選べる。のちにスキル欄として同じものをもう 1 つ置くので、再利用できる部品にする）。難易度そのものは本人が「これで良い」と決めている（ボスまでの歯応えは変えない）。

### ミスティカルドッジ
- **発動条件**: 回避（前転・後ろステップ）の**無敵フレーム**のあいだに、「その無敵がなければ当たっていた」攻撃（敵の近接の判定・敵の弾が相手の円に重なる）があったとき。被弾後の無敵・ミスティカル中は数えない（`Player.dodging` = 回避の無敵の中で、ほかに無敵の理由がない）。判定は `resolveEnemyAttacks`（`hitboxHits`）と `resolveProjectilesOnPlayer`（`segmentHitsCircle`）の無敵の分岐で、`onJustDodge` を呼ぶ。弾は消えずにすり抜けて飛び続ける。
- **効果**（`MYSTICAL`。`src/combat/data/mystical.ts`）: **3 秒**（180f）のあいだプレイヤーは無敵（`Player.setMystical`。ほかの無敵と同じ `body.invulnerable`）、**敵と敵の弾だけ 1/5 の速さ**（`enemyScale 0.2`）。プレイヤー・カメラ・演出・UI は等倍。**成功から 8 秒**（`cooldownFrames 480`。続く 3 秒より長い = 切れてから 5 秒は起こらない。稼働率は最大 3/8）は次が起こらない。ランダムに回避を連打する自動の試験では、100 秒で 5〜7 回発動した（5 秒だと稼働率が最大 60% になり、「難易度はこのまま」から外れるので 8 秒にした。実機で見て詰める）。
- **時間の遅らせ方**: 敵の中のフレームの数え方（予備動作・持続・クールダウン）をいじらず、**敵・弾の sim ステップを間引く**（`Mystical.step()` が true のステップだけ `stepSwarm` と `ProjectileSystem.step` を呼ぶ。0.2 を足して 1 に届いたら進める）。「dt を 0.2 倍する」案は、敵のロジックが整数フレームで動くので採らなかった。間引くと敵の見た目が 5 ステップに 1 回だけ跳ぶので、**描画は敵・弾だけ別の補間係数**（`Mystical.visualAlpha(alpha)` = 端数 + alpha × scale）と、アニメの時間 × scale で進める（`Game.render`）。純粋なクラスは `src/combat/mystical.ts`（three・DOM に依存しない）。
- **避けた攻撃は「空振り」にする**: ミスティカルが切れたあと、遅い時間のなかで止まっていた持続中の攻撃が無敵の切れ目に刺さらないよう、無敵のあいだに重なった攻撃は `hitTracker` に記録する（ハンドラが true = 発動した・発動中のときだけ。クールダウン中の普通のロールの無敵は従来どおり記録しない = 無敵が切れて持続が残っていれば当たる）。ミスティカル中にぶつかった攻撃も同じ（`DefenderView.evading`）。
- **演出**: 発動の瞬間にヒットストップ 7f・画面の揺れ・青紫の閃光（`FX_TINT.mystic`）・「MYSTICAL」の文字・音（`mysticalStart`）、切れるときに `mysticalEnd`。発動中は**画面の縁が青紫に染まり**、HP バーの下に**残り時間のゲージ**（切れる手前の 36f は点滅）、切れたあとは次までの**再使用の溜まりのゲージ**（灰色）が出る（`Hud.setMystical`）。

### アイテム欄（薬瓶）
- **データ**（`ITEMS`。`src/combat/data/items.ts`）: **薬瓶（小）**= 回復 30・持てる数 5、**薬瓶（中）**= 回復 60・持てる数 3。使うと 45f（0.75 秒）は次のアイテムを使えない。最初は何も持たない。
- **ドロップ**（`EnemyDef.drops`。種類ごとに別々の確率で抽選）: 子鬼 10%・小蝙蝠 5%・猪 20%・提灯 18%・岩鬼 小 35% + 中 30%。ボスと**ボスが呼んだ手下は落とさない**（呼ばせて稼げない）。**救済**（`ITEM_RULES.pityKills 8`）: 何も落ちない撃破が 8 回続いたら、次の撃破で必ず薬瓶（小）が落ちる（運の悪い回で回復がゼロにならない）。いっぱいなら落ちない。デモ 1 周の期待値は、小 約 2.3 本 + 中 約 0.3 本（満タンから使い切れば体力 約 90 ぶん）。落ちたものは拾う操作なしでストックに入り、出た敵の頭上に「＋薬瓶（小）」の文字・緑の光・音。
- **使う**: 選んでいるアイテムを使う（`Inventory.use`）。**体力が満タン・持っていない・使い直しの待ち**のときは使わず、数も減らない（満タン・空のときは「使えない」音）。使えたら `Player.heal`（死んでいれば回復しない）、緑の光・回復量の数字・音（`potion`）。**一瞬で回復する**（飲む動作の硬直はない = 窮地で押せる代わりに、待ちと数の制限で釣り合わせた）。
- **`Inventory`**（`src/combat/inventory.ts`。純粋）: 持っている数・選んでいるアイテム・使い直しの待ち・ドロップの抽選と救済・`serial`（UI が変化を検出）。体力の回復そのものは `Game` が `Player.heal` を呼ぶ。

### 再利用できるスロットボタン（アイテム欄・のちのスキル欄）
- **操作**: **タップで「選んでいるもの」を使う**。**長押し（0.26 秒）または上へ 24px 払う**と一覧が開き（ボタンから上へ 72px ずつ）、**指をすべらせて離すと、その選択肢が「選んでいるもの」になる**（使いはしない）。ボタンの近くで離す・一覧と逆へ動かすと取り消し。一覧は兄弟の `div.slot-menu`（ボタンの押し込みの scale に巻き込まれない）に `position: fixed` で並べる。
- **分割**: ジェスチャの判定は**純粋な状態機械** `SlotGesture`（`src/input/slot-gesture.ts`。指の位置はボタンの中心からの差・時刻は呼ぶ側が渡す。tap / open / hover / choose / cancel）。DOM は `SlotButton`（`src/input/slot-button.ts`。Pointer Events・一覧の表示・ボタンの顔。`setFace` / `setOptions`、`onTap` / `onChoose`）。ゲームの中身（何を使うか）は知らない。**スキル欄を足すときは、`#btn-skill` を HTML に置いて `SlotButton` をもう 1 つ作り、一覧の中身（`SlotOption`）と `onTap` / `onChoose` を渡すだけ**（一覧の向きは `gesture.dirX / dirY` で変えられる）。
- **入力の流れ**: タップ = `InputIntent.itemPressed`（sim が扱う = 使用はステップ内で決まる）、一覧からの選択は UI の操作なので `TouchInput.onItemChoose` で `Game` へ直接伝える（`InputIntent` には載せない）。キーボードは U = 使う、I = 選択を次へ（`itemCycle`）。

**検証**: `src/combat/mystical.test.ts`（発動・クールダウン・続く長さ・割合・間引きの等間隔・切れたステップから等倍・`visualAlpha` が戻らない）、`src/game/mystical-combat.test.ts`（本物の `Player` / `Enemy` / 弾との結合: 猪の突進をロールで避けて発動する押し始めの範囲・早すぎ遅すぎは発動しない・発動中は無敵で敵だけが 1/5・プレイヤーは等倍・避けた攻撃は切れたあとに刺さらない・クールダウン中は発動しない・回避の無敵と被弾後の無敵の区別・鬼火も避けて発動し弾はすり抜ける・弾も 1/5）、`src/combat/inventory.test.ts`（数・上限・使用の結果・選択・ドロップの抽選・救済・データの整合）、`src/input/slot-gesture.test.ts`（タップ・開く・選ぶ・取り消し・向き）。撮影: `npm run shot` にミスティカル発動（縁の色・ゲージ・文字）とアイテム欄（ボタン・長押しの一覧・選び替え・使った直後）を追加。全ロードアウトでランダム入力（回避・アイテム・選択の切替を含む）を長く回して例外・不正な値なし。

**まだ入れていないもの**: スキル欄そのもの（部品は用意した）、薬瓶以外のアイテム（毒消し・攻撃の補助）、飲む動作（硬直）のアニメ、ミスティカル中の専用の反撃技・攻撃力の上昇、ドロップを拾う演出（飛んでいく光）、アイテムの数のセーブ（ステージ構造ができてから）。

**代償・既知の問題**
- **実機で未確認**。確かめること: ミスティカルの**受付の広さ**（突進・鬼火・ボスの技を回避の無敵で避けたとき、狙って成功させられるか・簡単すぎないか。猪の突進では、ロールを押す遅れが十数フレーム幅で成功する）、**時間が遅くなる気持ちよさ**（敵が 1/5 でカクつかず見えるか。描画の補間が効いているか）、**3 秒の長さ**（反撃に足りるか・長すぎて簡単すぎないか）、8 秒のクールダウン（簡単になりすぎないか・待ちが長すぎないか）、演出（縁の色・ゲージ・「MYSTICAL」・音）、**薬瓶の落ちる頻度**（デモ 1 周で何本拾えるか・回復の価値・ボスまで足りるか）、**アイテムボタンの位置**（回避・ガードの左。親指が届くか）と**長押し + スワイプ**の操作感（開く時間 0.26 秒・選択肢の間隔 72px・誤って使ってしまわないか・iPad Safari の長押しで選択・メニューが出ないか）、回復が即時で強すぎないか（待ち 0.75 秒・持てる数 5）。
- ミスティカルの 3 秒のあいだ、敵の予告の床表示も 1/5 の速さで消えるので、**遅くなった敵の黄色い帯が画面に残る時間が長い**（見やすさを見る）。
- ミスティカル中のヒットストップ（sim を止める）は等倍なので、ヒットストップの長さは変わらない。敵は 1/5 の速さなので、ヒットストップの間に敵が止まる感覚は薄い。
- 敵が間引かれる間、**敵の被弾リアクション（ひるみ・ノックバック）も 1/5 の速さ**になる（反撃が刺さった敵は、ゆっくり吹き飛ぶ）。ひるみの時間も 5 倍に伸びるので、ミスティカルのあいだは敵をほぼ一方的に殴れる（意図どおり）。
- 倒した敵の演出（消える時間）も遅くなる（`deathFrames` は敵の時間）。

## ADR-031 成長・スキル・武器・ステージの方針と、スキル欄・剣技（M6-1）

**状態**: 採用（2026-10-04、M6-1）。ADR-030 の続き。本人の指示（「スキル欄を作りスキルを考えていきましょう。一連の剣技などのアクティブスキルとパッシブスキルなどのスキルレベル方式。成長は dex / int / agi / str などにステ振りする形式。武器の種類や強化もおいおい拡充。ステージは現在デモ版の闘技場だが、最終的にはダンジョンやオープンフィールドで、地形や障害物も戦闘に生かす。実装の順は考慮」）を受けて、全体の方針と順序を `docs/07-progression-and-world.md` にまとめ、**M6-1（スキル欄とアクティブスキル）**を実装した。

### 全体の方針（詳細は docs/07）
- **順序**: M6-1 スキル欄 + 剣技 → M6-2 成長の土台（経験値・レベル・ステ振り・`Modifiers`・セーブ・キャラ画面）→ M6-3 スキルツリー（スキルポイント・パッシブ）→ M6-4 スキル拡充 → M7-1 世界の土台（障害物の衝突・遮蔽を `World` に束ねる）→ M7-2 地形を戦闘に使う → M8 武器の拡充と強化 → M9 ダンジョン → M10 オープンフィールド。**成長・スキルはステージに依存しない**ので闘技場のまま先に作れる。地形は戦闘の中身が固まっているほど作りやすい。武器は 1 種ごとにモーション制作が重いので土台の後。
- **成長**: STR / DEX / AGI / INT / VIT（初期各 5、レベルごとにステ 3 + スキル 1。上限 Lv30。1 ポイントの効きは小さく、30 を超えると逓減）。**難易度は育てても崩れない**（初期のままで今のボスまでの歯応えを保つ）。
- **`Modifiers`**: ステータス・パッシブ・（将来）武器・装備の効果は**1 か所の純粋関数に集計**し、戦闘のコードは `Modifiers` だけを読む（M6-2）。武器の強化・装備・状態異常が後から入っても戦闘のコードを触らない。
- **スキルのレベル**: 1〜5。威力・クールダウンが良くなり、**連なりが伸びる**。習得はスキルポイント（Lv n にするには n ポイント）と前提のあるツリー（M6-3）。振り直しは無料。
- **世界への約束**（M6 の間も守る）: 成長・スキル・アイテムの状態は闘技場（`Encounter` / `arena`）に依存させない。世界への問い合わせは 1 か所の入口に集める（M7-1 の `World`）。出現と進行は「トリガー」で考える（M9 の部屋のトリガーに差し替えられる形）。

### 剣技（アクティブスキル。M6-1）
- **（この項の「新しいモーションは作らない」は ADR-032 で置き換えた。剣技は専用モーションを中心にする。連なり・レベル・クールダウンなど他の部分は有効）** **剣技 = 既存の攻撃（`ATTACKS`）の連なり**（`SKILLS`。`src/combat/data/skills.ts`）。1 回の入力で、決まった順に技が**押さなくても自動で続く**。新しいモーションは作らず、**既存の技のつなぎ（`next` / `branches` の辺）に沿った連なりだけ**を作る = 姿勢のつなぎ目が自然で、手付けの工数が要らない。辺であること・連なりの途中の受付（`cancelFrame`）が持続のあとであることは**テストで保証する**（新しい剣技を足してつなぎが不自然ならテストが落ちる）。
- **レベル 1〜5**（`SKILL_LEVEL_MAX`）: 威力 +8%/Lv・クールダウン −6%/Lv。**`minLevel` を持つ段が解放されて連なりが伸びる**（五月雨 = Lv1 で 3 段、Lv3 で 4 段、Lv5 で 5 段）。威力は `AttackerView.attackPower` に載せる（ダメージ・ノックバック・ヒットストップ・地面を叩く演出に掛かる既存の仕組み）。段ごとに倍率（とどめを強く）。
- **コスト = クールダウン**（スキルごと。6〜14 秒）。ゲージ（MP）は足さない（画面の部品が増える・管理が増える・クールダウンはボタンの扇だけで読める）。INT で縮む（M6-2）。
- **武器の系統ごと**（`family`。**中身の一覧は ADR-032 で専用モーションの剣技に置き換えた。以下は M6-1 当初の案**）: 片手剣（盾付きも）= 燕返し（斬 → 跳び退き → 突き込み）・五月雨（連なる斬り。レベルで伸びる）・旋風（二連 → 回転斬り）・疾風突き（踏み込み → 切り返し）。大剣 = 断岩（溜めなしの重い縦斬り → 返し）・大渦（斬り → 回転して薙ぐ）・崩山（二連 → 地を叩き割る）・昇竜（斬り上げ → 叩きつけ）。装備を替えるとスキルボタンの中身が替わる。
- **`SkillBook`**（`src/combat/skills.ts`。純粋）: レベル・系統ごとの選択・クールダウン・`prepare`（選んでいるスキルの連なりを返す。クールダウンには入らない）→ `start`（Player が**実際に始められたとき**だけクールダウンに入る = 始められない状態で押しても消費しない）。**M6-1 は習得の仕組みがないので、全スキルを Lv1 で最初から使える**（M6-3 のスキルポイントで 0 から振る形になる。`SkillBook` はもう `level 0 = 使えない` を扱える）。
- **`Player` の連なりの実行**: `requestSkill(run)` は**1 ステップだけ有効**な頼み（`step` の終わりで捨てる）。始められるのは、立っている・走っている（回避の次の優先）・**攻撃の次段の受付以降**・**回避のキャンセル受付以降**。始まったら `skillSerial` / `lastSkill` を更新し、Game がそれを見てクールダウン・演出を起こす（Player は Game を知らない）。以降の段は `stepAttack` が**受付（`cancelFrame`）のたびに自動で** `beginAttack(次の技, power, continuing = true)` する（向きはスティック・ロック対象）。**被弾で途切れる**（`takeHit` が連なりを捨てる）、**持続のあとの回避キャンセルで連なりを捨てられる**、ふつうの攻撃を始めたら連なりは終わる（`beginAttack` が連なりを消し、剣技の段だけが付け直す）。受付のあいだに別のスキルを頼まれたらそちらを始める（スキルから別のスキルへ）。**始まるのは `step` の中**（攻撃の開始と同じ位置）に置いた: `step` の前で始めると 1 フレームずれて、手付けの前進と接地足のそろえ（ADR-012）が崩れるため。
- **UI**: スキルボタン（アイテムボタンの左。`#btn-skill`）は**アイテム欄と同じ `SlotButton`**。タップで使う・長押しか上への払いで一覧（その系統のスキル。名前・`Lv n`・剣の絵）・すべらせて選ぶ。**`SlotButton` を汎用にした**（`SlotOption` = `badge` / `dim` / `icon: 'bottle' | 'blade'`、`setCooldown(ratio)` = ボタンの上に暗い扇が時計回りに消える。アイテムボタンにも使い直しの扇が出る）。入力は `InputIntent.skillPressed` / `skillCycle`、キーボードは O = 使う、P = 選択を次へ。技名が頭上に出て（`dmg-skill`）、音（`skillStart`）が鳴る。

**検証**: `src/combat/skills.test.ts`（データの整合 = 連なりが辺・系統と合う・受付が持続のあと・解放レベルが単調・レベルで威力 / クールダウンが単調、`skillSteps` のレベルによる伸び、`SkillBook` の選択・順送り・prepare / start / step・レベル 0・serial・reset）、`src/game/skill-combat.test.ts`（本物の `Player` との結合: 押さなくても連なりが順に出る・段ごとの威力・当たるダメージ・レベルで 5 段・大剣・始められない状態では始まらず頼みは 1 ステップで捨てる・被弾で途切れる・回避キャンセルで捨てられる・攻撃 / 回避の受付から始められる・ガード中は始められない・盾付きでも使える）。撮影: `npm run shot` にスキル欄（連なりの途中・クールダウンの扇・一覧・選び替え・大剣のスキルボタン）を追加。全ロードアウトでランダム入力（スキルの連打・選択の切替を含む）を長く回して例外・不正な値なし（手元）。

**まだ入れていないもの**: 習得の仕組み（M6-3）、パッシブ（M6-3）、INT による短縮（M6-2）、剣技ごとの専用モーション・アーマー・無敵・飛ぶ斬撃、魔法系のアクティブ、スキルの説明を見る画面（M6-3 のスキル画面）、盾専用・パリィ連動のスキル。

**代償・既知の問題**
- **実機で未確認**。確かめること: スキルボタンの位置（アイテムの左。親指が届くか・誤タップしないか）、**剣技が気持ちよいか**（押さなくても進む連なりの速さ・つなぎ目の姿勢・当たりが空振りしたときの見た目・全部で何秒か）、威力（+30% 前後）と**クールダウン**（6〜14 秒）の釣り合い、**ふつうのコンボと比べて使う理由があるか**（現状は「自動で続く + 威力が高い」だけ。アーマー・無敵・専用モーションはまだ無い）、一覧の見やすさ、技名の文字、音。
- 剣技は**既存の技のつなぎだけ**なので、「連なりの中身」は今のコンボで手動でも出せる（入力が要らない・威力が上がる・クールダウンがあるだけの差）。**専用モーション・無敵・アーマーなど「それだけの価値」**は、M6-4（スキル拡充）で足す候補（`SkillStepDef` に `armor` / `invulnFrames` / `hitboxScale` を足す形）。
- 連なりの 1 段目に、いまのコンボの途中の姿勢から入ると、つなぎ目が 1 段目の予備動作へクロスフェードで入る（ふつうに 1 段目を始めるのと同じ）。
- 連なりは受付（`cancelFrame`）で次へ進むので、**入力のない完璧なテンポ**で続く（手動より速い）。遅い・重い剣技にしたいときは段ごとに待ち（`holdFrames`）を足す。

## ADR-032 剣技は専用モーション・多段ヒット・スーパーアーマー（M6-1 の続き）

**状態**: 採用（2026-10-04）。ADR-031 の「剣技 = 既存の攻撃の連なり・新しいモーションは作らない」を**置き換える**（スキル欄・`SkillBook`・レベル・クールダウンなど他の部分は有効）。
本人の指示: 「**剣技は新たな専用モーションである必要がある**（途中に既存のものが混じるのはあり）。**3 連撃以上、途中でキャンセルできる**もの。**無敵はなし**。**敵の攻撃でキャンセルされるスキルと、一部はスーパーアーマー**。片手剣 = ①右上から斜め斬り・下から逆に斜め斬り・左上から右下へ・逆に下から斜め斬りの 4 連 ②フェンシングのような高速の突き 5 連（出が早く速い。前方に長い細い範囲）③回転斬り 2 周半（前方 180° は 3 ヒット・後方は 2 ヒット）。大剣 = ①右払い・左払い・頭上から地面へ叩きつけ（地面と周囲に衝撃波）②剣を後ろへ振りかぶって少し溜め → ほぼ一瞬で前へダッシュ → 踏み込み斬り（前方かなり長く広い・1 回）。**参考にして他にも案を考える**。レベルでモーションが進化する案（未決定）」。

### 決定
- **専用の攻撃は別の表 `SKILL_ATTACKS`**（`src/combat/data/skill-attacks.ts`。`findAttack(id)` が `ATTACKS` → `SKILL_ATTACKS` の順で探す）。剣技の攻撃は出が速い（五月雨は 0.15 秒）・全体が長い・多段ヒットなど、**`ATTACKS` 全体にかけている不変条件（出 ≥ 8f・全体 ≤ 60f など）の外**にある。表を分けて、既存の検査を緩めずに済ませる。手付けクリップは `AUTHORED_ATTACKS`（盾版・大剣版の焼き込みの対象）に同じように登録する。連なりの途中に既存の技（`ATTACKS`）を混ぜてもよい（四ツ葉の前半は combo1 / combo2 を `reuse()` で速めて使い、後半を左右反転の新しい動きにした）。
- **連なりのつなぎの保証**: 「`next` / `branches` の辺であること」をやめ、**次段のクリップの `continueFrom` が前段のクリップを指し、その時刻が前段の受付時刻（`cancelAt`）に一致する**ことをテストで保証する（姿勢が跳ばない）。
- **多段ヒット（`AttackDef.windows`）**: 当たりの窓の列（`HitWindow`: 開始・終了秒、当たり判定の形、`yawOffset`（向きのずれ。後ろの半円は π）、`damageScale` / `knockbackScale` / `hitStopScale`、`group`）。**同じ `group` の窓は当たりの記録を共有**する（1 体に 1 回）。違う group に変わると記録を消すので、また当たる（五月雨・竜巻は窓ごとに別 group = 毎回当たる。崩山の叩きつけは直接の斬りと衝撃波を同じ group にして 1 体に 1 回）。窓の列は時間順で重ならない（テスト）。
- **円の当たり（`HitboxDef { kind: 'circle', offset, radius }`）**: 攻撃者の正面 `offset` の点を中心にした円。地面の衝撃波に使う（演出の輪 `GroundFx` と大きさを合わせる）。`hitboxReach` で予告の幾何も扱える。
- **スーパーアーマー（`AttackDef.armor` = `{ from, to, breakDamage }`）**: 区間のあいだ、`breakDamage` 未満の攻撃は**ダメージは受けるが、ひるまず・飛ばされず・技が続く**（短い無敵 24f はつく = 連続で削られないための、被弾直後の無敵と同じもの。剣技の無敵ではない）。`breakDamage` 以上（岩鬼・ボスの重い攻撃）と、区間の外はふつうに割られて途切れる。倒されるときはふつうに倒れる。Game は `Player.armorSerial` を見て「ARMOR」の文字と金属音（被弾の音のかわり）を出す。アーマーなしの技（四ツ葉・五月雨・払い）は被弾で途切れる。
- **回避でのキャンセル（`AttackDef.dodgeCancelAt`）**: 多段・長い技を途中でやめられる。省略は従来どおり持続の終わりから。**溜めのある技は持続（`activeStart`）より前にも置ける**（一閃は溜め始めて 0.3 秒から回避でやめられる）。
- **無敵は付けない**。守りは「アーマー」「回避でやめられる」「速さ」で作る（回避・ミスティカルが無敵の役目）。

## ADR-033 成長（経験値・レベル・ステ振り・スキルポイント）・一時停止メニュー・同心円の選択（M6-2）

**状態**: 採用（2026-10-04、M6-2）。ADR-031 の続き。本人の指示（M6-1 の実機確認「感触はとても良い」のあと）: 「**数値はレベルで滑らかに伸ばし、モーションが変わるのは Lv4 と Lv7 の 2 段階だけ（最大レベル 10）**。スキル（と道具）の選択は縦に並べると選びづらいので、**スワイプ先を同心円上に配置**する。**経験値でレベルアップ**し、**スキルポイントとステ振り**がそれぞれできる（**スキルポイント 1、ステ振り 3 ポイントずつ**）。**ボスの召喚雑魚敵では経験値は 0**。ステ振り・スキルポイント画面は**一時停止画面**にする（設定などの画面も同じところに配置、機能が増えるごとに順次拡大）」。設計の元は `docs/07` §3。モーションの進化（Lv4 / Lv7）は M6-3b（ADR-034）。

### 成長（`src/combat/growth.ts` + `data/growth.ts` + `data/stats.ts`。純粋）
- **経験値とレベル**: 敵を倒すと `EnemyDef.xp`（子鬼 20・小蝙蝠 6・暴れ猪 40・提灯 35・岩鬼 100・ボス 250 = デモ 1 周で **660**）。次のレベルまで `round(27 × level^1.1)`。デモ 1 周で Lv 7〜8、5 周で Lv 14〜16、上限 Lv 30。**ボスが呼んだ手下（`summonedIds`）は経験値 0**（呼ばせて稼げないように。ドロップと同じ扱い）。経験値は**撃破の合図**から `Growth.addXp` に渡す（`Encounter`・闘技場を経由しない = ステージが変わっても同じ状態を持ち越せる。docs/07 §5.3）。
- **ポイント**: レベルが 1 つ上がるごとに **ステータスポイント +3・スキルポイント +1**。**不変条件: 未使用 + 振った = もらった**（`(level − 1) × 点`）。テストでランダムな操作を長く回して保証し、読み込み時に壊れていたら振り分けを初期に戻してポイントを返す。
- **ステータス**: STR / DEX / AGI / INT / VIT（初期各 5）。**1 ポイントの効きは小さく**（1% 前後）、振った点が 30 を超えた分は**効き半分**（逓減）。数値は `data/stats.ts` に集め、戦闘は `Modifiers` だけを読む:

  | 効く先 | 1 点あたり（効きに使う点） |
  |---|---|
  | **STR** | ダメージ +1.0%・ノックバック +0.5% |
  | **DEX** | 攻撃の速さ +0.5%（`AttackDef.rate` に掛かる）・パリィの受付 10 点で +1f |
  | **AGI** | 移動 +0.6%・回避の無敵 8 点で +1f・ミスティカルの長さ +3f（0.05 秒） |
  | **INT** | スキルのクールダウン −0.8%（下限 0.5 倍）・スキルの威力 +0.6%・薬瓶の回復 +1% |
  | **VIT** | 最大体力 +2・受けるダメージ −0.3%（下限 0.7 倍） |

  全部を 1 つに振る極端な場合（Lv30・87 点 → 効く点 58.5）でも、ダメージは +58.5%。初期のままなら全て等倍（既存のテストが変わらない）。
- **`Modifiers`**（`src/combat/modifiers.ts`）: ステータスから集計する純粋関数（`computeModifiers`）。**戦闘のコードは数値を `Player.mods`（`Modifiers`）からだけ読む**: `Player.setModifiers`（最大体力 = 増えた分は体力も増える・移動・攻撃の速さ（攻撃を始めるたびに `rate` を掛けた**写し**を使う。元のデータは書き換えない）・回避の無敵・パリィの受付・受けるダメージ（最低 1。ガードの削りにも掛かる。アーマーを割るかどうかは元のダメージで判定））、当たり判定（`AttackerView.damageMul` / `knockbackMul`）、`SkillBook.prepare(family, powerScale)` と `start(id, cooldownScale)`、薬瓶の回復、`Mystical.trigger(bonusFrames)`。パッシブ・装備が入るときは `computeModifiers` に引数を足すだけで戦闘のコードは変わらない。
- **スキルのレベル**: 1〜**10**（`SKILL_LEVEL_MAX`）。**全スキルを Lv1 で習得済みから始め**（M6-1 の感触を保つ。習得制・前提つきのツリーは今は入れない）、**スキルポイント 1 でレベルが 1 上がる**（1 本を Lv10 にするのに 9 ポイント。Lv30 のスキルポイント 29 では 3 本ぶん = 全部は取れない）。数値は**なめらかに**伸びる（威力 +5%/Lv・クールダウン −3.5%/Lv。Lv10 で +45% / −31.5%）。**モーションが変わるのは Lv4 と Lv7 の 2 段階だけ**（M6-3b。`SkillDef.evolutions` が画面の説明）。
- **振り分けの取り消し**: **−** は**メニューを開いてから振った分だけ**戻せる（間違えて振っても、閉じるまでは取り消せる）。**全部振り直しは、いつでも無料**（二度押しで実行。試行錯誤を罰しない。docs/07 §2.3）。
- **セーブ**（`src/combat/save.ts` 純粋 + `src/platform/storage.ts`）: `localStorage` の `mw.save`（JSON。`{ version, level, xp, statPoints, skillPoints, stats, skills, selected }`）。**版番号 + 移行関数**（`MIGRATIONS[n]` が n → n + 1）。壊れている・版が新しすぎる・使えないときは「セーブなし」で始める（ゲームは止めない。Safari のプライベートブラウズは例外を投げるので `try/catch`）。保存のタイミング: レベルアップ・振り分け・スキルの選択・戦闘の終わり・メニューを閉じるとき・タブが隠れるとき。**戦闘の途中の状態（敵・体力・アイテム）は保存しない**。サンドボックス（`?sandbox=1`）は読み書きしない。装備（`mw.loadout`）・操作ガイド（`mw.guide`）は従来のキー。

### 一時停止メニュー（`src/ui/pause-menu.ts` + `src/ui/menu/*.ts`）
- 右上の「メニュー」ボタン（旧「技表」ボタン）・M キー・Escape で開き、**開いているあいだは戦闘が止まる**。未使用のポイントがあるとボタンとタブに金の点。
- **タブ式**で、`MenuTab`（`id` / `label` / `mark` / `build` / `refresh`）を満たすものを `addTab` で足す。メニュー本体は中身を知らない = **機能が増えるごとにタブを足していける**（装備・持ち物・図鑑など）。いまは **ステータス**（Lv・経験値・ポイント・＋/−・効果の文章）・**スキル**（系統ごと・Lv・威力・クールダウン・進化の説明）・**技表**（旧の技表。`MovesTab`）・**設定**（操作ガイドの入り切り・「最初から」= セーブの消去、二度押し）。
- ＋/− は押し続けると連打（`onPress`）。縦に長い本文は `data-scroll` を付け、`installGestureGuards` の touchmove 抑止から**除外**した（これまで touchmove を全部止めていたので、長いメニューが iPad でスクロールできなかった）。

### 同心円の選択（`src/input/slot-layout.ts`。純粋）
- 縦に並べると選びづらいので、アイテム欄・スキル欄（`SlotButton` 共通）の一覧を**ボタンを中心にした同心円（扇）の上**に並べる。真上を中心に、内側の輪（半径 116px・5 個まで）から詰め、次の輪（200px・8 個まで）へ。隣どうしの中心は約 76px（選択肢の円 64px が重ならない）。番号は時計回り（左から右へ読める）。選択肢が少ないあいだは扇の中心に寄る（指の移動が小さい）。
- **指の向き（角度）と距離（輪）で選ぶ**: 半径がいちばん近い輪の中で、向きがいちばん近い選択肢。**輪より遠くまで払っても、その向きの選択肢が選ばれる**（払う操作に強い）。ボタンの近く（54px 未満）・扇の端から外れた向き（半ピッチ + 38° 以上）は選ばない = 取り消し。輪の目安の弧（点線）を描く。`layoutSlots` / `pickSlot` / `ringArcs` は純粋関数で、`SlotGesture`（状態機械）がそれを使う。

### 検証

## ADR-034 剣技のモーション進化（Lv4 と Lv7）・数値のなめらかな伸び（M6-3b）

**状態**: 採用（2026-10-04）。ADR-032 の「レベルでモーションが進化する案（未決定）」に決着をつける。ADR-033（スキル Lv1〜10・全スキル Lv1 から・SP 1 / Lv）の続き。本人の指示: 「**あなたの剣技の案を採用する**（`docs/07` §2.1.2）。**数値はレベルで滑らかに伸ばし、モーションが変わるのは Lv4 と Lv7 の 2 段階だけ**にする案も採用（最大レベル 10）」。

### 決定
- **数値はなめらか・モーションは 2 段階**: 威力 +5%/Lv・クールダウン −3.5%/Lv（Lv10 で +45% / −31.5%。ADR-033）は、どのレベルでも同じ連なりのまま伸びる。**連なりの動き（攻撃 id）が変わるのは Lv3 → 4 と Lv6 → 7 の 2 回だけ**（テストで保証: 全スキル・全レベルで連なりの差分が Lv4 / Lv7 にしか出ない）。進化は必ず「当たりが増える・派手になる」（Lv1 < Lv4 ≤ Lv7 の当たりの数）。
- **進化の手段は 2 つだけ**（`docs/07` §2.1.3 の 1 と 2。3「窓の数を Lv ごとに増減」は、クリップに焼かれた時刻と食い違うので採らない）:
  - **段を足す**（`SkillStepDef.minLevel`。既存）: 四ツ葉 Lv4 の 5 つ目・Lv7 の 6 つ目、崩山 Lv7 の 4 つ目、一閃 Lv4 の 2 つ目・Lv7 の 3 つ目。
  - **段を別の動きに差し替える**（`SkillStepDef.evolve: [{ minLevel, attack }]`。新設）: 満たしている中でいちばん高い `minLevel` の攻撃を使う（`stepAttackAt`。並び順は問わない）。段の数・威力の倍率は変わらず、`skillSteps(def, level)` が差し替え後の攻撃 id を返す。戦闘のコード（`Player` の剣技の連なり）は触らない。五月雨 5 → 7 → 9 連、竜巻 2.5 → 3.5 → 4.5 周、崩山の叩きつけ → 飛翔崩山。
- **差し替え・追加したクリップも `continueFrom`（前段の受付時刻 `cancelAt` の姿勢から続く）を守る**。差し替えで前段が変わるので、継ぎ目のテストは**全レベルの連なり**（`skillSteps(def, 1..10)`）を走査する（これまでは基本の `steps` だけだった）。例: 崩山 Lv7 の地裂は、基本の叩きつけではなく飛翔崩山の `cancelAt`（保持 0.56 秒）から続く。

## ADR-035 会心（会心率・会心ダメージ）（M6-3a）

**状態**: 採用（2026-10-04）。ADR-033（`Modifiers`・ステータス）の続き。本人の指示（M6-2・M6-3b の実機確認「かなり良い」のあと）: 「**会心率や会心ダメージもあって良い**」。設計の元は `docs/07` §3.2（DEX = クリティカル率と倍率）。

### 決定
- **会心率・会心ダメージは `Modifiers` に集計する**（`critRate` = 0..1、`critDamage` = 倍率）。戦闘のコードは数値を `Player.mods` からだけ読む（ADR-033 の原則）。パッシブ（M6-5）が入っても `computeModifiers` に引数を足すだけで済む。
- **初期は会心率 5%・会心ダメージ ×1.5**（`src/combat/data/crit.ts`）。**DEX が効く**: 効きに使う点 1 あたり 会心率 +0.5%・会心ダメージ +0.015（逓減は ADR-033 のまま。30 点で 20% / ×1.95）。会心率の上限は 75%（常時会心にならない）。DEX は「攻撃の速さ・パリィの受付・会心」の技術のステータスになる。STR は「当たったときの重さ」（ダメージ・ノックバック）で、役割が分かれる。
- **命中 1 回ごとに抽選**（`resolvePlayerAttack(attacker, targets, onHit, rng)`）: `rng() < 会心率` なら会心。多段の技（五月雨 9 連・竜巻 9 ヒット）は**窓ごとに別々に抽選**するので、手数の多い技ほど会心が出やすく、1 発の会心の重さは変わらない。会心率 0（古いテスト用の見え）では乱数を引かない。**乱数の既定は `NEVER_CRIT`（常に会心しない）**: テストの結果が乱数で揺れない。ゲームは `Game.critRng`（既定 `Math.random`。ドロップの `dropRng` と同じ形で、開発・テストで差し替えられる）を渡す。
- **会心の効き**: ダメージ × 会心ダメージ（STR・溜め・反撃など他の倍率と掛け算）、ノックバック ×1.2、ヒットストップ +3 フレーム（上限 24 は守る）。`HitEvent.crit` は**会心のときだけ `true` で付く**（付かなければ通常の命中。既存の `toEqual` の比較を壊さない）。敵の体勢・アーマーを割る重さの判定はダメージで見るので、会心は重い攻撃を割りやすくする（STR と同じ向き）。
- **会心の見た目**: ダメージ数字が**大きな金色の数字（末尾に「!」）**、画面の揺れ ×1.35・エフェクトの強さ ×1.3、命中音の上に重ねる**きらめく高音の `crit`**（`SFX.crit`）。とどめ・反撃でも会心が優先して読める。
- **敵は会心しない**（今は）。弾き返した鬼火・反射した弾にも会心はない（ダメージが決まった弾なので）。

### 検証
`modifiers.test.ts`（初期 5% / ×1.5・DEX だけが効く・単調・上限・逓減・画面の文章）、`combat.test.ts`（既定は会心なし・会心でダメージ倍・ノックバック・ヒットストップ・境界（等しければ会心でない）・会心率 0 で乱数を引かない・STR と掛け算・命中ごとに 1 回ずつ（2 体 = 2 回）・同じ敵への別の窓は別の抽選）、`feedback.test.ts`、`growth-combat.test.ts`（本物の `Player` で DEX → 会心率 / 倍率。同じ乱数 0.1 で初期は通常・DEX 20 は会心）、`sfx.test.ts`（`crit` を含む）、`sfx-check`（クリップ・DC のずれなし）。撮影に会心のシーン（乱数を固定して通常と会心を 1 発ずつ。ダメージが ×1.5・数字が「15!」）。

### 代償・既知の問題
- **実機で未確認**。確かめること: 会心の出る頻度（5% で気づけるか。五月雨・竜巻の多段で会心が出る気持ちよさ）、金色の数字の見やすさ（ほかの数字と間違えない・うるさすぎない）、音の高さ・大きさ（ヒットの音を邪魔しないか）、揺れ・ヒットストップの重さ、DEX を振ったときの実感。
- 会心率・会心ダメージの効き（DEX 1 点 = +0.5% / +0.015）は仮置き。極端な DEX 集中（Lv30・87 点 → 効く点 58.5）で 会心率 34%・×2.38。パッシブ（M6-5）で重ねるときの上限は `CRIT.maxRate`。
- 攻撃速度（DEX）と会心がどちらも DEX なので、DEX は強い選択肢になる。STR（ダメージの底上げ）との釣り合いは実機で見る。

## ADR-036 敵の色違い・段階（Tier）と、挑戦の進み具合（M6-4）

**状態**: 採用（2026-10-04）。ADR-033（成長）・ADR-035（会心）の続き。本人の指示（M6-2・M6-3b の実機確認「かなり良い」のあと）: 「**こちらの強化がされてきているので、敵についても色違いバージョンの追加などで段階的に強くなっていくような形にしましょう**」。`docs/07` §6 の「周回の強い難易度（敵の倍率）を入れるか」にここで答える: **入れる。倍率だけの周回ではなく、色違いの強化版（見た目が変わる）の段階として**。

  | 肆 黒 | 21 | ×4.6 | ×2.0 | ×1.18 | ×0.82 / ×0.7 | ×2.5 / ×3.0 | ×6.5 | ×1.6 | ×1.15 |
- **強化版は元の敵のデータから作る純粋関数**（`src/ai/data/enemy-variants.ts` の `makeVariant(base, tier)` と、キャッシュつきの `enemyDef(id, tier)`）。元の `ENEMIES` は書き換えない（段 1 = 元のオブジェクトそのもの）。**`id` は元の種類のまま**（見た目・効果音・召喚の種類は `id` で決まる）で、`tier` と名前（「紅の子鬼」。ボスは「紅蓮の大将」など固有）だけが変わる。新しい敵（M6 以降）を足しても、`ENEMIES` に書くだけで 4 段が自動で付く。
- **読みやすさの保証**（テストで全敵 × 全段を検査）: 予備動作は **下限 22 フレーム（0.37 秒）を下回らない**（元が短い技は元のまま）。**硬直（反撃の窓）・発生・持続は変えない**（強くなっても「見て避ける・隙を打つ」が成り立つ）。追う区間・アーマーの区間は予備動作の中に収める。割り込めない（9999）・割り込みなし（0）の約束は変えない。
- **倍率では表せない段階ごとの変化**（`flavorMove`）: **提灯**は段 3 で鬼火が 3 方向の扇、段 4 で 5 方向（1 発ずつは弱い）。**ボス**は号令で呼ぶ小蝙蝠が増える（3 → 4 → 5 体。呼ばれた手下も同じ段の強化版）、連弾が 7 発（段 3〜）、鬼火の輪が 12 発（段 4）。**全周の円**（岩鬼・ボスの地ならし）は段 3 で ×1.1・段 4 で ×1.2 に広がる（当たりの届く距離・床の予告の円・地面の演出の輪が一緒に広がる）。
- **弾のダメージの倍率**: 弾のダメージは弾のデータ（`PROJECTILES`）にあるので、技に `projectileDamageScale`（= 段のダメージ）・`projectileReflectScale`（= 段の HP の倍率）を持たせ、`Enemy.shot` → `spawnShot` → `ProjectileSystem.spawn` が弾に写す。**弾き返したときのダメージは段の HP に比例して伸びる**ので、「弾き返せば同じ段の提灯を一撃で倒せる」関係が全段で保たれる（テスト）。
- **色違いの見た目**（`enemy-visual.ts` の `TIER_COLORS`）: 種類ごとに段 2・3・4 で置き換える色（体・縁・目・割れ目など。書いていない色は元のまま）。**紅 = 赤〜橙、蒼 = 青〜青緑、黒 = 墨色に紫の縁・赤い目**で、元の色と被らないよう種類ごとに決めた（子鬼: 紫 → 紅 / 蒼 / 墨、岩鬼: 橙 → 赤 / 青 / 墨、など）。`EnemyVisual(kind, tier)` で作り、段階ぶんだけひと回り大きい。
- **挑戦の進み具合**（`src/combat/progress.ts` の `Progress`。純粋）: **クリアした最高の段**と**選んでいる段**。段 n をクリアすると n + 1 が解放される（最初は壱だけ）。解放済みの段はいつでも選び直せる。**セーブに入る**（セーブの版を 2 に上げ、版 1 → 2 の移行関数 `MIGRATIONS[1]` が「何もクリアしていない」進み具合を足す。古いセーブの成長は壊れない）。
- **段階の選び方（画面）**:
  - **開始画面**: 装備の選択の下に、段階の 4 つのチップ（名前・推奨 Lv）。未解放は暗く「？？？ / n をクリアで解放」で押せない。選んだ段はセーブされ、始めるとその段の敵が出る。
  - **リザルト**: 勝った段階の名前・**「次の段階『弐 紅』が解放されました」**・**「次の段階へ」**ボタン（押すと次の段で最初から）。「もう一度」は同じ段。
  - **メニューの「段階」タブ**（新設）: 4 段の一覧（名前・推奨 Lv と達成・敵の HP / ダメージ / 経験値の倍率・クリア済み / 選択中）、「この段階にする」、**「この段階で最初から」**（二度押し。いまの戦闘を捨てて、選んだ段で最初のウェーブから）。
  - **HUD**: レベルの下に段階の印（「弐 紅」。色つき）。最初のウェーブのバナーに段階の名前が添う（段 2 以上）。敵の HP バーの名前は強化版の名前。
- **経験値の釣り合い**: デモ 1 周の経験値は 壱 660・弐 1450・参 2640・肆 4291。**壱を 1 周で Lv 7、もう 1 周で Lv 9（弐の推奨 Lv 8）、弐を 1〜2 周で Lv 14（参の推奨）、参を 1 周で Lv 23**と進むので、各段を 2 周ほどすると次の段の推奨 Lv に届く（レベル上限 30 は肆の 1 周で届く = 肆の周回は育成より腕試し）。
- **評価（ランク）の基準**: 段が上がるほど敵が硬く痛いので、S / A / B の**時間・被ダメージの上限を段の倍率で緩める**（`TierDef.rankTime` / `rankDamage`。壱は従来どおり）。リザルトの `ResultSummary.tier`。
- **ウェーブの構成は全段で同じ**（敵の並びは変えず、敵が強化版になる）。段ごとに敵の数・種類を変える（段 3 から 2 体増やす、など）のは、実機で足りなければ次の段階で。

### 見つけた不具合の修正（同梱）

## ADR-037 パッシブスキル（習得制・前提つきのツリー・イベント効果）（M6-5）

**状態**: 採用（2026-10-04）。ADR-033（成長・`Modifiers`）・ADR-035（会心）の続き。設計の元は `docs/07` §2.2（パッシブの案）・§2.3（ポイントとツリー）。本人の指示（M6-4 の実機確認「問題ありません。続けましょう」）に従い、M6-3 本体として残っていた「パッシブ・習得制・前提つきのツリー」を入れる。

### 決定
- **パッシブは 12 種**（`src/combat/data/passives.ts` の `PASSIVES`。攻め 6・守り 5・補給 1）。常に効く。効果は **`Modifiers` のキーへの加算**（`effects: [{ key, perLevel }]`）。戦闘のコードは `Player.mods` だけを読む（ADR-033 の原則）ので、パッシブが増えても戦闘側の読み方は変わらない。数値はこの表だけで調整する。
  | 系 | 名前 | 最大 Lv | 1 レベルあたり | 前提 / 制限 |
  |---|---|---|---|---|
  | 攻め | 剣術習熟 | 5 | ダメージ +4% | 片手剣（盾付きも）を構えているあいだだけ |
  | 攻め | 剛力習熟 | 5 | ダメージ +4%・ふっ飛ばし +3% | 大剣を構えているあいだだけ |
  | 攻め | 会心の心得 | 5 | 会心率 +2% | |
  | 攻め | 急所突き | 3 | 会心ダメージ +0.1 | 会心の心得 Lv2 |
  | 攻め | 連撃の心得 | 5 | 連携・剣技の 3 発目以降のダメージ +4% | |
  | 攻め | 闘気 | 3 | 撃破で 4 秒、攻撃力 +2%（最大 5 回重なる） | 連撃の心得 Lv2 |
  | 守り | 見切り | 3 | 回避の無敵 +1f・ミスティカル +0.2 秒 | |
  | 守り | 受け流し | 5 | パリィ受付 +1f・パリィ成功で体力 +2 | 見切り Lv1 |
  | 守り | 追い打ち | 3 | 反撃（弾かれた敵・体勢を崩した敵への攻撃）のダメージ +6% | 受け流し Lv1 |
  | 守り | 身軽 | 5 | 移動 +2% | |
  | 守り | 鉄壁 | 5 | 受けるダメージ −3% | |
  | 補給 | 薬師 | 5 | 薬瓶の回復 +10%・ドロップ率 +5% | |
- **習得制**: アクティブの剣技は Lv1 から始まるが、**パッシブは Lv0（未習得）から始め、最初の 1 ポイントで習得する**。以降 1 ポイントで 1 レベル。**ポイントはアクティブの剣技と同じスキルポイント**（レベルごとに 1。ADR-033）を分け合うので、「剣技を伸ばす」か「パッシブを取る」かが選びになる。パッシブを全部取ると 52 ポイント（`PASSIVE_POINTS_TOTAL`）で、Lv30 の 29 ポイントでは全部は取れない。
- **前提つきのツリー**: 前提のあるパッシブは、前提のパッシブが指定のレベルになるまで習得できない（画面では暗く「前提: 会心の心得 Lv2」）。**前提を割る取り下げもできない**（会心の心得を Lv2 → Lv1 にすると、習得済みの急所突きが割れるので、先に急所突きを戻す）。前提の判定は純粋関数（`unmetPrereqs` / `brokenByLowering`）。段は 3 まで（心得 → 急所突き / 連撃 → 闘気 / 見切り → 受け流し → 追い打ち）。
- **系統つきの効果**: 剣術習熟・剛力習熟のように `family` を持つものは、**その系統の武器を装備しているあいだだけ効く**。ポイントは使ったままで、装備を替えるとその分は効かなくなる（画面に「いまは効かない」）。そのため **`computeModifiers(stats, passives, family)` に系統を渡す**。`Growth.modifiersFor(family)` は系統ごとの写しを持ち、ポイントや振り分けが変わったとき（serial）だけ作り直す。`Game.mods`（private の getter）が装備中の系統で引き、`setLoadout` で装備の id が替わったら `applyGrowth` で反映し直す。`Growth.modifiers`（ステータスだけ）はステータス画面の説明にだけ使う。
- **`Modifiers` に足したキー**: `comboDamage`（3 発目以降のダメージ）・`riposteDamage`（反撃のダメージ）・`parryHeal`（パリィ成功の回復）・`dropRate`（ドロップ率）・`killBuff`（闘気 1 回あたりの攻撃力の加算）。**VIT の「受けるダメージ」**は VIT だけなら下限 0.7（ADR-033）のまま、鉄壁を引いたあとは全体の下限 **0.5**（`damageTakenTotalFloor`）。会心率・会心ダメージの上限（ADR-035）は、パッシブを足したあとも守る。
- **イベントで発動する効果は Game が行う**（`Modifiers` は数値を持つだけ）:
  - **闘気**（`src/combat/buffs.ts` の `KillBuff`。純粋）: 敵を倒すたびに重なりが 1 つ増え（最大 5）、残り時間が満タン（240f = 4 秒）に戻る。時間が尽きると全部いっぺんに消える。攻撃力は `damageMul` に **`Modifiers.killBuff × 重なり`** を足す（Lv3・5 重なりで +30%）。闘気を取り下げる・最初から・撤退で消える。**ボスの呼んだ手下を倒しても重なる**（経験値は 0 のまま）。HUD のレベルの下に「闘気 ×3  +6%」と残り時間のバー（満タンで MAX）。
  - **受け流しの回復**: パリィ成功（敵の攻撃・弾き返した鬼火の両方）で `Modifiers.parryHeal` だけ体力が戻り、回復の数字が出る（最大体力を超えない）。
- **連撃の心得の数え方**: 連携の履歴（`Player.chain`）が 3 つ以上のとき。通常の連携の 3 段目以降と、剣技の連なりの 3 段目以降の両方（剣技の次段は `continuing` で履歴に足される）。1・2 段目・単発の技には効かない。
- **追い打ちの効き**: 既存の反撃（弾かれた敵・体勢を崩した敵への攻撃。`riposteDamageScale`）の倍率に、さらに `riposteDamage` を掛ける（`resolvePlayerAttack` の `AttackerView.riposteMul`）。
- **薬師のドロップ率**: `Inventory.rollDrops(drops, rand, chanceScale)` が確率に掛ける（上限は 100%）。救済（`pityKills`）は従来どおり。
- **セーブ版 3**: `passives`（id → レベル）を足す。版 2 → 3 の移行関数（`MIGRATIONS[2]`）が「パッシブなし（空）」を足すので、古いセーブの成長は壊れない。復元時に、レベルの上限・未知の id は丸め、**ポイントの合計が合わない・前提を割っているときは、スキルとパッシブをまとめて振り直す**（同じポイントなので、片方だけ戻すと合計が崩れる）。成長の不変条件（未使用 + 使った = 得た）は保たれる。
- **画面（メニューの「スキル」タブの下）**: 「パッシブ」の見出し・説明・カテゴリ（攻め / 守り / 補給）ごとのカード。カードは名前・系統のタグ（片手剣 / 大剣）・Lv・ピップ・**＋ / −**（ステータス・スキルと同じ。− はメニューを開いてから上げた分だけ）・ひとこと・**効果（いま）/ 次のレベル**・前提の行（満たすと緑、足りないと赤）。未習得で前提が足りないカードは暗く＋が押せない。系統の違う武器を持っているときは「いまは効かない（片手剣を装備すると効く）」の注記。「スキルを全部振り直す」はパッシブも戻す。

### 検証
`passives.test.ts`（表の整合: id・カテゴリ・最大 Lv・前提が実在し循環しない・数値が正・文章・`unmetPrereqs` / `brokenByLowering`）、`modifiers.test.ts`（パッシブを足した各キー・系統が合わなければ効かない・フレームは整数・受けるダメージの下限・会心の上限）、`growth.test.ts`（習得制・ポイントの増減・前提・取り下げ・`modifiersFor` の系統とキャッシュ・復元の丸めと食い違いの振り直し・ランダムな操作列で不変条件）、`save.test.ts`（版 3・版 2 からの移行・壊れた値の丸め）、`buffs.test.ts`（重なり・上限・残り時間の更新・失効・ratio・clear・serial）、`inventory.test.ts`（ドロップ率の倍率）、`passive-combat.test.ts`（本物の `Growth` / `Player`: 連撃の心得が連携の 3 発目からだけ・追い打ちが反撃にだけ・闘気が `damageMul` に足されて時間切れで戻る・剣術習熟が片手剣のときだけ効き大剣では剛力習熟が効く・見切り / 受け流し / 身軽 / 鉄壁 / 会心の心得が `Player.mods` に届く）。`npm run shot` に、パッシブ欄（12 枚・前提で暗い 4 枚・＋でポイント −1・ダメージの倍率が上がる）と実戦（受け流しでパリィして体力が戻る・敵を倒して闘気の印「闘気 ×1  +2%」）の撮影と検査を追加。

### 代償・既知の問題
- **実機で未確認**。確かめること: パッシブ欄の見やすさと押しやすさ（12 枚の縦スクロール・＋ / − の連打・前提の暗いカードの分かりやすさ）、**ポイントの釣り合い**（剣技を伸ばすかパッシブを取るかの選びが生きているか。52 ポイントに対し Lv30 でも 29。1 点の効き（ダメージ +4% など）が実感できるか）、闘気の手応え（HUD の印の見やすさ・4 秒の長さ・5 重なりで +30% が強すぎないか）、受け流しの回復量（+2 / Lv。Lv5 で +10）、鉄壁の下限 0.5（VIT 振りと重ねたとき硬すぎないか）、装備を替えたときの「いまは効かない」の分かりやすさ。
- **数値は仮置き**。とくに 会心の心得（+2% / Lv）と DEX の重なり、急所突き（+0.1 / Lv）、剣術習熟 +4% / Lv（Lv5 で +20%）は STR（1 点 +3% 前後）との釣り合いを実機で見る（`PASSIVES` の表 1 か所）。
- パッシブは**武器の系統（剣・大剣）だけを区別する**。盾付きの片手剣と素手の片手剣は同じ「剣」。新しい武器の系統（M8）が増えたら、`family` の型（`WeaponId`）と習熟の行を足す。
- 前提を割る取り下げはできないが、**メニューを開いたあとの「ステータス・スキルを全部振り直す」では前提に関係なく全部戻る**（ポイントは全部返る）。
- 闘気の重なりは**セーブしない**（戦闘のたびに消える）。ミスティカル・アーマーなど他の一時効果との重なり方は、実機で足りなければ。
- 魔法系・状態異常の効果は未実装（`PassiveKey` に足すだけで増やせる）。

### 代償・既知の問題
- **実機で未確認**。確かめること: 各剣技の**見た目と手触り**（居合の溜めの長さ・ダッシュの一瞬感・抜き打ちの広さ / 十字斬りの縦・横・突き立ての間隔と爆ぜる範囲 / 疾風連斬の駆ける速さ・太刀の間隔 0.2 秒の読みやすさ / 大渦の回る速さ・ずっとアーマーの感触 / 剣山の動けない長さ（Lv7 で約 2.6 秒）・輪の広がり / 飛竜落としの跳ぶ高さと着地の衝撃）、**スキルの扇**（片手剣は 6 本で外側の輪が出る。払って選べるか）、クールダウンと威力の釣り合い（6 本を既存 5 本と比べて強すぎ・弱すぎないか）。
- 数値は仮置き（`SKILLS` と `skill-attacks-ex.ts` と `skill-*-ex.ts` の仕様の数字）。**剣山（Lv7 = 約 2.6 秒）と十字斬り Lv7（約 2.6 秒）は長い**ので、割り込まれやすい。剣山はアーマーで耐えるが、十字斬りにアーマーは無い。長すぎるなら輪の間隔・十字の間隔（`KENZAN_T.ringGap` / `CROSS_BEAT.next`）を縮める。
- **疾風連斬は、1 体の敵に密着すると前へ進めず、その場で斬り続けるはず**（体がぶつかって止まる）。敵が並んでいれば、それぞれに当たりながら抜ける。本物のゲームで敵の体を抜けてしまわないか（一閃と同じく、押し戻されて止まるはず）は実機で。単体のテストの場には体の衝突がないので、テストは敵を前に置き続ける（`follow`）形で太刀の数を数えている。
- 居合の「抜き打ち → 斬り上げ」の継ぎ目で、刃を 180° 回す（`roll`）。両刃の直剣なので見た目は同じだが、鍔の向きが一瞬入れ替わるように見えるかもしれない。
- **次に回した案**（`docs/07` §2.1.2）: 螺旋突き（回転しながら進む突き = 体を回さず突きだけが回る見せ方が要る）・流星（跳び退いて急降下）・月影（左右へ位置をずらす）、大剣の 返し斬り（被弾で分岐する連なり）・旋断（敵の「浮き」の状態）・地走り（味方の飛び道具）。**どれも新しい仕組みが 1 つ要る**ので、1 本ずつ別の段階で。

## ADR-039 M7 の方針（世界・縦の動き・乗り越え・登り）と、世界への問い合わせ `World`（M7-1）

**状態**: 採用（2026-10-05）。本人の指示（M6-6 のあと）: 「**M7 へ進みましょう。オープンワールド的な方向性を考えているので、ジャンプや掴んで登る・乗り越えるなどのモーションも必要でしょうか**」。`docs/07` §5 の地形の計画を、その方向に合わせて並べ替える。高低差は ADR-002 / 003（物理エンジンを入れない。段差のある地形が欲しくなったら Rapier を検討）の見直し条件に触れるので、判断もここに書く。

### 決定
1. **答え: 必要。ただし 3 段階に分けて、縦の動き（ジャンプ）を最初に入れる。**
   - **ジャンプ**: いちばん安く（クリップは跳び立ち・上昇・落下・着地の 3〜4 本）、あとの全部の土台（足の高さ `y` と接地）になる。
   - **乗り越え**: 低い障害物（上面 およそ 0.5〜1.3m）に向かって走る・跳ぶと**自動で越える**（ボタンを足さない。クリップ 1〜2 本）。
   - **掴んで登る**: 高い縁（およそ 1.3〜2.5m 以上）に掴まって登る。クリップ 2〜3 本（掴み・引き上げ）と縁の検出・カメラの追従が要り、重いので**最後**。**登れるのは、ステージのデータで「登れる縁」と明示した面だけ**にする（任意の形を登らない = 手付けのクリップと手の位置を決定的に合わせられる）。登れる高さは段階（低・中・高）に分け、段階ごとにクリップ 1 本、実際の高さとのずれはルートの高さの補正と手の IK で吸収する（`authoring.ts` に高さのチャンネル（rootY）を足す）。
2. **M7 の順序**（`docs/07` の M7-1 / M7-2 を 4 段に組み直す）: **M7-1 世界の土台**（いま）→ **M7-2 縦の動き**（ジャンプ・落下・着地・低い段差に乗る）→ **M7-3 乗り越え・掴んで登る** → **M7-4 地形を戦闘に使う**（敵の迂回・突進の激突・視線・壊せる物・危険な床・カメラの衝突）。理由: 足の高さは Player・敵・弾・カメラ・UI に及ぶので、障害物を戦闘に使う段階（敵の経路・視線）より先に入れたほうが手戻りが少ない。どの段階も、実機で遊べる状態で区切る。
3. **高低差は自前で作る（Rapier は入れない）**。いまは XZ の円と高さ 0 だけ。縦は「足の高さ `y`」と「障害物の上面 `top`」だけで足りる（段差 = 上面が足元から `STEP_UP`（0.45m）以下なら乗れる、足場 = 障害物の上面、地形は階段状の高さ）。坂・動く足場・物理で転がる物が要るようになったら Rapier を再検討する（ADR-002 の条件のまま。代償は WASM の読み込みと iPad の性能）。
4. **`World`（M7-1。`src/world/world.ts`。three にも DOM にも依存しない純粋なクラス）**: 世界 = **円形の境界**（中心は原点）+ **静的な障害物**（円柱 `circle` と箱 `box`。位置・大きさ・**上面の高さ `top`**）。問い合わせはすべて**足の高さ `y`（既定 0）**を取る = 縦の動きが入っても API が変わらない。
   - `moveCircle(c, y)`: 体を、**足の高さ y で体を止める障害物**（上面が `y + STEP_UP` より高いもの）の外へ押し出し、境界の内側へ収める（2 回まわす）。円は中心を結ぶ向きへ、箱は最も近い面へ。真正面からぶつかる以外は、押し出しだけで障害物の面を**滑る**。
   - `raycast(a, b, y, out)` / `lineOfSight`: 高さ `y` の線分を、**上面が `y` より高い**障害物が遮るか（当たった点・外向きの法線・線分上の位置を `out` に書く。毎回確保しない）。弾・視線・敵の射線の入口。
   - `overlapsObstacle` / `contains` / `clampBounds`。**呼び出し側は円の半径（`arena.radius`）を直接読まず、ここを通す**（`docs/07` §5.3 の約束）。
5. **闘技場の障害物**（`src/world/data/arena-props.ts`。**当たりの World と見た目の Arena が同じ表から作られる** = 見えている物と止まる物がずれない）: 縁の柱 8 本（上面 4.5）・**折れた太い柱 4 本**（斜めの 4 方向・半径 9m・上面 3.2。弾の遮蔽）・**低い岩 2 本**（上面 0.85）・**崩れた低い壁**（上面 0.9）・**石の箱**（2m 角・上面 1.5）。縦・横の軸の上は空けた（ロックして向かい合う戦いの邪魔をしない）。弾の高さ（`PROJECTILE_HEIGHT` = 1.1）より高い柱・箱は弾を遮り、低い岩・壁は弾が上を通る。
6. **Game・弾の変更**: 体の押し出しと境界は `world.moveCircle`（飛んでいる敵 = 小蝙蝠は足の高さ `FLYING_Y` = 1.8 なので、低い障害物の上を通り、柱には当たる）。**弾は障害物の手前の面で消える**（`ProjectileSystem.step(dt, world, onEnd)`。線分で調べるので速くてもすり抜けない。消える理由は `wall`、演出は当たった面の上）。弾き返した弾も遮られる。出現位置・召喚位置の範囲は `world.radius`。

### 検証
`world.test.ts`（15 本）: 境界・円柱の押し出しと滑り（めり込まず向こう側へ抜ける・真正面は止まる）・箱の面 / 角 / 中心が中・yaw・足の高さ（段差に乗れる・高いものは止める・跳んでいれば越える）・体の幅の通路は通れて狭い隙間には入れない・境界を出ない・`raycast`（円柱・箱・法線・高さ・始点が中・複数のうち最初）。`projectile.test.ts`（柱で消える・手前の面で止まる・低い岩の上を通る・脇を通る・1 ステップで柱をまたぐ速さでも遮る・弾き返した弾も遮られる）。`npm run shot` に、俯瞰で障害物を撮る絵と、(1) 柱へ走り込むと半径の和でぴったり止まって脇へ滑る (2) 弾が柱の手前で消える (3) 弾が低い岩の上を通る、の確認を追加。

### 代償・既知の問題
- **実機で未確認**。確かめること: 柱・岩への当たりの手触り（引っかからず滑るか）、**柱の陰で鬼火を防げるか**、敵が柱・壁・箱にはまって動けなくならないか（特に壁・箱。まだ「迂回」はしない）、障害物の見た目と配置（斜めの 4 本の柱が戦闘の邪魔にならないか。低い岩・壁・箱の高さの見え方）。
- **敵は障害物を避けて追わない**（押し出されて滑るだけ。真正面だと止まる）。ロックオン・遠距離の敵（提灯）は**視線を見ない**（柱越しにも撃つ。弾は柱で消える）。**カメラは障害物にめり込む**。いずれも M7-4。
- **低い障害物（岩・壁・箱）は、まだ「またげない壁」**（足の高さがまだ動かない）。ジャンプ・乗り越え・登りは M7-2 / M7-3 で、`y` と `top` の引数がすでにあるので `World` の API は変えずに済む。障害物の底の高さ（浮いた足場・天井・橋）はまだ持たない（ステージの定義 M9 で足す）。
- 箱の面と円柱だけ（坂・階段・穴・水はない）。坂が要るときは「階段状の高さ」から始め、滑らかな坂が必要なら Rapier を検討する（上の 3）。
