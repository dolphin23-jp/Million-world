## 検証結果（仮キャラ）

良かった点
- 顔: 正面・斜め・側面とも輪郭は破綻せず、鼻・顎の凹凸がある。目は「描かれた絵」寄りだがアニメ調として許容範囲
- 手: 指は融合気味だが 5 指の形があり、剣を握る用途なら通る
- 三角形 39,872（予算 40k 内）、テクスチャ 2048² 1 枚、メッシュ 1 つ
- リグ: 24 ボーン、名前は Mixamo 系（`Hips` `Spine` `Spine01` `Spine02` `neck` `Head` `LeftShoulder` `LeftArm` `LeftForeArm` `LeftHand` `LeftUpLeg` `LeftLeg` `LeftFoot` `LeftToeBase` と右側）。身長 1.7m に自動スケール。モーション付与も成功（`Roll_Dodge` 1.87 秒）

要対処の点
- **向き**: モデルは +X を向いて出力される。取り込み時に Y 軸回転で +Z 正面へ正規化する
- **スキニング**: 回避の前転ポーズで股・裾まわりに尖った破れ（ウェイトの乱れ）が出る。ゲームのカメラ距離・速度で許容できるかは M1 で判断
- **指ボーンなし**（手は剛体）、**髪・服のボーンなし**（揺れない）。設計で長髪・マント・ロングスカートを避ける方針は正しい
- **ルートモーション**: クリップは腰が並進する。ゲームでは移動をコードで行うので、取り込み時に `Hips` の並進（XZ）を除去する
- 左目付近にテクスチャの乱れ（小さな黒い滲み）。ベースカラーに薄い陰影が含まれて見える（トゥーン着色と重ねたときの影響は M1 で確認）
- クリップごとに別 GLB で返る。同一骨格なので、取り込みスクリプトで 1 ファイルに結合する

## 確定した取り込み手順（2026-10-03、2 体目で確立）

```
3面図(front/side/back, A ポーズ)  →  tripo_h3_1_multiview_to_3d (quad:true, detailed)  → FBX
  → tools/fbx2glb.mjs（三角形化・テクスチャ埋込）→ 正規化（足裏原点・身長・+Z 正面・JPEG2048）
  → Higgsfield に file としてアップロード（公開 URL）
  → 3d_rigging(+animation) × クリップ数（毎回リグし直される。8 クレジット/本）
  → 土台: 1 本目の出力を tools/weld-by-position.mjs（三角形スープ→連結メッシュ）
          → tools/smooth-weights.mjs（隣接平滑化 0.5×3、4 本制限）
  → tools/build-character.mjs（manifest.base に土台、clips に各出力）
       リターゲット（バインド差分）・ルートモーション除去・接地補正・WebP 2048
  → tools/skin-stress.mjs で全クリップの伸び率を数値検査
  → tools/pose-sheet.mjs / tools/inspect-glb.mjs で目視
```

### 検査基準（`tools/skin-stress.mjs`）

全フレームで「メッシュの辺の長さ ÷ バインド時の長さ」を three.js と同じスキニングで計算する。
- 採用: **1.8 倍超の辺が 1% 未満、p99 < 1.9**（2 体目: 0.26〜1.1%、p99 1.42〜1.86）
- 不採用: 1 体目は 11〜15%、p99 8〜11（Meshy から返った直後でも同値 → リグのウェイト自体が破綻）
- `max` は数 mm の辺 1 本で跳ねるので単独では判定に使わない（脇の下の 4〜7mm の辺が 10 倍前後になる）
- `minJointY` は足の床貫通の検出。接地補正後は常にバインド時の足の高さ（≈0.06〜0.10m）になる

### 分かったこと

- **衣装と体型が最大の要因。** 裾の広い服・長髪は自動リグのウェイトが破綻する。タイトな服、露出した四肢、短髪なら安定する
- **四角メッシュ（Tripo `quad`）は FBX で返る**。glTF は四角を表現できないため。FBX→GLB は three.js の FBXLoader で三角形化すればよい
- FBXLoader 経由のメッシュは**三角形ごとに頂点が分かれている**（177,960 頂点 = 59,320 三角形 × 3）。Meshy はそのままリグするが、
  ウェイトの平滑化や検査には位置で結合した連結メッシュが要る（`tools/weld-by-position.mjs`）
- **Meshy の自動リグはジョブごとに違う**（関節 ≤0.5cm、ロール最大 90°、ウェイトも別物）。クリップはボーンの「バインド姿勢からの世界回転差分」で写す
- Meshy のクリップは別体格向けの並進アニメ（ボーン伸縮）を含む。ボーン長を固定すると足が床を貫く（1 体目で最大 26cm）ので**接地補正**が必須
- Blender（`bpy` 5.2、pip で入る）のボーンヒート自動ウェイトは、AI 生成メッシュ（1,000 以上の小片、非多様体辺多数）では解が出ず失敗。
  Blender でのウェイト平滑化は効くが、再エクスポートで法線がノイズ化（斑点）したため、自前の `smooth-weights.mjs` を使う
- 支配ボーンから遠いボーンの影響を機械的に落とす掃除は、隣接頂点との不連続を生んで悪化した（既定で無効）
- `meshopt`/量子化は使わない（IBM に逆変換が畳み込まれ検査と切り分けが難しくなる）。2 体目の `hero.glb` は 8 クリップ込みで 3.6MB

**腕の挙上量との関係（`tools/clip-arm-height.mjs`）**: 上腕の最大挙上角は idle 36° / run 57° / slash 111° / Left_Slash 128° / dodge 143° / heavy 161° / combo 163°。
脇がきれいなのは 128° まで（slash・Left_Slash を 4 方向の近接で確認）、ささくれが出るのは 143° 以上。
→ 攻撃クリップは **上腕の挙上 130° 以下** を採用目安にする。旧 combo（163°）は該当したので差し替えた（下記）。
Left_Slash（Meshy 97、8 クレジット）はしゃがみ込みの盾剣モーション（3.2 秒に斬り 2 回）。脇は合格だが、単体では `slash` より特に良いわけではなかった。

### 攻撃を手付けに変更（2026-10-03、実機の指摘「攻撃モーションはやはりまだ違和感が大きい」）

Meshy の斬りクリップの区間選びと調整では限界があると判断し、**1 段目を手付け（キー → IK → 60fps に焼く）に置き換えた**（ADR-012）。
重撃・回避は、実機確認のあとで同じ方法に置き換える（2・3 段目は下の追記のとおり手付けにした）。

**1 段目（`src/character/data/combo1.ts`、0.66 秒）**: 右手の袈裟斬り（右上から左下）に左足を踏み込む。
予備動作 0〜0.14（右へひねって右肩の後ろへ振りかぶる、左足が浮く）→ 頂点で 0.03 秒の一拍 → 斬り 0.17〜0.31（0.245 に体の前を通る最高速）→ 振り抜き〜0.37 → 0.5 まで姿勢を保持 → 戻り〜0.66（右足を揃えて idle のポーズに戻る）。
当たりは 0.21〜0.29、次段受付は 0.37 から。前進は 0.3m（`rootZ`）。

**読み取り（`rig-capture.ts`）**: 骨名・親子・位置は GLB のスケルトンから（Armature の 0.01 倍で cm → m）、基準ポーズは idle の t=0、肘膝の蝶番軸は走りの曲がったフレームから実測。
Armature が identity でない資産は拒否する（手付けはキャラ基準 +Z 前・右 −X を前提にしている）。今の資産は identity。

**診断値（焼くたびに `HeroVisual.authoredStats` / `authoredTrace` に出る）**: 腕・脚が届かず伸び切ったフレーム数（combo1 は 0）、右手首の目標とのずれ（1e-16m）、
上腕の最大挙上角（104°）、右肘の最小曲がり（5°）、右手首の最大の曲がり・ねじれ、腰を下げた量（最大 4cm）。
`tools/scratch/authored-info.mjs trace` でフレームごとの表が出る。

**見た目の確認手順**（`tools/scratch/` は git 管理外。道具が要るときは同じものを書く）: `game-atk-key.mjs <tag> <フレーム列> <視点列> <サイズ>` で攻撃の指定フレームを複数視点
（side / front34 / back / 手元の近接 handside・handfront・handback）から撮って 1 枚に並べる。`game-foot.mjs` で攻撃中の接地足の滑りと剣先速度を測る。
オフラインの調整は `dump-rig.mjs` が実リグを JSON に書き出し、vitest の別設定（`tools/scratch/vitest.config.ts`）で `combo-roll` / `combo-opt` を 0.4 秒で回せる。

**分かったこと**
- 手ボーンの Y 軸は指の向きから約 22° ずれている。手首の曲がりは `HERO.hand.right.f`（指の向き）で測らないと、idle でも大きく出る。
- このグリップ（刃 = 親指側 t を指 f へ 35° 倒した向き）では、刃を前腕と同じ向きにそろえると手首は尺屈 55° が要る。斬りの面を水平寄り（水平から 38°）にして roll（±20°）を足すと、
  見た目に破綻のない範囲に収まった。縦に近い斬り（55°）は手首のねじれが 100° を超えた。
- 前腕のねじれは前腕の骨と手首で半分ずつに分けないと、片側のスキンだけが潰れる（`FOREARM_TWIST_SHARE`）。
- 足を「ワールド固定」で書くと、ルートが進んでも足が滑らない。ただし sim のルートとアニメ時刻が 1 フレームずれると、ルート速度 × 1 フレーム（最大 3cm）だけ滑る。

**2・3 段目と連鎖（2026-10-03 夜、実機の指摘「2 撃目以降は体の形が変形する」）** — 詳細は ADR-012 の追記。
- 2 段目（`combo2.ts`、0.65 秒）: 右の逆袈裟（左下 → 右上）。1 段目の 0.37 秒の姿勢から続く。溜め 0〜0.075 → 斬り上げ（0.15 に体の前を通る最高速）→ 0.23 → 振り抜き 0.32（当たり 0.13〜0.2、次段受付 0.32 から）→ 0.45 まで保持 → 戻り。右足が前へ出る（踏み込み 0.3m）。
- 3 段目（`combo3.ts`、0.62 秒）: 右の突き。2 段目の 0.32 秒の姿勢から続く。右腰へ引き絞って（0〜0.13、頂点で一拍）→ 突き出し 0.13〜0.18（最高速）→ 0.24 に伸び切る（当たり 0.15〜0.24）→ 戻り。右足が大きく踏み込む（0.3m）、左足は小さく浮かせて引き寄せる。
- 斬りの面の関数 `plane(θ, tilt)` は `src/character/data/cutting-plane.ts` に出した（3 段で共用）。
- 並べて確認する道具（git 管理外の `tools/scratch/`）: `combo-diag.scratch.ts`（`COMBO=2` でフレームごとの 挙上・肘・手首・ねじれ・クランプ・腰の下がり・剣先の位置と速さ・足の高さを表にする）、
  `combo-roll2.scratch.ts`（時刻ごとに roll を −180〜180° で振ったときのねじれ/曲がり）、`combo-opt2.scratch.ts`（刃の傾き・roll・肘の向きの探索）、
  `game-atk-key.mjs`（環境変数 `PRESS=0,2,26` で連打のタイミングを指定。視点に `chestf` / `chestb` / `chests` の胸の近接を追加）、`game-chain.mjs`（3 連続での接地足の滑り）。

**分かったこと（連鎖）**
- 前の技の終わりと次の技の始まりを同じ姿勢にするだけで、「体の形が変形する」はなくなった。Meshy のクリップ同士のクロスフェードが原因だった。
- idle は左足が前に 23cm ずれた立ち方（足首の前後位置が左 +0.06 / 右 −0.17）。足の z は「idle からの前進量」なので、踏み込みの歩幅を決めるときはこのずれを足して考える。
- 手首のねじれ（`wristTwist`）は ±180° で折り返す。キー列の途中で 180° をまたぐと、前腕の骨（ねじれの半分を持つ）が 1〜2 フレームで反転する。ロールを振った表（`combo-roll2`）で、連続に変化する枝を選ぶ。
- 左腕は「前に出して肘を曲げる」と体の釣り合いに見える。体の脇に垂らして拳をみぞおちに置くと握りしめた形に見えたので、1 段目の予備動作の左腕を前へ出した。

### 腰の背面の崩れ（2026-10-03、実機の指摘「腰〜ウエストが角度によって静止時から崩れる」）

切り分けの結果、**メッシュの形・スキンウェイトは原因ではなかった**。原因は 2 つで、どちらも見た目（テクスチャと輪郭線）の問題。

| 原因 | 見え方 | 切り分け | 対策 |
|---|---|---|---|
| 輪郭線（inverted hull）が背骨の溝・トップス裾で表面を突き破る | 背中中央に暗いギザギザの縦線、裾のささくれ | 輪郭線を消すと消える | `aONormal`・`aOutlineCut`・`uDepthPush`（ADR-009 追記、`src/render/outline-attrs.ts`） |
| 焼き込みテクスチャの描き崩れ | 腰の背面の傷のような赤い線、裾中央の赤い楔、ウエストバンド上端・裾の黒いささくれ | フィルタを mipmap/線形/最近傍に変えても同じ → テクスチャ本体の絵 | `tools/clean-texture.py`（腰の領域だけ塗り直し） |

- 原メッシュ（Tripo の静的出力）は同じ視点で綺麗。ウェイトで隣り合う頂点の差が大きい辺は腰帯 17,172 本中 16 本（0.1%）で、ウェイトの乱れではない
- テクスチャの UV は小さな島に分かれているため、直す対象は「テクスチャ上の座標」でなく「3D 上の領域」で選ぶ（領域に入る三角形の UV をラスタライズ）。
  領域: 背中側の素肌（y 0.98〜1.29m）、ウエストバンド上端（0.93〜1.10m）、トップスの裾（1.17〜1.31m）。素肌の線は周囲の肌色で塗り直し、バンド・裾は中央値フィルタでささくれを均す
- 取り込み: `manifest.textureFrom` に PNG/WebP のパスも指定できる。腰の修正版は `raw/heroine/texture-clean.png`
- 残り: 背骨の細い線がごくわずかに残る、トップス裾の中央に小さな黒い点がある。ポーズ中（アイドル・走り）の腰のねじれ方は未確認
- 計測の取り違え（記録）: 途中で「UV がテクスチャの 99.5% を埋めていて余白がない」と誤判定した。GLB のバッファがインターリーブ（byteStride 付き）なのを無視して読んでいたため。正しくは 60.3%、島の外側の余白は肌色で埋まっており、島の縁のにじみが原因という仮説は撤回した

### 足の接地（2026-10-03、実機の指摘「待機で足が地面に全て設置していない」）

原因は**配信元クリップ（Meshy ライブラリ）の足の姿勢の系統的なずれ**で、リターゲットの不具合ではない。
配信元の GLB をそのリグ上で再生しても同じ値になる（`tools/scratch/foot-ground.mjs` で、足裏の頂点のかかと/つま先の高さと足裏のピッチを測った）。

| クリップ | 足裏のピッチ（つま先が上がる向き） | つま先の浮き |
|---|---|---|
| idle（Idle_02）| 24°（両足）| 9〜10cm |
| stance / hit / death 冒頭 / heavy | 15〜19° | 5〜8cm |
| combo / slash / run（接地中）| 14〜18° | 5〜7cm |

加えて、接地補正が**ジョイント（足首・つま先ボーン）の高さ**を見ていたため、靴底の最低点は検出できず、stance・hit では靴底が 4〜5cm 床にめり込んでいた。

対策（`tools/build-character.mjs`）:
- `footPitchDeg`（既定 19°、manifest で全体、クリップごとに上書き可）: 足・つま先ボーンを、バインド姿勢の横軸まわりに「つま先を下げる向き」へ回す。
  足とつま先に同じ世界回転を掛けるので足に対するつま先の相対角は変わらない。idle だけ 26.7°（Idle_02 は他より 8° 大きい）
- 接地補正を**足裏の頂点**で行う（`buildSoleProbes`: 足・つま先ボーンが支配的でバインド姿勢の高さが最低点から 2cm 以内の頂点 1,248 個を、支配ボーンのローカル座標で保持）。
  フレームごとに最低点が床を下回ったら Hips を持ち上げる（持ち上げる向きだけ）

結果（出荷版 hero.glb、足裏のピッチ。静止・接地中のフレーム）: idle 0.1°/0.1°、stance 2°/-2°、hit 2°/1°、combo -0.5°/-0.3°、slash -1°/-2°、heavy 2°/0.7°、run 接地中 0.3°/-1°、死亡冒頭 1°/0.4°（いずれも ±3° 以内）。
idle のつま先の浮きは 9〜10cm → 1cm 未満（右足 0.0cm、左足 0.9〜1.1cm）。変形の数値検査（`tools/skin-stress.mjs`）は補正の前後で同じ（>1.8 倍の辺の割合は 0.122〜1.122% のまま）。
なお footPitchDeg の初期値 16° では idle が 9.8° 残ったので、idle だけ個別に上書きした。

残り: 元のポーズが片足を高くしているクリップでは、高いほうの足が浮く（stance 右足 3.5cm、slash 3.3cm、combo 1.8cm、hit 1.6cm）。
低いほうの足を床に付けているので、めり込みはない。直すには脚の IK が要る。stance は M3 のロックオン中に使う予定なので、使う段階で検討する。

### 頭の向きと横顔（2026-10-03、実機の指摘「走りの横顔の違和感」）

原因は**顔の輪郭線が太すぎる**こと。輪郭線を全部消した描画と並べると、同じカメラ距離（約 5m）・同じ解像度で、横顔の目・鼻・唇・耳がはっきり見える。
輪郭線の太さは画面上で一定なので、遠いほど顔の細部より輪郭線のほうが太くなる。顔の太さ倍率は 0.35 → 0.12 でも黒い筋が残り、0.04 でほぼ消える。
→ `faceOutlineScale` を 0.04 に（ADR-009 追記）。

あわせて頭の向きも直した。頭ボーンの前方軸が水平から何度ずれるかを測ると（`tools/scratch/head-pitch.mjs`）、idle -18.5°（うつむく）、stance -28°、combo/slash -17〜-19°、hit -35°、run -3.4°。
ゲームのカメラは上から見下ろすので、うつむくほど前髪とつむじしか見えなくなる。
- `headPitchDeg`（manifest、クリップごとに上書き可、正 = 上を向く）: 頭・頭の子ボーンを、バインド姿勢の横軸まわりに回す。idle +16°（→ -2.5°）、run +6°（→ +2.6°）。他のクリップは 0
- 攻撃クリップ（combo/slash）は頭が -17〜-19° 下を向くが、斬る相手を見る演出として残している。M2 で見た目を確認して決める

元の設定画の横顔は、前髪が顔の後ろへ流れて目・鼻・唇が見える。3D モデルは前髪が顔の前に垂れて頬と目を隠す形になっている（上から見下ろすと特に）。
輪郭線を細くしても残るのはこの形で、直すにはメッシュの前髪の編集が要る。必要になったら検討する

### 重撃・回避・左手を手付けに（2026-10-03 深夜、ADR-012 追記）

重撃（縦斬り、`heavy.ts`）と回避（2 歩のダッシュ、`dodge.ts`）を手付けにして、Meshy の `heavy` / `dodge` の区間を撤去した。両方とも腕を頭上へ振り上げる姿勢を含んでいたが、
手付けでは上腕の最大挙上が重撃 108°・回避 38° で、脇の破れは出ない（Meshy 版は heavy 161°・dodge 143°）。
診断（`tools/scratch/combo-diag.scratch.ts`、`FILE=heavy EXPORT=HEAVY` のように任意のデータを指定できる）: クランプ 0、手首のねじれ最大 85° / 112°、剣先の最高速は重撃 82m/s（体の前を水平に通る瞬間）。
回避は最初の 2 フレームで剣を体の後ろへ寝かせるため剣先が 76m/s になる（走り出しの 1〜2 フレームのみ）。

左手（素手）は指ボーンが無く形を変えられないので、置き場所を共通ポーズにした（`offhand.ts`: 構え手 / 引き手 / 脇）。
手の向き（手のひらの向き）は前腕と肘の向き（pole）で決まり、手首の回転は指定できない。盾を持たせるときは左手の回転目標を足す（`docs/06-moveset-ideas.md`）。
